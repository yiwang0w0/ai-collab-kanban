# 多执行者协作

同一台机器上有几个 AI 执行者同时干活时(看板的执行线、看板外的 AI 会话、另一家模型的目标模式),
它们靠看板交换四样东西:谁在做什么(状态)、谁占着什么(锁)、发生过什么(流水)、停下时交给谁(交接)。
操作者不需要在模型之间口头转话。

接口都在 `/api/coord/*`,只监听回环地址;命令行入口是 `cli/board.py` 的 `exec`、`lock`、`journal`、`handoff`。
面板在「设置」→「协作」里显示这四样。

## 执行者与令牌

操作员登记执行者,拿到一枚执行者令牌:

```
python cli/board.py exec register agent-one --kind external --name agent-one --save <令牌文件>
```

- `id`:小写字母、数字、`-`、`_`,1–32 位;`operator`、`system`、`undefined` 是保留名。
  不能与受管执行线(非外部执行线)或角色座席同名:那条线第 1 个座位的名字就是线 id,同名的执行者令牌会等同座位凭据。
  登记时 409;反过来,加受管线时与已登记执行者同名也 409。外部执行线没有受管座位,可以同名。
- `kind`:`line`(看板执行线)、`external`(看板外的会话)、`other`。
- 令牌只显示一次(或用 `--save` 写进文件,文件已存在则拒绝覆盖)。库里只存 sha256。
  丢了就 `exec register <id> --rotate` 换发,旧令牌立即失效;显示名与种类保持原样,换发时带 `--name` / `--kind` 才改。
- 令牌文件放在执行者自己读得到、但工作仓之外的地方;不要放进被版本管理的目录。
- 注销(只属于操作员):`python cli/board.py exec unregister <id>`,即 `DELETE /api/coord/executors/:id`。
  令牌立即失效,执行者不再出现在列表里,同一个 id 之后可以重新登记(当作新登记,状态从空白开始)。
  它还持有进行中的卡或未释放的锁时返回 409,写明是哪些;等它交付、释放,或等租约到期、强制释放锁之后再注销。
  注销写一条 `executor.unregister` 流水;它写过的流水、锁记录、交接记录都留着。执行者令牌、worker 令牌 403,
  批准令牌与远程入口也不能注销。
- 旧库里与受管执行线同名的登记(修复前留下的)会让共享 `worker_token` 用不了那个座位名:把它注销即可。
  这种同名登记领不了卡,所以那个名字下进行中的卡算座位的,不挡注销。

执行者令牌能做的:读看板;领卡(`claim`、`take`)、续租、交付(`done`、`wait`);写自己的状态和流水;
加锁、释放自己的锁;确认交接。不能做的:裁定(approve/reject)、bless、起停线、改设置、建卡、登记执行者。
越权一律 403。

持执行者令牌时,命令行加 `--token-file <令牌文件>`;`--as` 可以省略,身份按令牌认定。给了 `--as`
但和令牌不一致会被 409 拒绝。不加 `--token-file` 时一切照旧,用数据目录里的 `board_token`。

请求正文里的 `worker` 只接受字符串或数字(数字按它的十进制写法当名字),其他类型(数组、布尔、null、对象)一律 400。
共享 `worker_token` 把 `worker` 写成已登记的执行者 id 时 409:执行者 id 只属于它自己的令牌。

### 心跳与租约

```
python cli/board.py take 12 --version 3 --lease 60 --token-file <令牌文件>
python cli/board.py exec heartbeat --lease 60 --token-file <令牌文件>
```

- `take`、`claim` 可用 `--lease <分钟>` 指定租约;执行者令牌的上限是 240 分钟(操作员仍是 1440)。
- `exec heartbeat` 更新最后心跳,并为该执行者手上所有进行中的卡续租;`--task <id>` 只续一张。
  不带 `--lease` 时只往后续:每张卡取默认 30 分钟与现有剩余租约里较长的,不会把长租约缩短;带 `--lease` 就按给的值。
- 直接调卡片级心跳 `POST /api/tasks/:id/heartbeat` 是同一条规则(对执行者、worker、操作员令牌都一样):
  不带 `lease_minutes`,或给的不是正数(`null`、`0`、负数)时只往后续;给了正数就按给的值。执行线循环每次心跳都带
  `lease_minutes`,行为不变。
- 心跳超过 `BOARD_COORD_STALE_MIN` 分钟(默认 20)没有更新,看板按「心跳中断」生成交接包。
  从未心跳过的执行者不按中断处理。中断后再心跳,执行者回到活动状态。

### 外部执行线

配置里给线加 `"external": true`(或 `lines add` 接口带 `external: true`、面板加线勾「外部执行」),
这条线的卡由持执行者令牌的外部执行者领取。面板对它显示「外部执行」,不出启动按钮;看板拒绝启动它,
启动恢复也跳过它。

```json
{ "lines": [ { "id": "alpha" }, { "id": "outside", "label": "外部会话", "external": true } ] }
```

### 桌面客户端经 MCP 领卡

Zcode 桌面版这类带 MCP 的聊天客户端,可以作为一条外部执行线的执行者:操作者在客户端里说一句,模型用 MCP 工具领卡、交付。
入口是 `cli/exec-mcp.mjs`(stdio)。它只把执行者的读卡、领卡、续租、交付接口包成工具,带执行者令牌发给本机回环的看板;
不接收数据库路径,令牌文件里不是 `exe_` 开头的执行者令牌就拒绝启动(操作员、worker 令牌都不收),也没有文件、命令、网络工具。
它和 `cli/mcp.mjs`(联邦本机代理的受限凭据,见 [federation/mcp.md](federation/mcp.md))是两套身份,不通用。

1. 加一条外部执行线,例如 `{"id":"zcode","label":"Zcode","external":true}`(面板加线勾「外部执行」,或 `POST /api/config/lines`)。
2. 登记同名执行者并把令牌存进仓库外的文件:`python cli/board.py exec register zcode --kind external --save <令牌文件>`。
3. 客户端的 MCP 配置。Zcode 写在 `mcp.servers` 下;`protocolVersion: "legacy"` 让它直接用本桥支持的握手版本:

```json
{ "mcp": { "servers": { "fleet-board": {
  "type": "stdio", "protocolVersion": "legacy",
  "command": "C:/Program Files/nodejs/node.exe",
  "args": ["C:/board-code/cli/exec-mcp.mjs", "--url", "http://127.0.0.1:47824",
           "--token-file", "C:/board-data/credentials/zcode.token", "--line", "zcode"] } } } }
```

| 工具 | 做什么 |
|---|---|
| `list_cards` | 列卡(默认只列未开始的),带版本号 `aggregate_version` |
| `get_card` | 读完整卡面:要做什么、说明、验收条件、状态、持有者 |
| `claim_card` | `id` + `expected_version` 领取,卡进入执行中 |
| `heartbeat` | 给自己手上的卡续租;可带 `note`(≤120 字)写「现在在做什么」 |
| `report_result` | `done` 进入待验收,`wait` 进入待决策 |
| `wait_for_card` | `timeout_sec` 1–50(默认 30):有可领的卡(已放行、未开始)立即返回 `{card:{id,subject,summary,aggregate_version}}`,到时返回 `{none:true}` |
| `ask_operator` | `id` + `question`:把问题交回操作员,卡进入「等你决定」(同 `report_result` 的 `wait`) |

- 给了 `--line` 就只看这条线:别的线的卡读不到、领不走(`NOT_FOUND`)。不给则不限线,能做什么仍按执行者令牌。
- `report_result` 带上领卡时的 run_id;客户端重连后桥进程是新的,就取卡上当前的 run_id,持有者是不是自己由看板按令牌核对。
- 连接时先用令牌读一次 `/api/coord`:看板没在跑、令牌已注销或已换发,客户端在连接阶段就显示失败。
- 握手接受 2025-11-25、2025-06-18、2025-03-26、2024-11-05;客户端要别的版本时回 2025-11-25。
- 交付不等于验收,裁定仍属于操作员。这条路不经调度器、不占预算,也不记用量。

### 本机桌面对话清单与勾选

面板「设置」里列出本机 Claude 与 Codex 桌面端的对话,操作者勾选要整合的,并可把会话登记成一条来领任务的受管线:
这条线第一次领卡时以该会话的副本为起点(Claude `--fork-session`,Codex `exec fork`),原会话不动,之后沿用 fork 出来的自己的会话。
看板不代管 AI 的批准:线仍是普通的自动领取线,工具与沙箱按线的身份与座席走。两家 CLI 能怎样续接,见
[桌面对话续接_CLI能力.md](桌面对话续接_CLI能力.md)。实现在 `core/desktop-sessions.mjs`。

| 接口 | 说明 |
|---|---|
| `GET /api/desktop-sessions?source=claude\|codex\|all&days=N&q=&limit=&selected=1` | `{sessions:[…], truncated, unavailable:[{source,reason}], threshold_tokens, threshold_bytes}`(后两项 = 登记成线的大体量阈值:有用量记录按 token,没有按文件字节),最后活动新的在前。`limit` 默认 50、上限 200(超了按 200);`days` 按文件修改时间筛;`q` 只比对标题(不分大小写);`selected=1` 只列已勾选的,不受 `days` 限制。参数不合法 → 400 |
| `GET /api/desktop-sessions/:source/:id/messages?limit=50&before=<游标>` | 只读看历史 → `{messages:[{role:"user"\|"assistant", text, at, tools}], next_before\|null}`,按时间正序。只给文字(单条截 4000 字);工具调用折叠进它前面那条 assistant 的 `tools` 个数(前面没有文字时补一条空文字的);工具结果、思考、元消息、`<…>` 注入块不给。`limit` 默认 50、上限 200;`before` 是上一页给的 `next_before`(字节位置,会话文件只追加所以一直有效),不合法 → 400;本机没有 / 子代理线程 → 404 `SESSION_UNKNOWN`。正文不缓存、不写日志、不落盘。每页至多读 16MB;单行超过 4MB 时不再读进内存,往前找到它的行首后给一条 `{role, text:"这条太长,已省略", at, tools:0, omitted:true}` 占位(工具结果、子代理、元消息的超长行照旧不给),游标每页严格变小、最终为 `null` |
| `POST /api/desktop-sessions/lines` `{source, id, label?, confirm_large?}` | 登记成线 → `201 {line:{id, label, runtime, lineage:{source, session_id_hash, forked:false}}, approx_tokens, size_bytes, threshold_tokens}`。线 id = `<source>-<会话 id 的 sha256 前 8 位>`;运行时 = 来源;缺省显示名「Claude 会话 <哈希>」(**不用会话标题**:显示名写进 fleet.config.json);登记不启动线。已登记(含手写 lineage.json 里的同一会话)→ `409 ALREADY_A_LINE`;本机没有 / 子代理线程 → `400 SESSION_UNKNOWN`;体量超阈值没带 `confirm_large:true` → `400 NEEDS_CONFIRM_LARGE`(带体量)。`label` 先去掉换行、ESC 等控制字符、零宽与双向控制字符,并空白,再限 24 字。201 另带 `start_blocked:{code, message}|null`:登记成功但这条线现在起不来的原因(`SEAT_LOCKED` 座席未解禁 / `SEAT_CMD_MISSING` 座席缺命令路径 / `PROFILE_NOT_READY` 执行配置未就绪,与起线时同一判据;判不出为 `null`)。解除继承后同一会话再登记 → `201` 接回原来那条线(`reattached:true`,不新建、不改显示名) |
| `DELETE /api/desktop-sessions/lines/:line` | 解除继承并停线 → `200 {line:{id, lineage:null}, stopped}`;线本身、已建的卡与历史保留。不是面板登记的线 → 404;手写 lineage.json 的项 → `409 LINEAGE_HANDWRITTEN`(从那份文件删掉再重启) |
| `PUT /api/desktop-sessions/selection` `{add:[{source,id}], remove:[{source,id}]}` | `200 {selected:<总数>}`。`add` 只收本机确实存在、且会出现在清单里的对话(否则 `400 NOT_FOUND`);总数上限 50,超了 400 且整批不落地;重复 add、remove 不存在的项都是幂等成功。有改动才推 SSE `{type:"desktop-sessions.changed"}` |

- 每项:`{source:"claude"|"codex", id, title, project, updated_at, size_bytes, approx_tokens, origin, selected, line, start_blocked, line_forked, line_forked_at}`(`line` = 已登记成哪条线 `{id, label}|null`,含手写 lineage.json 的;`start_blocked` 同登记接口,没登记为 `null`;`line_forked` = 这条线已从该会话的副本起步过(第一次领卡已 fork),`line_forked_at` 是那一刻,面板据此写「在跑 / 已停 · 已从该会话起步 / 还没启动」);
  看板自己 fork 出来的会话副本(登记成线的会话第一次领卡时 fork,之后这条线沿用的那个会话)默认不列:它与原会话同标题,再勾一次就成了第二条线。要看它们带 `include_forks=1`;
  勾选了但对话文件已不在的项(只在 `selected=1` 里出现)其余字段为 `null`,另带 `missing:true`,可以被 remove。
- 鉴权:只认操作员(面板会话或操作员令牌),与 `/api/coordinator` 同档。执行线、审阅线、执行者令牌 → 403;
  批准令牌在本机接口上不认(401);远程批准入口只路由批准接口,到不了这里。
- 来源与标题:
  - Claude:`~/.claude/projects/<项目目录>/<uuid>.jsonl`,只看第一层(子代理的 `<uuid>/subagents/…` 不算对话)。
    标题取最后一条 `custom-title`,其次 `ai-title`,都没有用首条真人消息(跳过 `<…>` 注入块、工具结果、元消息)。
    `project` 取对话里的 `cwd`,取不到用项目目录名;`origin` 取 `entrypoint`(如 `claude-desktop`、`sdk-cli`,用来区分桌面端对话与看板自己起的会话);
    `approx_tokens` = 最后一轮 usage 的 input + cache_creation + cache_read。
  - Codex:`~/.codex/sessions/YYYY/MM/DD/rollout-…-<id>.jsonl`(也有 `…-<id>_<另一个 uuid>.jsonl`,id 取第一个)。
    标题取 `session_index.jsonl` 里同 id 的最后一条 `thread_name`,没有用首条 `user_message`;`project` 取首行 `session_meta` 的 `cwd`,
    `origin` 取 `thread_source`;`approx_tokens` 取最后一个 `token_count` 的 `last_token_usage.input_tokens`。
    **子代理与审阅线程(`source.subagent`、`thread_source` 为 `subagent` / `guardian_review`)默认不列出,也不能勾选。**
  - 某一家目录不存在 → 进 `unavailable`,不报错;损坏行跳过。
- 只读:不写两个根目录下的任何文件;不返回正文,标题截到 80 字;符号链接与联接一律不跟随,目录用 realpath 核一次仍在根内。
  不整读:先按修改时间排序筛选,再只读每个文件的头 64KB 与尾 512KB,按 (修改时间, 大小) 缓存在内存。
  一台约 160 个 Claude 对话、200 多个 Codex rollout 的机器上实测:冷读约 0.6〜1 秒,之后 50〜120 毫秒。
- 勾选存在数据目录的 `desktop_sessions_selected.json`(不进 git),只存 `{source, id, added_at}`,重启后保留。
- 体量阈值 200k token(`approx_tokens`;没有 usage 记录时按文件 4MB):取 Claude 默认上下文窗口。超过它的副本第一轮就要先压缩
  (又一次模型调用)或装不下,而且每次冷缓存续接都按全价输入计这 20 万以上的 token,所以要人明确确认。
- 继承表:面板登记的存数据目录 `desktop_lineage.json`(不进 git,运行时增删,重启保留);手写的 `lineage.json` 照旧生效
  (没写 `source` = claude,同名以手写为准,面板解除不了)。会话 id 只在这两份文件里,接口只回哈希前 8 位。
- 起线时只在槽的运行时与会话来源一致时下传 `WORKER_FORK_FROM`;已 fork 过的线下传 `WORKER_LINEAGE_FORKED=1`,Codex 线据此
  `exec resume` 自己的会话。Codex 首次领卡 = `codex exec fork <会话> -`,沙箱 / 批准与 resume 同在 `exec` 之前的 `-c` 配置层;
  fork 回报的 `thread_id` 经 `POST /api/workers/:line/forked` 登记(与 Claude 线同一口)。修复轮照旧走自己的续接,不碰继承。
- 测试用环境变量:`BOARD_CLAUDE_PROJECTS`、`BOARD_CODEX_HOME` 把两个根目录指到临时目录(Codex 根目录平时按 `CODEX_HOME`,没有则 `~/.codex`)。
  `node --test tests/desksessionstest.mjs` 只用合成夹具。

### 凭码接入

不用先加线、登记、存令牌三步:操作员发一个码,对方的 AI 应用把码填进 MCP 配置,第一次启动时自己换到令牌。

1. 操作员发码:`POST /api/connect/codes {kind, line?, label?, role?}`(操作员令牌或面板会话)。
   - `kind`:`claude`、`codex`、`zcode`、`other`。`label` 是显示名(≤24 字)。
   - 不给 `line`:兑换成功时新建一条外部执行线,线名发码时就定好(由 kind 派生:`claude`、`codex`、`zcode`、`bot`,
     重名加序号 `zcode-2`),兑换时走加线的同一条路(写进配置文件,不用重启)。码没兑换就过期或作废,不留线,名字下次发码可再用。
     给 `line`:必须是已有的外部执行线;受管执行线 409。
   - 同时待兑换的码(没用、没作废、没过期)最多 5 个,第 6 个 409 `TOO_MANY_PENDING_CODES`。
   - 执行者 id 默认与线同名,已被占用时加序号。发码时执行者就登记上了,但兑换前它的令牌哈希是一个不可能命中的值,谁也用不了。
   - `role`:`executor`(缺省)或 `assistant`(助手,见下文「助手能看到什么」)。助手不绑线、不建线,带 `line` 400;
     执行者 id 由种类派生(`asst-claude`、`asst-bot`……);片段里的桥参数不带 `--line`,`prompt` 是助手那一句。码没兑换就过期或作废,这个助手的登记收回(列表里不留行),名字下次发码可再用。
   - `label` 与 `live_note` 同一清洗:换行、控制字符换成空格,零宽、双向控制符、BOM 去掉,路径与令牌样串遮成「…」。
   - 应答 201:`code`(`XXXXX-XXXXX`,10 位,一次性,10 分钟有效)、`expires_at`、`line`、`executor_id`,以及 `snippets`:
     `mcp_config`(按 kind 给好的配置片段:Claude 的 `.mcp.json` `mcpServers` 项、Codex 的 `config.toml`
     `[mcp_servers.fleet-board]`(带 `default_tools_approval_mode = "approve"`,另在注释里给一次性的 `codex exec -c …` 覆盖形)、Zcode 的 `mcp.servers` 项(带 `"protocolVersion":"legacy"`)、other 给一行 PowerShell 命令,
     `& '<node>' '<桥>' '--url' …`,每个参数都是单引号字面量,路径里有 `&` `%` `!` `^` 空格也不会被切开)
     和 `prompt`(一句值守提示词,见下节)。
2. 对方把片段贴进自己的 MCP 配置。Codex 的 `codex exec` 不交互,MCP 工具默认要批准,批准策略为 `never` 时第一次调工具就失败(「MCP tool call requires approval」);片段里的 `default_tools_approval_mode = "approve"` 只对 `fleet-board` 这一个服务免批准,不改全局 `approval_policy`,别的 MCP 服务与命令执行仍按对方原来的批准设置。片段里桥的启动参数是
   `--url http://127.0.0.1:<端口> --line <线> --code <码> --token-file <令牌目录>/<执行者 id>.token`。
   令牌目录缺省是当前用户应用数据目录下看板专用的子目录:`%LOCALAPPDATA%\ai-fleet-board\executors\<看板数据目录哈希前 8 位>\`,
   **不在看板数据目录里**(操作员的 `board_token` 在数据目录)。哈希把同一台机器上的几块看板分开。
3. 桥启动时令牌文件还不存在 → 用码调 `POST /api/connect/redeem {code}` 兑换,把令牌写进文件
   (缺的目录逐级新建成只有当前 Windows 账户可访问,至多 4 级;文件同样)。令牌文件已存在 → 忽略 `--code`。
   只给 `--token-file` 的旧用法不变。兑换失败(码错、过期、用过、看板没在跑)桥启动即退出,客户端显示连接失败。

兑换的规则:

- 只接本机回环地址发起的请求(`LOOPBACK_ONLY` 403),带了别的来源页面的 `Origin` 也 403;不需要别的凭据,带了令牌也不看。
  远程入口不开放这条路径。
- 200 `{token, executor_id, line, role}`:令牌只在这一次应答里出现。码与令牌库里都只存 sha256。
- 用过的码 410 `CODE_USED`;过期或已作废 410 `CODE_EXPIRED`;没有这个码 404 `CODE_UNKNOWN`。码不分大小写,连字符可省。
- 不锁定、不按来源分桶:每次都先验码,对的码永远立即成功。错的码(以上三种都算)应答前等 200ms;同一时刻最多 20 个错码在等,
  超出的立即 429 `RATE_LIMITED`(带 `Retry-After: 1`)。暴力猜码每秒至多约 100 次,10 位码约 50 bit,10 分钟内猜中的概率约 6×10⁻¹¹;
  本机别的进程连错再多,也挡不住合法的桥兑换。
- 不给 `line` 发的码:兑换时那个线名已被一条受管执行线占了 → 409 `LINE_TAKEN`,码不消耗,请操作员重新发码。

已知限制:接入的 AI 与看板在同一个 Windows 账户下运行时,有文件工具的 AI 理论上读得到本机其它文件(包括看板数据目录里的
`board_token`)。令牌目录已移出数据目录、发码片段里也不再出现数据目录,但真正的隔离靠对方应用自己的权限设置(文件读写范围、沙箱)。
不要让接入的 AI 能读看板数据目录。

#### 绑线执行者能看到什么

凭码接入的执行者绑在它的线上,只能看到和领取 **line 恰好等于自己那条线** 的卡(line 为空的卡也不行)。
看板按令牌判,不靠桥:桥里的 `--line` 只是第二道。用令牌直接登记的执行者(上一节)不绑线,下表不适用,行为不变。

| 接口 | 绑线执行者能看到什么 |
|---|---|
| `GET /api/tasks` | 只有本线的卡(`line` 参数被改写成本线;问别的线返回空表);没有全板的 `archived_count` |
| `GET /api/tasks/:id` | 本线的卡;别的线、未指定线的卡 404 |
| `GET /api/tasks/:id/runs` · `/history` · `/decisions/:n` · `/evidence/:n` | 同上,本线的卡才给 |
| 卡上的 `live_note` / `live_note_at` | 只有自己持有的卡才有值;同线别人手上的卡、列表里的别的卡一律 `null` |
| `GET /api/coord` | 只有自己:自己的登记、自己的锁、自己写的流水、自己的交接;`external_lines` 只列本线 |
| `GET /api/approvals/request:<n>:<v>` | 只有自己发起的批准请求 |
| `POST /api/claim` | 只挑本线的卡(不挑未指定线的卡);空手时 `held_ids` 也只列本线 |
| `POST /api/tasks/:id/claim` | 别的线、未指定线的卡 403 |
| `GET /api/events`(SSE) | 404:桥是轮询,不用长连接 |
| 其它读接口(`/api/task-events`、`/api/tasks/:id/related`、`/api/workers`、`/api/usage`、`/api/setup`、`/api/meta`、`/api/context`、`/api/requests`、`/api/pools`、`/api/review/pending`、`/api/approvals`、`/api/approvals/decisions`、`/api/coord/locks`、`/api/coord/journal`、`/api/coord/executors`、卡的裁定附件……) | 404 |
| 写接口 | 与所有执行者相同(`EXECUTOR_WRITES`):领卡、续租、交付只对自己持有的卡;写状态、流水、锁、交接确认、批准请求 |

#### 助手能看到什么

助手(`role:"assistant"`)给聊天机器人、可穿戴设备背后的常驻 AI 用:只读全板 + 挂未放行卡 + 被提醒。它也是 `exe_` 令牌,
看板按登记的角色判,另走一张白名单,执行者能用的接口它一概用不了;桥(同一个 `cli/exec-mcp.mjs`)握手时调 `GET /api/connect/me`
认角色,只给它 `get_brief` / `list_cards` / `get_card` / `post_card` / `wait_for_attention` 五个工具。

| 接口 | 助手能看到什么 |
|---|---|
| `GET /api/brief?max_chars=` | 简报(与面板会话 / 操作员令牌读到的同一份):`text`(默认 ≤280 字,80–600,全部遮蔽路径与令牌样串)、`headline`(效率主句,读不到为 `null`,text 写「本周效率暂无数据」)、`attention:[{kind,task_id?,title,since,posted_by?}]`(= 首页「待我处理」那一栏 + 执行线故障;`kind` 为 `review` 待验收 / `decision` 等你决定 / `release` 待放行 / `stalled` AI 卡住 / `line_fault` 线故障 / `blocked` 受阻 / `other`)、`doing:[{task_id,title,who}]`、`done_recent:[{task_id,title,at}]`(24 小时内) |
| `GET /api/tasks` · `GET /api/tasks/:id` | 全板的卡,只给卡面、状态与来源几项(`subject` `summary` `description` `acceptance` `status` `waiting_for` `line` `released` `posted_by` 等与阻塞原因);交付证据、运行轨迹、`live_note`、方案包不给 |
| `GET /api/tasks/:id/history` | 历史摘要(与操作员同一份,已遮蔽) |
| `GET /api/connect/me` | 自己的 `{executor_id, role, line}` |
| `POST /api/assistant/cards {subject,description,acceptance,line?}` | 挂卡:一律未放行,卡上记 `posted_by:{executor_id,label}`;它挂的未放行卡(未放行、未归档、未完成)同时最多 20 张,超出 409 `TOO_MANY_POSTED`;标题去零宽与双向控制符、断行换空格,正文保留换行 |
| `GET /api/events`(SSE) | 403:助手只通过 `get_brief` / `wait_for_attention`(桥每 3 秒读一次简报)获知变化 |
| 其它读接口(运行记录、证据、裁定附件、会话清单与正文、设置、用量、效率、协作、接入管理……) | 403 `ASSISTANT_FORBIDDEN` |
| 其它写接口(领卡、续租、交付、裁定、放行、改卡、建普通卡、改配置、发码、撤销、锁、批准请求) | 403 |

执行者令牌调 `/api/brief`、`/api/assistant/cards` 被拒(绑线执行者 404,其余 403);操作员用 `POST /api/tasks` 建卡,不走助手的口。
撤销与执行者相同,令牌立即失效。`wait_for_attention` 同一件事(类别 + 卡号 + 标题 + 时刻)在一次桥连接里只提醒一次。

看谁接上了:`GET /api/executors`(只给操作员)。每个执行者一行:

| 字段 | 意思 |
|---|---|
| `online` | 最近 90 秒内有过带它令牌的请求;`last_seen_at` 是最后一次(看板在每次执行者请求时记) |
| `holding` | 手上执行中的卡 `[{id,subject}]` |
| `last_report` | 最近一次交付 `{task_id,at,outcome}`,没有为 `null` |
| `state` | `working`(手上有卡、心跳正常)、`idle`(在线、没卡)、`stalled`(手上有卡、超过 `BOARD_COORD_STALE_MIN` 分钟没心跳也没请求)、`offline` |
| `role` | `executor` 或 `assistant`(助手:`line` 为 `null`,`holding` 恒空) |
| `connected_via` | `code`(凭码)或 `token`(令牌登记) |
| `pending_code` | 有一个还没兑换、没过期的码 |
| `revoked` | 已撤销 |

`stalled` 是要人看的:卡在它手上不动了。撤销或等租约到期,卡就回到未开始。

撤销:`POST /api/executors/:id/revoke`(只给操作员)→ `{revoked:true, released:[卡号], released_locks:[资源]}`。令牌立即失效(下一次请求 401,
桥在握手阶段就失败),它已建立的 SSE 连接由看板主动断开,还没兑换的码作废,手上执行中的卡按停线时的回收规则放回未开始,
它持有的协作锁一并释放(释放理由「执行者被撤销」,推 `coord.lock {op:"revoke_release"}`),写一条 `executor.revoke` 流水。
同样会断开 SSE 的还有:执行者被注销、令牌被换发(`rotate`)、面板会话「退出连接」或被新配对挤掉;面板会话 30 天到期这类
没有撤销动作的失效,在下一次保活(至多 25 秒)时断开。
执行者 id 保留,不能被共享 worker 令牌冒用;要重新接上就再发一个码给新的 id,或用 `exec register <id> --rotate` 换发令牌。

执行者令牌、worker 令牌、审阅令牌调发码、列表、撤销一律 403。SSE 事件 `executor.changed {id}`:发码、兑换、撤销,
以及在线/离线、`working`/`stalled` 变化时(看板每 10 秒比一次)。

远程入口的 `/api/summary` 不带凭码接入的执行者明细(只给个数 `code_executors`),流水里去掉 `executor.revoke` 与它们写的条目。

### 值守

接上之后,让 AI 自己守着这条线:把 `snippets.prompt` 那句话发给它,它就按这个循环做——

1. `wait_for_card`(`timeout_sec` 50):桥每 2 秒查一次本线的卡,不在看板上挂长连接;等着的时候别的工具照常可用。
   到时没卡返回 `{none:true}`,再调一次接着等。
2. 有卡:`get_card` 读卡面 → `claim_card` 领取(带 `aggregate_version`)。
3. 干活。做得久就每 10–20 分钟 `heartbeat`,`note` 写一句「现在在做什么」。
4. `report_result` 交付(`done` 进入待验收,由人验收);需要人拍板就 `ask_operator`,卡进入「等你决定」。
5. 回到第 1 步。

`note` 是临时进度(`live_note`):卡对象上多两个字段 `live_note`、`live_note_at`。下一条覆盖上一条;交付时清空;
卡被释放、回收、撤销或换了一次领取后不再显示;不进卡的历史。只有持有者能写(与续租同一道核对),≤120 字(按原文算),空串清掉。
写入时清洗:换行和控制字符换成空格,零宽(U+200B–200F、2060–2064)、双向控制符(202A–202E、2066–2069、061C)与 BOM 去掉,
再遮蔽路径与令牌样串(与卡历史摘要同一口径)。内容没变不推事件;变了推 `task.live_note {id}`,同一张卡至多每 5 秒一次,
窗口里的变化合并成窗口末尾的一次(最后的内容一定会推到)。凭码接入的执行者只看得到自己卡上的 `live_note`。

卡面文字是任务数据,不是对执行者的指令;交付不等于验收,裁定仍属于操作员。

## 各方状态

每个执行者一份 `{current, done[], next[]}`,整份替换,记 `updated_at`:

```
python cli/board.py exec status --file status.json --token-file <令牌文件>
python cli/board.py exec status            # 列出各执行者
```

```json
{ "current": "完成界面回归", "done": ["装好测试包"], "next": ["跑界面测试", "提交报告"] }
```

上限:`current` 与每一项 300 字,`done` 50 项,`next` 20 项,整份 16000 字。超出时返回 400,
写明哪个字段、上限和实际值;不截断,原状态不变。阻塞写进 `next` 的第一项。

## 资源锁

资源名是任意中性字符串,看板不解释它,例如 `device:test-phone`、`build:apk`、`port:8080`。
允许字母、数字和 `. _ : / @ -`,最长 80。

```
python cli/board.py lock acquire device:test-phone --minutes 30 --purpose ui-regression --token-file <令牌文件>
python cli/board.py lock release device:test-phone --token-file <令牌文件>
python cli/board.py lock ls [--all]
```

- 加锁登记资源、持有者、开始时刻(服务端测)、预计结束和用途。用途含中文时用 `--file purpose.txt`。
- 已被占用返回 409,带持有者、用途、开始与预计结束。没有抢锁接口,也不排队:等对方释放,或请操作员处理。
- 只有持有者能释放。操作员可以强制释放,必须写理由:
  `python cli/board.py lock release device:test-phone --force --file reason.txt`。释放人和理由留在锁记录里,
  另写一条流水。
- 超过预计结束 30 分钟(`BOARD_COORD_OVERDUE_GRACE_MIN`)仍未释放,标为「逾期」:面板标出,
  SSE 发一次 `coord.lock_overdue`,写一条流水。不自动释放。

改设备配置、重启设备上的应用、改共享端口这类会打断别人的动作,先拿锁再做。

## 事件流水

只追加,一行一件:服务端时刻、执行者、种类、不超过 300 字的正文、产物列表。
正文、锁用途、状态的 `current` 与 `done` / `next` 各项都写成一行:含换行、制表符、其他控制字符(ESC 等)或双向控制符的
一律 400,不写入。`board.py` 打印这些文字前再把控制字符换成可见的转义(防修复前已入库的旧数据),
所以命令行输出里一行就是一条记录,`executor` 列只可能是服务端按令牌认定的名字。

```
python cli/board.py journal add --kind test.run --file body.txt \
  --artifact commit:1a2b3c4 --artifact path:out/report.txt --token-file <令牌文件>
python cli/board.py journal ls --since 40 --executor agent-one --limit 20
```

- 产物类型:`sha256`(64 位十六进制)、`commit`(7–40 位十六进制)、`path`(不含控制字符,最长 260)、
  `url`(http/https,不带用户名密码,不含控制字符)。类型名必须是字符串。任一不合格整条拒绝。
- 没有改写和删除接口;数据库触发器也挡住 UPDATE、DELETE 与按已有主键的 REPLACE(整行替换)。
- `since` 是流水编号(取其后)或 ISO 时刻;不给 `since` 时取最近 `limit` 条(默认 50,上限 500)。

## 交接包

执行者 `exec stop`,或心跳中断时,看板生成一份只追加的交接记录:

- 目标(`current`)、进度(`done`)、阻塞和下一步(`next`)、最近 10 条流水编号、仍持有的锁。
- `done` 从最近一项、`next` 从第一项起,整项放进 2000 字的预算;放不下的整项换成指针
  `{"omitted": true, "see": "full_status.done[3]"}`,指向同一记录里保存的整份状态。不从中间截断。
- 同一次停止只生成一份;重复 `stop` 返回同一份。
- 写状态、写流水、加锁放锁都不算心跳。心跳中断生成交接包之后,执行者又写了状态或流水(或动了锁)再 `exec stop`,
  看板重新生成一份(`stop_seq` 加一),接手方读到的是最后的状态;此后没有新内容时重复 `stop` 仍返回这一份。
- 下一个执行者确认接手:

```
python cli/board.py handoff ls --token-file <令牌文件>
python cli/board.py handoff show 7 --token-file <令牌文件>
python cli/board.py handoff ack 7 --token-file <令牌文件>
```

每份交接只确认一次。停下的执行者仍持有的锁不会转给接手方:接手方要用就请原持有者释放,
或请操作员强制释放。

## 一个例子

两个执行者 agent-one、agent-two 共用一台测试设备:

1. 操作员登记两人,各给一枚令牌文件。
2. agent-one `lock acquire device:test-phone --minutes 30` 后跑测试;agent-two 想改设备配置,
   `lock acquire` 得到 409,看到 agent-one 在跑回归、预计何时结束,于是先做别的。
3. agent-one 跑完写一条流水(带提交和报告路径),`lock release`,再 `exec stop`。
4. agent-two `handoff ls` 看到交接包,`handoff ack` 确认接手,然后拿锁改配置。
