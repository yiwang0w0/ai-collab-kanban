# 测试宿主环境

验证命令仍接收运行看板所需的环境；隔离由测试自己的宿主负责，不修改 `verify_environment` 的合同。

启动看板服务、执行循环、审阅循环或看守的测试，把 `tests/harness-env.mjs` 的导入放在产品模块之前，先清理当前测试进程，避免模块导入时缓存部署面的默认路由、人工闸等。再用 `harnessEnvironment()` 取子进程环境，显式写回本测试的配置、数据目录、工作仓、登记簿与假 CLI。隔离整族覆盖 `BOARD_`、`WORKER_`、`REVIEWER_`、`REVIEW_`、`KANBAN_`，含未来新增变量及 Windows 大小写变体；不改变父执行循环，过滤函数对传入字典保持只读。解释器从普通 `PYTHON` 工具配置或本机命令选择，不采用部署的 `BOARD_PYTHON`。

已登记的库自检 `selftest.mjs` 同样先隔离，再设置它自己的临时数据库、路由和登记簿；避免尚未起子进程就受部署人工闸影响。现有 `BOARD_AUTH_TEST_ROOT` 仅作为面板鉴权测试的专属目标选择器在清理前捕获，不透传到被测服务。配置缺省场景应指向本测试的空配置入口，不能依赖工作树没有 ignored `fleet.config.json`。

部分测试有意让某个变量缺失，以检查配置文件回填或默认行为；共享过滤保证这个“缺失”不会被部署面偷偷补上。测试自己的显式覆盖继续保留。SDK 测试额外剔除供应商凭据的规则不变。

运行 `node tests/harness-env-audit.mjs` 输出逐文件机器清单，也可追加一份基线的 `tests` 目录作对照。它按启动点与服务符号列静态候选、共享过滤接线和整份继承行号，不把静态清单当成完整运行证明。普通 Git、显式数据库或纯夹具子进程单列；`cli-boundary-probe.mjs` 是人工真实调用工具，不自动运行。`seven-module-baseline-probes.mjs` 用于旧安全基线的漏洞复现，其“漏洞存在”断言不是当前修复版的回归条件，也单列为手工工具；不为通过它而改动安全判据。

`tests/harnessenvtest.mjs` 用真实配置加载器证明宿主部署配置不会抢占测试入口，并检查显式覆盖仍生效；CI 沿用原验证步骤运行它。检查受影响的宿主时，可在外层保留一组假部署变量，确认测试在污染环境中仍通过。不要把假配置指向现有部署或提供真实凭据。
