# 用量结算

一张卡做完后,可以看到它花了多少词元、多长时间、多少费用,按阶段和模型分开;也可以按卡、线、模型、阶段汇总,或导出 CSV。

本页讲服务端接口与命令行。面板上的显示另行安排。

按期汇总的「效率」(本期对上期、并行、返工)见 [效率口径](效率口径.md),其中模型耗时与费用取自本账本,沿用这里「未知不当 0」的口径。

## 数字从哪里来

每一轮模型调用在 `<data>/usage_ledger.jsonl` 追加一行。这个文件只追加,不改写。

| 谁写 | 阶段 `phase` | 说明 |
| --- | --- | --- |
| 执行线(`loops/worker_loop.py`) | `initial`、`repair` | 一次尝试的首轮与续修轮;汇总时分别读成 `implement`、`fix` |
| Zcode 执行循环(`core/execution/zcode-worker.mjs`) | `initial` | 每个结算了的分派一行,汇总时读成 `implement`。供应商不给用量:词元与费用是未知,耗时取监管进程量到的墙钟。见 `docs/Zcode接入.md` |
| 审阅线(`loops/reviewer_loop.py`) | `review` | 记到**被审的那张卡**上 |
| 外部执行者(`board.py done/wait --usage`) | 自报,默认 `implement` | 见下文「外部执行者自报」 |
| 服务端的拆解、压缩、协调线对话 | `decompose`、`compact`、`coord` | 通过 `core/usage.mjs` 的 `append(row)` 写入 |

每行除了原有的 `ts、card、attempt、worker、model、effort、sid、calls、in、cc、cr、out` 之外,新增:

| 字段 | 含义 |
| --- | --- |
| `phase` | 阶段,取值见上表 |
| `duration_ms` | 这一轮模型进程的墙钟耗时(毫秒),不含验证命令 |
| `cost_usd` | 这一轮的费用(美元) |
| `cost_source` | 费用的来源,见下表 |
| `cli_version` | 执行器命令行的版本 |

**不知道的值一律写 `null`,不写 0。** 汇总时也不把未知当 0 加:一组里只要有一行某项未知,这一项的合计就是 `null`;已知部分的和在 `known` 里,未知的行数在 `unknown` 里。没有任何记账记录的卡,各项也是 `null` —— 没有记录不等于没花。

旧行没有这些新字段,照常可读:阶段按已有信息推出(审阅座席的行算 `review`,其余算 `implement`),其余新字段读成 `null`。

### 费用来源 `cost_source`

| 取值 | 含义 |
| --- | --- |
| `reported` | 执行器自己随结果回报的金额 |
| `estimated` | 按 `gates/gates_lib.py` 的单价表用词元折算。只是参考,不是账单;订阅通道本来不按美元计费 |
| `external-reported` | 外部执行者交付时自己报的 |
| `unknown` | 不知道。此时 `cost_usd` 是 `null` |

单价表里没有的模型、词元不全的轮次,都不估价,记 `unknown`。汇总里一组的 `cost_source` 是这组已知费用的来源;来源不止一种时是 `mixed`,各来源的行数在 `cost_sources` 里。

## 一张卡的结算

结算 = 这张卡名下所有用量行的合计,加上按「阶段 × 模型」的明细,以及单列的失败尝试。每一项都带词元(`in、cc、cr、out`)、调用数 `calls`、行数 `rows`、尝试数 `attempts`、耗时 `duration_ms`、费用 `cost_usd`。

- 尝试数只数实现与续修:同一次尝试里续修几轮仍是一次尝试;审阅一次不算尝试。
- **失败尝试**:最后一轮明确没通过的尝试。旧行不带结果时,后面又开了新尝试的那一次算失败。失败尝试的用量仍然计入合计,`failed` 只是把它们单独再列一遍。

卡变成「已完成」时,服务端往账本追加一条结算事件(`event: "settlement"`):

```json
{"ts":"2026-11-10T14:03:22","event":"settlement","settled_card":42,"seq":1,
 "resolved_at":"2026-11-10T06:03:22.123Z","resolved_by":"human","line":"alpha","rows_through":3,
 "totals":{"rows":3,"attempts":2,"calls":3,"in":1420,"cc":100,"cr":400000,"out":342,"duration_ms":5500,
           "cost_usd":null,"cost_source":"reported","known":{"cost_usd":0.5},"unknown":{"cost_usd":2}},
 "by":[{"phase":"implement","model":"claude-opus-5","rows":2,"attempts":2},
       {"phase":"review","model":"claude-fable-5","rows":1,"attempts":0}],
 "failed":{"rows":1,"attempts":1,"in":1000}}
```

(示例里 `by` 与 `failed` 省略了部分数字项;实际每一项都与 `totals` 同形。)

- 同一次完成只写一条。
- 卡被重开后再次完成,再写一条,`seq` 加一。数字是这张卡**到那一刻为止的累计**,不是两次结算之间的差;要看最新的,取 `seq` 最大的那条。
- 人工通过、自动验收、联动结案、目标自动完成,都会结算。
- 第一次启用时,此前已经完成的卡会各补一条结算。
- 结算事件的卡号放在 `settled_card`,不放 `card`,所以它不会被当成一轮用量。

## 接口

都是只读的 `GET`,需要看板令牌。

| 请求 | 返回 |
| --- | --- |
| `/api/usage` | 不带参数时形状不变:`{cards: {<卡号>: {rows, rounds, attempts, calls, in, cc, cr, out}}}`。面板卡面用的就是它 |
| `/api/usage?by=card\|line\|model\|phase` | `{by, from, to, groups: [{key, rows, attempts, calls, in, cc, cr, out, duration_ms, cost_usd, cost_source, cost_sources, known, unknown}], total}` |
| 同上加 `&from=…&to=…` | 只算这段时间内的行。可以写日期 `2026-11-10`(按本地日历日,`to` 含当天全天)或时刻 `2026-11-10T08:30:00`。`since` / `until` 与 `from` / `to` 同义,两种写法同时给且不一致时返回 400 |
| `by=card` 另有 | 每组加 `attempts_failed`(这段时间内有行的失败尝试数,判据与单卡结算的 `failed` 相同;卡号未知的 `?` 组为 `null`)与 `settled`(这张卡有没有结算事件,不看时间范围);`total` 加 `attempts_failed`;顶层加 `settled: {cards, rows, attempts, calls, in, …}`,是已结算卡在这段时间内的合计 |
| 同上加 `&format=csv` | CSV:第一列是分组维度,未知值是空格子 |
| `/api/usage/card/<卡号>` | 这张卡此刻重算的结算(`totals、by、failed`),加上已经写下的结算事件 `settlements` |
| `/api/usage/card/<卡号>?format=csv` | CSV:每个「阶段 × 模型」一行,另有 `failed` 与 `total` 两行 |

分组时,线 = `worker` 去掉 `@槽位` 后缀,审阅座席归为 `review`;行里带 `line` 时以它为准。哪一维缺值,就归到 `?` 这一组,不丢行。

`by`、`from`、`to`、`since`、`until`、`format` 写错时返回 400 和说明。

卡面上那个旧形状有一处变化:审阅等记到卡上的用量会计入词元合计,但不再把一次审阅数成一次尝试或一轮执行。

## 命令行

```
python cli/board.py usage ls [--by card|line|model|phase] [--from 2026-11-01] [--to 2026-11-10]
python cli/board.py usage card <卡号>
python cli/board.py usage csv [--by …] [--from …] [--to …] [--card <卡号>] [--out 文件]
```

`ls` 与 `card` 把未知显示为「未知」;只知道一部分时显示「≥已知部分」。`csv` 不给 `--out` 就打到标准输出。

## 外部执行者自报

不由看板启动的执行者,看板量不到它的用量。它可以在交付时自己报:

```
python cli/board.py done <卡号> --run <run_id> --file 证据.md --usage usage.json --token-file 令牌文件
```

`usage.json` 是一个对象,或最多 50 个对象的数组(用过几个模型就写几条):

```json
[{"model": "gpt-5.6-sol", "calls": 4, "in": 1200, "out": 300, "cost_usd": 0.9, "duration_ms": 60000, "cli_version": "0.164.0"},
 {"model": "local-llm", "phase": "fix", "in": 50}]
```

- 可写的键:`model、effort、calls、in、cc、cr、out、duration_ms、cost_usd、cli_version、session_id、phase`。词元也可以用 `input_tokens、output_tokens、cache_creation_input_tokens、cache_read_input_tokens` 这组名字。
- 不知道的项不要写。不写就是未知,看板不会替你补 0。
- 数字必须不小于 0;除费用外必须是整数。格式不对时,**这次交付整个被拒**(400),改好再交。
- 卡号、尝试号、执行者、线由看板按这次交付填写,自报里写了也不采用。
- 写了费用的行,来源记为 `external-reported`;这些行另带 `reported_by: "external"`,表示数字是对方报的,看板没有核对。

直接调接口时,把同样的内容放在 `POST /api/tasks/<卡号>/report` 正文的 `usage` 键里。

## 给服务端代码接线

拆解、压缩、协调线对话在服务端调用模型,调用结束后记一行:

```js
import { append, fromClaudeResult } from "./usage.mjs";

append({ phase: "decompose", card: id, worker: "decompose", model, effort,
         ...fromClaudeResult(parsedStdout) });   // parsedStdout = `claude -p --output-format json` 的结果对象
```

- `phase` 取 `decompose`、`compact`、`coord` 之一;有对应的卡就给 `card`,没有就不给。
- `fromClaudeResult` 把结果对象里的 `usage、total_cost_usd、duration_ms、num_turns、session_id` 换成账本的键;拿不到的项是 `null`。
- 不走 Claude 命令行时,直接给 `calls、in、cc、cr、out、duration_ms、cost_usd、cost_source、cli_version`,不知道的不写。
- `append` 从不抛错:写不进去时返回 `{ok: false, error}` 并在日志里留一行,不打断调用它的流程。
- 三处的记法(`core/server.mjs`):一键拆解记到目标卡上,没拆成的一轮也记;压缩的两步各记一行,记在那条线上、不挂卡,这两步不带 `--output-format json`,词元与费用是未知,耗时取墙钟;协调线对话每轮记一行,费用是这一轮的差额(续接时命令行报的 `total_cost_usd` 是会话累计;与对话 `usage` 上累计的是同一个值),对话已按计划建过卡就记到目标卡上,否则不挂卡,被停止、超时、输出过大的一轮也记一行(用量未知)。模型进程没有起跑的不记。
- 执行线在卡与卡之间写的压缩印记(`event: "compact"`)只是一个记号,不带用量,不参与汇总。压缩真正花掉的词元要由执行压缩的那段服务端代码用 `append({phase: "compact", …})` 记下来。
