# 面板设计规范(style guide)

> 面板(`core/panel.html`)所有颜色、字号、间距、圆角只认这一份。改视觉先改这里,再改 CSS 变量;
> 不在 CSS 里散写数值。对照物:diagram-design 的 style-guide(纸/墨/一个强调色、密度 4/10、无阴影),
> 但这是**整天盯着的操作台**,不是演示页——克制优先于好看。

## 一、原则

1. **删是最高级的改法。** 每个元素要能说出为什么在这;说不出的去掉。
2. **一个强调色,只给「需要你」的东西。** 等待中的卡、引导当前那一步、「更新到新代码」、待第二按的按钮。
   状态色(进行中/已完成/出错)退成低饱和;线的颜色只做 3px 左边条和徽章。想给四样东西上强调色=还没决定焦点。
3. **无阴影,用边框。** 只有浮层(弹窗、下拉、编辑浮层、任务侧栏)和正在移动的卡允许投影;焦点环不算阴影。
4. **字号有阶,不自由发挥。** 五档,见下表;等宽字体只给技术内容(卡号、哈希、命令、端口),不做「开发感」装饰。
5. **中文优先。** 正文 ≥ 12px;字体栈先系统中文字体;不依赖外部字体(面板必须离线自包含)。
6. **密度目标 4/10。** 最近会话、时间轴默认收起(点开才展开);上手引导、执行线、加线、「请你的 Claude 代劳」
   集中在「设置」页常显——不藏,但不挤占「全部任务」;五栏拿到整块空间。
7. **动效只在状态变化时出现**,尊重 `prefers-reduced-motion`。

### 不写注释性语句

界面正文只写**状态**和**下一步动作**。不写:

- 括号里的补充说明(`确认当前版本(开始干活前需要)`);
- 破折号夹的旁白(`你正在看它 —— 端口 47824`、`在这之前自动拉取会拒绝起线 —— 那是门在挡没确认过的代码,不是故障`);
- 「意思是…」「你正在…」「其实…」「也就是…」这类解释,以及名词定义(`「线」= 一条自动领卡的流水线…`)和机理说明。

确实需要的解释放进悬停提示(`title`)或文档,不放正文。按钮和确认弹窗写清**会发生什么**即可,不写原因论证
(「为什么要有这道门」属于文档)。上手引导的每一步:`title` = 这一步是什么,`detail` = 当前状态,
`hint` = 一句动作(没有动作就不给 `hint`),按钮文字 = 按下去会做的事。

文案闸把闭合的模板插值视为代码，检查插值外的正文；未闭合的表达式保留原文检查。例外须有理由且实际命中，失效条目删除。当前闸不覆盖所有 innerHTML 模板，完整提取另按对应任务补齐。

### 中文文案边界

- 菜单、状态、设置、空态、危险提示、悬停说明及无障碍名称使用自然中文；时间与用量用“秒／分／小时”“词元”和中文计数单位。智能体指执行身份，执行器指负责启动和管理进程的程序，不混称。
- 状态按所属语义域翻译：“已接收”不等于“已验收”，“已领取”不等于“已开工”，“已请求启动”不等于进程已被观察到；未知值显示“待核实”，不从机器字段名推断结果。
- 品牌、模型名、命令、标识、协议值、用户／模型原文和第三方日志原样保留；只给明确浏览器异常配中文提示，不用宽泛关键字覆盖业务错误。新增展示词不新增权限、状态或流程。

## 二、语义色(token)

沿用 Kanban 原有色彩与数据流；只借鉴其他工作台(Kandev)的体验思路——带图标的导航、独立设置页、统一控件、
状态徽标必须带图标或文字——不搬其代码、字体或色彩 token。默认使用暖纸色；系统深色模式使用暖褐底。两种模式均以琥珀色突出「需要你」，不靠大面积高饱和色装饰。

| token | 含义 | 暗色 | 亮色 |
|---|---|---|---|
| `--bg` | 纸(页面底) | `#1e1a16` | `#f7f2e8` |
| `--bg2` | 侧栏底(首页左右两栏、抽屉) | `#191511` | `#f2ebdf` |
| `--panel` | 面(区块底) | `#27211c` | `#fffcf6` |
| `--panel2` | 面-2(卡片/输入底) | `#312920` | `#f1e9dc` |
| `--line` | 发丝线(所有边框) | `#463a2d` | `#ddcfbb` |
| `--fg` | 墨(主文字) | `#f4eadb` | `#332b23` |
| `--dim` | 次级文字 | `#c2b19a` | `#756652` |
| `--dim2` | 柔和(占位、分隔) | `#a7957d` | `#726451` |
| `--accent` | **强调:需要你** | `#e7ab5c` | `#9b530b` |
| `--ok` | 已完成/健康 | `#8db394` | `#396a4c` |
| `--cc` | 已领取/处理中 | `#c99760` | `#80572c` |
| `--bad` | 出错/危险 | `#f08a77` | `#b74332` |
| `--warn` | 警告(心跳陈旧、脏树) | `#d7b765` | `#7f5d0e` |
| `--l0` | 目标 | `#cfb18b` | `#936544` |

规则:`--warn` 与 `--accent` 不同义——警告是「有问题」,强调是「轮到你」。`--wait` 是 `--accent` 的别名(历史类名)。

## 三、字号阶 · 字体

| token | 值 | 用在 |
|---|---|---|
| `--fs-xl` | 18px / 600 | 页面标题 |
| `--fs-lg` | 14px / 600 | 区块标题、弹窗标题;对话正文与输入框用常规字重 |
| `--fs-md` | 13px / 1.5 | 正文、卡片标题(500) |
| `--fs-sm` | 12px | 元信息、按钮、页脚 |
| `--fs-xs` | 10.5px | 眉标签(栏名、标签)、时间轴刻度 |

- `--font`:`"Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif`
- `--mono`:`ui-monospace, "Cascadia Mono", Consolas, "Noto Sans Mono CJK SC", monospace` —— 只给卡号/哈希/命令/端口。
- 眉标签(`.eyebrow` / 栏标题):`--fs-xs`、字距 `.06em`、`--dim`;计数用 tabular-nums。

## 四、间距 · 圆角

- 间距阶:`--sp-1: 4px` `--sp-2: 8px` `--sp-3: 12px` `--sp-4: 16px` `--sp-5: 24px`。
- 圆角两档:`--r-sm: 6px`(按钮、标签、徽标、输入、卡片)、`--r-md: 10px`(区块、弹窗、导航条)。不出现第三种
  (执行线状态点、单选框、开关这类正圆/胶囊除外)。
- 边框一律 1px `--line`;强调用 3px 左边条,不用整圈粗框。
- 控件变量:`--ctl-h`(控件高,32px/触摸 40px)、`--ic`(图标 16px)、`--ring`(焦点环,强调色 30%)、`--hover`(悬停底)。

## 五、组件要点

- **栏(column)**:标题是眉标签 + 计数;左边条按状态(等待中=强调色)。
- **卡(card)**:默认只露四样——第一行卡号(mono)· 执行线徽章 · 状态徽标(右对齐),第二行标题(`--fs-lg` 600),
  第三行元信息(`--fs-sm` `--dim`:心跳、租约、尝试、关键时间,以及说明卡为何不动的警示标签)。来历标签、证据、方案、
  留言框与「通过/编辑/归档」收进卡底的展开区(`<details data-stop>`);点卡片本身 = 在任务侧栏打开它。
  按钮的 `data-a` / `data-edit` / `data-open-decision` 不变,两押、版本锁、人工闸照旧由 document 级处理器负责。
  等待中的卡左边条强调色,展开区入口在「等你处理」时也用强调色。
- **按钮**:见 §六。
- **引导 / 横幅**:当前步或横幅用强调色左边条 + 5% 底色,不用整块黄底。
- **空态**:一句「现在可以做什么」,不用「暂无数据」。
- **首页**:面板默认打开首页:一条设备摘要,下面三栏——左 对话列表、中 对话、右「待我处理」「正在执行」两段;已完成进「历史」,
  五栏原样在「全部任务」。电脑 1440×900 不滚屏看到两段的标题和计数;手机 390×844 顶栏一行写两段的件数,点开才展开;
  都没有横向滚动。对话部分见 §七。
- **首页卡**:只写四样——标题(`--fs-lg` 600)、所属电脑、当前状态(图标+文字徽标)、下一步。下一步单独一行(`--fs-md`)。「待我处理」的卡左边条和「下一步」用强调色;
  执行中的卡不用强调色,心跳中断这类异常用 `--warn`。动作不在卡上:点开详情,「去处理」把你带到能处理它的地方。
- **设备摘要**:一切正常时只有一句话;同步失败、本机运行问题、设置未完成、执行线故障时才逐条展开,左边条 `--warn` / `--bad`。
  - 告警行(`.hs-alert`,首页状态条与设置页执行线共用):一句原因(哪里 + 什么问题,原因里已写了是哪里就不重复)、
    一句下一步(命令用等宽小块)、最多一个按钮——服务端一次请求能做完的那一步用主按钮,否则「去设置 / 查看详情」,否则「复制命令」。
    有日志时行尾一个默认折叠的「日志」(`details.hs-log`):连续重复的行合并成一行并写 ×N,内容按纯文本放、保留换行;
    展开状态按「哪里 + 什么问题」记住,告警行重画后照原样展开。不进正文的补充放 `title`。
  - 执行线故障按原因合并:同一原因的几条线只出一条(「执行线 设计、协调 崩溃」),各带一句下一步;外部线和运行中的线不算。
    原因的字取服务端的停止说明,面板不另译退出码。命令行 `status` 读的是同一份规则。
    订阅额度用完被看板停下的线单列一种:「订阅额度用完，已暂停」,下一步「无需操作，额度恢复后看板自动启动」,
    不建议重启,首页这一条不给「去设置」;设置页那一行的状态词写「额度用完，已暂停」。
  - 断开只说一遍:页头只写短状态「已断开 / 出错」;状态条第一行只写「下面是断开前的内容」;原因(从几点起)和下一步只在
    那一条告警里,查看日志的命令折叠在「日志命令」里,「已有任务和结果都保留」放 `title`。看板重启超过 30 秒没回来,
    页头写一句状态加一句下一步,日志路径放 `title`。
  - 服务端带出上次故障时,状态条末尾多一行灰字「上次故障：月-日 时:分 …」;没有这个字段就没有这一行。
    这一行只写发生了什么(「看板连续重启，已停止自动重启」「看板运行中断」),可能的原因放 `title`。
  - 日志展开时状态条不限高,只留日志自己那一层滚动。
- **读得到才显示**:还没随服务端到位的接口(单卡用量、用量汇总、执行器 CLI 版本),取到 404 或旧形状时对应区块整块不出,
  不报错、不显示 0;有过成功结果后读不到,写「暂时读不到」并保留上次结果。这几类读取不进每次刷新的并行读取。
- **用量的数**:未知的数不当 0——有已知部分写「不少于 X」,一行已知的都没有写「待核实」;词元 = 输入 + 输出,
  用中文计数单位;耗时写秒、分、小时;费用写「美元」,来源不是执行器自己回报时加标记「 · 估算 / · 含估算 / · 外部自报」。
  阶段写 实现、续修、审阅、拆解、压缩、协调。口径说明只进 `title`;数字用等宽数字(tabular-nums),不用强调色。
- **单机**:只有一台电脑是常态,不是缺了什么——写「本机「X」运行正常」;没有其他电脑时,页头不出「全局视图」,
  详情不列所属电脑、数据来源、未绑定的项目和跨机操作。
- **设置页**:「设置」视图依次放上手引导、执行线与自动拉取(每线一行:状态点、名称、状态词、停止时间、齿轮、启动/停止;
  停止原因和日志不写在行里,故障合并成列表上方的告警行,停止说明的原文在行的 `title`)、协作(见下「协作区」)、
  加线(带标签的表单网格)、请你的 Claude 代劳、最近会话。执行线列表下面是「执行器 CLI 版本」:每个 CLI 一行四格(`.rs`)——
  当前、最新、上次核对、实测;能判断有新版本时「最新」格带警示色徽标「可升级」,行下一句写升级命令,不放升级按钮
  (不是 npm 装的写「按这个 CLI 的官方说明升级」);判断不了新旧就不写新旧;没有配置的 CLI 整行不出;可执行文件的路径不进正文。
  格子里只写短状态:「当前」读不到写「未找到」「版本读不出」,行下一句「运行 node cli/doctor.mjs 查看原因」——警示态的格子都带下一步;
  「实测」写 已实测、部分实测、未实测,口径说明在这一格的 `title`。标题行右侧次按钮「重新核对」,按下后禁用并写「核对中…」。
  ≤620px 四格折成 2×2。左侧小目录(宽 184px、吸顶)列这几块,点击滚到该块,滚动时
  当前块左边条强调色;≤900px 变成内容上方横向滚动的标签。目录用按钮不用 `#锚点`(地址栏 # 留给 `#task=`)。
  首页设备摘要里「还差 N 步」的按钮把人带到这里。页面型视图底部留 80px、五栏留 96px(手机 112px),最后一行不被固定页脚压住。
- **协作区**:设置页「协作」一块,从上到下:待你批准、执行者、资源锁、待接手的交接、最近流水、批准令牌。区块标题下不写说明句。
  - 重画保护:待你批准、协作状态、令牌列表三块各按要显示的内容算签名,没变不动节点;变了但块里有焦点、上膛的按钮或展开的
    理由输入,等这些状态消失再画。随时间变的字(最后心跳、最近使用)原位更新;折叠的开合、批准行写了一半的备注重画后照原样。
    执行者和协调线写的字一律 `textContent`。
  - 行不共用一套列。批准行:左 种类与时间,中 标题、摘要、备注上下叠放,右 按钮。锁行:上 资源、持有者、状态、按钮,下 用途、时间。
    交接行:上 编号与执行者、原因、仍持锁数、时间、徽标,下 目标一行。令牌行一行。≤620px 种类(锁行是状态徽标)和时间一行,
    标题、摘要、用途、备注、按钮组各占整行,徽标不通栏,按钮间距 `--sp-2`。
  - 待你批准:强调色左边条只给这一块。任务类(待裁定、待验收、放行确认)的标题是按钮,行里只有次按钮「打开任务」,通过、打回、
    放行在任务侧栏里做;逾期锁的标题滚到锁表里那一行。版本确认、逾期锁、执行者请求留按钮,行里一个备注框,决定带上备注:
    逾期锁写「释放理由」才能按「强制释放」,其余可不填;强制释放的决定带锁记录编号与持有者,锁已换人(409 `LOCK_CHANGED`)时
    不弹窗,在这一块上方写「资源名：这把锁已换人，请重新核对」。
    执行者请求的摘要位置写服务端给的完整 `action`(首页「待我处理」那张卡的标题同样写全,不截两行)。
    放行确认:摘要里的【再次放行】【配置已变化】换成警示色徽标放在摘要前;摘要下逐行写「工作目录」(等宽)、「权限」、
    「预算」(金额上限 · 时限 · 轮次,有几样写几样)和再次放行时的「收回原因」;未知写「待核实」。本机面板放行不带 `confirm_rerun`。
  - 两押按钮第一下写「再按=确认」加原按钮文字(「再按=确认更新并重启」「再按=确认吊销」),4 秒不按复原。
    版本确认 / 更新的批准钮例外:第一下在行内展开「上次确认后改了 N 个文件 / 首次确认」、服务端的确认说明(`confirm`,纯文本保留换行)
    和确认说明里没有的改动行,按钮上膛且不到时复原,展开期间这一块不重画;「收起」撤回,第二下才发出决定。
  - 锁表:每行次按钮「强制释放」,点了在行内展开「释放理由」,空着时确认钮不可按;确认钮用危险样式、两押,上膛写
    「再按=确认强制释放 资源名，持有者 X」。第二下的请求带这一行画出来时的锁记录编号(`lock_id`)与持有者,由服务端比对:
    回 409 `LOCK_CHANGED` 就中止,在锁表上方写「资源名：这把锁已换人，请重新核对」(同一持有者重新加过锁写「这把锁已重新加锁，请重新核对」,
    已经放掉写「这把锁已经释放」),随后重读锁表立即重画;其他失败的原因写在理由框下面,理由留着。
    理由框里回车等于按确认钮,按住回车的连发不算。
  - 执行者卡:徽标三态——从未心跳「已登记」(静色)、有心跳「活动」(成功色,离心跳超时不到四分之一时警示色)、「已停止」(静色);
    卡底是 `--panel2`,徽标用 `--panel` 做底。一行「种类 · 最后心跳」;「当前」限两行,全文在 `title`,≤620px 或粗指针不截断;
    「下一步 N 项」折叠。
  - 交接:徽标「待接手」用静色。行里写原因、目标一行(≤620px 或粗指针换行写全)、仍持有几把锁;默认折叠的「查看交接包」点开才读,列已完成、下一步、
    交接时仍持有的锁、最近流水编号,和给接手方的等宽命令 `board.py handoff ack <编号>`;不放「确认接手」按钮。
  - 最近流水整节默认收起;执行者一列里看板自己写的两种写成「操作员」「看板」。
  - 未知值写「待核实」,不写「–」。空态一句话(「还没有流水。」「没有被锁的资源。」),里面的命令用等宽。
  - 批准令牌:「生成批准令牌」是次按钮;新令牌放在可换行的只读文本块里,旁边「复制」「收起」,显示期间不自动刷新页面。
    远程入口关闭时只写「远程入口已关闭。在配置里打开 remote_access。」,不提示去生成令牌;出错的字用 `--bad`。
  - 执行者请求与逾期锁也进首页「待我处理」(状态「执行者请求」「逾期锁」,下一步「到设置页处理」),点开到设置页的「待你批准」;
    页签标题的待裁计数加上这两类。
- **执行器设置**:齿轮打开后**停靠在执行线列表下方**;再按同一齿轮或右上角关闭即收起。标题行 =「线名 · 执行器设置」+
  执行线运行状态徽标(图标+「执行线：已停止/运行中」)+ 保存状态;下面一行短说明,其余说明收进「说明」折叠。
  每个智能体一张横向卡:卡头「智能体 N」+ 会话方式徽标;左栏表单(标签在上、控件在下、字段间距 `--sp-4`,同行两个下拉等宽),
  右栏接入状态 2×2 徽标 + 一句下一步(最多两行,全文在悬停)+「检查接入」。多个智能体纵向排列;≤760px 右栏移到表单下方,
  ≤620px 表单单列。即改即存:标题行显示「保存中… / ✓ 已保存 时:分 / ⚠ 保存失败：原因」;CAS 冲突写人话并给「重新载入」。
- **全部任务**:只留一条工具条(按卡号定位、按标题筛选)、默认收起的时间轴和五栏。筛选只在本页隐藏不匹配的卡,列头计数不变。
  手机(≤620px)五栏上方放分段控件(`.seg`,栏名 + 该栏计数,同栏头),一次只显示一栏:默认「等待中」有卡就看它,否则第一个有卡的栏;
  按卡号定位、按标题筛选时切到命中卡所在的栏;你选的栏记在本标签页(sessionStorage)。桌面宽度不出现。
- **任务侧栏**:最上面是给人看的小块(`.side-brief`),四行按顺序 —— 要做什么(服务端的 `brief`:
  `summary` 优先,其次说明开头的「【一句话】」,都没有就不出这一行,**不截长正文充数**)、现在(状态 + 下一步,
  与首页同一个 `homeStep` 判断)、结果(交付后的 `result_summary`;交付了却没取到就写「交付里没有给人看的摘要」
  并给「看完整证据」)、要你做什么(只在轮到人时出现,强调色左边条只给这一行)。任务说明 / 验收条件 /
  执行结果 / 裁定记录与关联任务,收进下面默认折叠的「给执行者看的详细说明」。
  - 「现在」这一行:没被领的卡,状态和下一步照服务端给的原因写(依赖未完成、祖先未放行、派发次数到上限…),
    原因指向的卡画成卡号按钮(`--mono`),点开那张卡;无进展写「无进展，已暂停派发」;线没在跑写「「线名」未启动」;
    都不是才写「排队中」。受阻的卡把服务端的原因写在状态下面。下一步要去别处做的,右边给一个次按钮:
    「去设置」到执行线,「看逐项记录」展开本卡的记录。进行中的卡多一行「心跳 N 秒前 · 最近输出 时:分」,
    每秒原位更新,取不到写「待核实」。
  - 轮到人时有且只有一个主按钮。下一步的字和按钮同词:「同意或否决」「通过或打回」「核对后放行」。
    验收的留言框下面不写说明句:留空按钮写「通过」,写了一句按钮写「打回并交回原线」。
  - 只差放行的卡进首页「待我处理」(状态「待放行」,排在其他待办后面);侧栏里放行核对那一节就是「要你做什么」,
    强调色左边条给这一节,按钮还是核对区里那一个。祖先未放行、还有别的阻塞、或跨机流程有自己这一步的卡不算:
    核对区照常在,放行是普通按钮。整栏重建和局部刷新用同一个判断。核对区按钮上方只写动作(「先核对子任务。」)。
  - 待人工裁定的未开始卡:「要你做什么」只写处理位置,命令行里的命令用等宽字整条写出;面板不给解除人工闸的按钮。
  - 目标卡:状态写「子任务 N/M 完成」,下面列未完成的子卡按钮,子任务全部完成后下一步写「无需操作」;不画五步条;
    放行按钮写「放行这个目标」,上膛写「再按=确认放行这个目标」;
    「更多操作」里有置顶、重新拆解、起评审卡、归档,数据属性与看板目标卡相同。
  - 未开始和等待中的卡在「更多操作」里可编辑;未开始的卡还能改说明和验收条件,按「保存」才提交,
    改了没保存时点别处不收起浮层,再点「编辑」「改执行线」也不重填,浮层里写「先保存或关闭」。
  - 卡变化重建侧栏时,折叠区的开合与滚动位置照原样恢复;换一张卡从头看。留言、方案选择、执行结果、回执记在
    本标签页(sessionStorage,读写包 try),刷新后填回,正在选方案的卡把方案弹窗重开。`#task=` 后面是纯数字时按卡号打开。
- **跨机事项按任务归拢**:委派、绑定、交付都在这件任务的侧栏里看和处理;全局视图只作总览,核对弹窗与版本校验是同一个。
  - 等对端:状态写「等待「电脑名」接收任务 / 确认绑定 / 回传交付 / 停止回执 / 结案回执」,下一步「无需操作」,
    首页进「正在执行」;「更多操作」里给次按钮「查询对端回执」「重发」。词表外的状态写「待核实」。
  - 轮到本机:「要你做什么」只有一个主按钮,是跨机流程的这一步(接收任务、确认绑定、授权接收文件、核验接收内容、
    确认候选验收…);「拒绝」「要求返工」是它旁边的次按钮。协议持有的待验收卡「通过」不作主按钮,收进「仍要手动处理」。
    委派来的卡只有协议那一个「放行此任务」,条件没满足时禁用,不标强调色、不作主按钮;这一行的标签写「放行」,
    不写「要你做什么」,没满足的原因写在「现在」那一行。
    按钮写动作,核对弹窗写按下去会发生什么(「确认绑定」:「重新提交本机对这次绑定的确认…」),协议规则不进正文。
  - 其余步骤和操作回执收进默认折叠的「协议记录」;对方回传的交付,「结果」行写文件与检查状态,证据分页在默认折叠的「证据」里,
    读失败下次展开再读。这台电脑重新登记前留下的记录写「这台电脑重新登记前的旧记录」,只读;代次只在「技术信息」里。
  - 首页的「收到委派 / 待确认绑定 / 交付已回传」点开进侧栏:落在本机某张卡上的开那张卡,否则按这件事本身打开
    (「要做什么」只用记录带的 `brief`、没有就不出这一行,来源电脑、一个主按钮、次按钮「拒绝」,任务说明与验收条件折叠)。
    地址栏记 `#action=种类:编号`,刷新后重开同一件事;已经处理完的写「这件事已处理」。
  - 核对弹窗的正文只写电脑名、任务标题、说明和验收条件;任务编号、终端编号、关系编号收进弹窗里折叠的「技术信息」。
    「确认提交」是弹窗里唯一的主按钮。
    处理说明按「命令 + 对象」记在本标签页;提交过、结果未确认的请求刷新后按原编号和原内容重试。
  - 其他电脑的卡:侧栏按任务编号取多机列表里的当前行,也有「要做什么」「结果」两行;说明、验收条件、结果、裁定只读,
    默认折叠;多机列表还没读到写「正在读取」;详细说明读失败写一句并给次按钮「重试」,不自己反复重读。
  - 电脑下拉只写电脑名,重名时第二台起加序号。「分派」在未开始、没被领取的卡的「更多操作」里:本机改执行线,
    其他电脑写「由对方电脑决定」并打开发起委派的核对;卡没登记共享项目时只有本机,旁边给次按钮「查看全局视图」。
  - 单机环境以上元素一个都不出现。
- **派发步骤条**:任务侧栏的「派发与领取」一节常显,紧跟在给人看的小块下面,不收进详细说明。节首一行「交给「线名」」,
  下面 放行 → 领取 → 启动 → 回传 → 人工验收 五步;有本轮记录的写时间(绿),没有记录的写「待核实」(灰、虚线圈),
  轮到人的一步用强调色。节内只有「逐项记录」折叠,回执刷新时开着的照旧开着;放行前核对配置时摊开不收,
  核对区下面是「放行此任务」。
- **侧栏用量**:步骤条之后、详细说明之前的一节,只给本机卡,接口读得到才有。常显一行「词元 … · 尝试 N 次 · 模型耗时 … · 费用 …」;
  下面默认折叠的「按阶段与模型」,每组一个小标题(阶段 · 模型)加八个数——输入、输出、缓存读、缓存写、调用、尝试、耗时、费用,
  四个一行排两行;有失败尝试时多一行「失败尝试 N 次 · 词元 …」;折叠区里的次按钮「导出这张卡的 CSV」。没有用量行写
  「还没有用量记录」。读数变了只换这一节,不重建留言框;折叠开着的照旧开着。
- **历史页用量**:已完成列表上方的一节,接口读得到才有。四个数排一行(≤620px 两行两个):缓存读占比、每张完成卡的词元、
  失败尝试浪费、费用合计,数字 `--fs-xl`(手机 `--fs-lg`)、不用强调色,数的范围写在数下面的小字(「14 张完成卡」「本页 N 张卡」)。
  默认折叠的「最贵的 10 张」:每行卡号、标题、费用加来源标记、词元,点一行打开那张卡的侧栏;费用有未知行的按已知部分排并写
  「不少于 X」;费用全未知的不进榜,榜尾写「N 张费用待核实」;没记到卡上的用量单列一行「未记到卡上」。右上角次按钮「导出 CSV」,
  没导出成的原因写在按钮旁。没有任何用量行写「还没有用量记录」。
- **手动建卡**:不经协调线、直接建一张卡的表单。入口是首页输入框操作行里的次要按钮「手动建卡」,表单在输入框上方展开。
  样式化面板——标题栏 + 左侧右对齐标签的字段网格(标题、说明、交给、执行配置/模型)+ 底栏(取消、「创建任务」主按钮)。
- **用词**:源码闸对用户叫「确认当前版本」(不说 bless / 接受代码 / 树哈希);确认框先列版本号和改动。
- **技术信息**:UUID、哈希、运行号、回执、委派关系一律收进详情里默认折叠的「技术信息」(`--mono`)。
  任务侧栏最下面也是这一块(任务 UID、运行号、任务版本);「更多操作」里只留短卡号。
  首页和历史页不出现长串 ID;不知道电脑名时写「另一台电脑」,不拿 ID 顶替。

## 六、控件与图标

- **按钮**(`button` 统一):高 `--ctl-h`(32px;窄屏 ≤620px 与粗指针 40px)、`--r-sm`、`--fs-sm` 500,图标与文字间距 `--sp-1`。
  - 次按钮(默认):`--panel` 底 + `--line` 描边;悬停 `--hover`。
  - 主按钮 `.pri`:强调色 12% 底 + 强调色描边与字、600。整个面板同一时刻不该有超过两三个 `.pri`。
    对话首页的落点按钮 按计划建卡、发送 用强调色实底加纸色字,禁用态 `--panel2` 底加 `--dim2` 字。
  - 危险 `.danger`:`--bad` 描边与字,悬停 9% 底。无框 `.ghost`;纯图标 `.icon-btn`(正方形)。
  - 两押按钮 armed 态 = 强调色实底加纸色字、700,与 `.pri` 的浅底一眼可分。两押按钮的图标住在 `::before`(按下换文字不丢图标);
    写了留言的「通过」换成「打回」图标。
- **输入/下拉/多行**:同高、`--panel` 底、`--line` 描边、`--r-sm`;悬停描边 `--dim2`;焦点描边强调色 + `--ring`。
  下拉用 CSS 画的箭头(随主题变色);基础样式包在 `:where()` 里,局部只写宽度等布局。
- **勾选/单选/滑块**:自绘。勾选框选中 = 强调色实底 + 纸色对勾;单选选中 = 强调色圆点;滑块 4px 轨道 + 16px 强调色圆钮。
- **分段控件**(`.seg`,单选组):互斥的少量档位(如推理强度)用它,不用滑块——一眼看出有几档、当前是哪档。只列当前执行器/
  模型声明的档位;选中项 = 强调色 14% 底 + 强调色字;每段高 `--ctl-h`,手机上平分整行。只有一档时显示该档并说明「固定单档」。
- **开关**(`label.switch`):二元的设置项用开关样式(仍是 checkbox),文案说清打开后会怎样。
- **接入/就绪状态**(`.rs`):小格子 = 状态图标 + 名称 + 值。已就绪 = 成功色圆圈对勾;待核实 = 灰色虚线圈;缺失/未启用 = 警示色三角。
- **焦点**:所有可聚焦元素 `:focus-visible` = 2px 强调色外框、偏移 2px;不得用 `outline:none` 去掉而不给替代。
- **触摸目标**:≤620px 或粗指针时按钮、输入、展开区入口、勾选标签至少 40px 高;页面不得横向溢出(1440 与 390 宽都要看)。
- **图标**:内联 SVG 图标集(页内 `<symbol id="i-…">`,`<use href="#i-…">` 引用,不外取),24 网格、1.8 描边、圆端点,
  跟随 `currentColor`,默认 16px。现有:首页 home、全部任务 board、历史 history、设置 settings、新建 plus、搜索 search、
  关闭 close、展开 chevron、通过 check、打回 undo、启动 play、停止 stop、齿轮 gear、警告 warn、成功 success、等待 wait、退出 logout、
  对话 chat、发送 send、列表 menu、文件 doc。
  按钮写「图标+文字」;纯图标按钮必须有 `aria-label` 与 `title`;图标本身 `aria-hidden`。
- **状态徽标**(`.badge`):图标+文字、`--r-sm`、`--fs-sm`;语气 `data-tone`:need(强调色,轮到你)、run(`--cc`)、ok、warn、quiet(`--dim`)。
  颜色永远不是唯一信号。

## 七、对话与计划卡

首页是对话:操作者写下要做的事,协调线回一份计划,点「按计划建卡」才建卡。版式参考桌面聊天应用,只借版式;
颜色、字号、间距、圆角仍是本规范的令牌,强调色仍只给「轮到你」。

- **三栏**:≥1100px 左 对话列表(248px)、中 对话、右 任务两段(336px),三栏各自滚动,页面不滚;设备摘要在三栏上方。
  左右两栏、抽屉和手机上的任务面板用 `--bg2` 底,中栏用 `--bg`;两栏里无框按钮的悬停底是 `--fg` 6% 叠 `--bg2`。设备摘要一切正常时是一行 `--fs-sm` 灰字,不带底和框;有告警才出框。
  ≤1100px 对话列表收进左侧抽屉:顶栏的列表按钮打开,关闭按钮、遮罩、Esc 收起。≤620px 单栏:顶栏一行是列表按钮和
  「N 件待你处理 · M 件执行中」,点开后两段盖满顶栏以下,被盖住的对话区和输入区退出 Tab 顺序与读屏,焦点进面板,
  收起回到这个按钮;输入框吸底。横幅和告警把对话区压到 400px 以下时整页才滚。
- **对话列表**:「新对话」按钮(无框、600),下面每个对话两行——标题、一行状态(协调线正在回复 / 上一轮没有完成 / 计划第 N 版 · 待建卡 / 已建卡)。
  当前对话用 `--panel` 底、不带描边,不用强调色;「计划第 N 版 · 待建卡」那一行状态用强调色。悬停时第二行状态字用 `--fg`。
- **右栏**:两段不带底和框,段标题是 `--fs-sm` 小标题加件数;卡片用 `--panel` 底;页脚一行灰字,「全部任务」「历史」是无框按钮。
- **消息**:你的话靠右、`--panel2` 底、不带描边,说话人标签只留给读屏;协调线的话靠左、不带底,标签 `--fs-sm`,上方一行小字写工具调用(「看了 N 个文件」),不展开;
  正文 14px(`--fs-lg`)、常规字重、行高 1.7;
  系统事件(已建卡、已停止、计划没过校验、建卡后又出的计划没有记)是居中的一行小字,正文照服务端写的放;
  计划没过校验那一条用 `--warn` 加警告图标。阅读宽度不超过 760px。
- **纯文本**:协调线、人和系统写的字一律用 `textContent` 放进页面,`white-space:pre-wrap` 保留换行;不解析 Markdown,不执行其中的 HTML。
- **输入框**:多行,最小高 48px、字号 14px,随内容长高到 200px;Enter 发送、Shift+Enter 换行,输入法选字时的 Enter 不发;触摸屏上 Enter 换行、用按钮发。
  焦点环画在外框上。操作行:左「手动建卡」(无框次按钮,悬停出底)、右「发送」(实底主按钮)。
- **状态一行**:在输入框上方,同一时刻只出一条——没有发出去(原因 +「重试」)、协调线正在回复(+「停止本轮」)、
  这条消息超过 4000 字(写明现有字数,发送不可按)、协调线现在不可用(原因照服务端给的写,如「找不到 Claude CLI」「这个版本还没确认过」)、
  上一轮没有完成(原因 +「重试」)。左边条:进行 `--cc`、太长与不可用 `--warn`、失败 `--bad`,都带图标和文字。
- **空状态**:标题(18px)+ 三个示例,不带图标和说明句;示例是横排的透明底小条目,点示例只把字填进输入框,不发送。
  ≥621px 标题、示例、输入框成组居中。
- **计划卡**:在消息流里,跟在产出它的那条协调线消息后面。从上到下:页眉(「计划 · 第 N 版」+ 状态徽标 + 谁定的)、
  目标(标题 + 一句说明)、子任务表、页脚(合计 + 主按钮「按计划建卡」)。强调色描边只给最新、还没建卡的那一版。
  页眉、目标、页脚左右内边距都是 `--sp-4`;行间线用 `--line` 55%。
  - 子任务一行五样:勾选(建不建)、子任务(序号 + 标题 + 一句话摘要)、执行线下拉、依赖(「第 1、2 项之后」)、要你确认。
    对话栏够宽(≥640px)摆成五列的表:表头 `--fs-sm` 不加字距,执行线下拉平时不带底和框,悬停或聚焦才出框;
    窄了执行线、依赖、确认换到第二行并带上各自的标签(已有「要你确认」徽标的那一格不再重复标签);
    手机上每条折成一行(勾选 + 标题 + 展开按钮),点开才出其余三样:摘要横跨到右缘,三个标签等宽 4.5em。
  - 改动先留在本地并标出:改过的行左边条 `--cc` + 「已改，未提交」,页脚写「N 处改动还没提交」并给「撤销改动」。
    发消息或建卡前先把改动存成新版本(作者是人);已存版本里人改过的行标「你改过」。
  - 合计只写会发生什么:「将建 1 张目标卡、N 张子任务卡，其中 M 张要你确认后放行；K 项不建」;一项都没勾时写
    「至少勾选 1 项才能建卡」,主按钮不可按。依赖的项不建(「建卡时不带这条依赖」)、执行线不在可用范围,
    用 `--warn` 小字写在那一格里。
  - 建卡后:徽标换成「已建卡」(成功色),页脚列卡号按钮(`--mono`,「目标 #12」「#13」),点开任务侧栏;勾选和下拉变只读。
    要你确认的卡建好后不放行:合计写「其中 M 张要你确认后放行」,还没放行的卡号按钮用强调色并写「#13 待放行」
    (按看板上这张卡现在的状态算,放行后自动去掉);刚建完时页脚再写一句「M 张要你确认后放行：#13。点卡号打开，核对后放行。」
  - 旧版本折成一行「计划第 N 版 · 已有新版本」,点开只读。
- **刷新后保留**:输入草稿(每个对话各一份)、当前对话、计划卡未提交的改动记在本标签页(sessionStorage,读写包 try)。
