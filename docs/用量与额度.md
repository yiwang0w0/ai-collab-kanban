# 用量与额度

本页讲两件事:看板的用量账本按「谁发起、哪一池」怎么分,以及首页额度条的数字从哪里来(合同 J2)。账本本身的行格式、单卡结算与命令行见 [用量结算](用量结算.md)。

## 先说口径

- **读数是自报。** 额度条上的百分比是操作者或执行者在各自那一侧看到后报给看板的(`POST /api/pools/reading`)。看板不去读任何订阅用量页面、不读登录目录,也核实不了这个数。
- **「池用完」只认一条硬事实**:调用被限流时记下的那一条(`POST /api/pools/exhausted`,看板暂停到复查时刻)。读数再高也不会把池标成「已用完」,读数再低也不会清掉它。
- **看板记到的用量只覆盖板内调用**(`coverage:"board_only"`)。不在账内的(`excludes`):
  - `bridge_executors_without_usage`:经桥接入、交付时没带用量的外部执行者;
  - `coordinator_seat`:外部协调席(它没有记账口);
  - `desktop_sessions`:人在桌面里自己开的会话。

  所以「看板记到的 5h / 7d」只是下限,不是这一池真实用了多少。
- 读数只影响显示(以及之后的降并行开关,默认关)。看板不按读数自动停线、改派、换座席或做任何别的事。

## 账本的 `source` 与 `pool`

每行用量多两列(读时也给旧行推出来):

| 列 | 取值 | 说明 |
| --- | --- | --- |
| `source` | `managed` 受管线 · `reviewer` 审阅座席 · `coordinator` 协调线对话 · `decompose` 拆解 · `compact` 压缩 · `external` 外部执行者自报 · `seat` 外部协调席(留位,目前没有写入方) | 值域定死。写进来的值认不出 = `"?"`,行照样计入 |
| `pool` | 配置里的 runtime id(例 `claude`、`codex`)或 `other` | 写入方给的池名是配置里的 id 就用它;否则按 `model` 查座席的 `models` 表归池;归不了(没配置 runtime 的模型、`?`)= `other` |

谁写什么:执行线(`loops/worker_loop.py`)写 `managed` 与起线时看板给的 runtime;审阅线(`loops/reviewer_loop.py`)写 `reviewer` 与审阅座席的 runtime;服务端的拆解 / 压缩 / 协调线写 `decompose` / `compact` / `coordinator`,池按模型归;外部执行者交付自报的(`appendExternal`)写 `external`,池按它报的模型归。

旧行没有这两列,读时推:`reported_by:"external"` → `external`;阶段是审阅或 worker 是 `reviewer` → `reviewer`;拆解 / 压缩 / 协调阶段 → 对应来源;实现 / 续修且有 worker → `managed`;其余 `?`。池按 `model` 归。`reported_by` 读时保留。

分组:`GET /api/usage?by=source` / `by=pool`,命令行 `python cli/board.py usage ls --by source|pool`,CSV 同理。

## 池读数

`POST /api/pools/reading { pool, window, used_pct, resets_at?, note? }`

| 字段 | 规则 |
| --- | --- |
| `pool` | 配置里的 runtime id,或 `other` |
| `window` | 1–16 字、单行,例 `"5h"`、`"7d"`(看板不解释窗名,只按名字分组) |
| `used_pct` | 0–100 的数字(存一位小数) |
| `resets_at` | 可选,ISO 时刻;不能早于现在 10 分钟以上(早了说明这个窗已经重置过,请报重置后的读数),也不能晚于 35 天以后 |
| `note` | 可选,单行 ≤80 字,遮蔽路径后存下;只在操作者的读数清单里出现,不进额度接口、不进简报 |

- 谁能写:操作者令牌(面板会话)与执行者令牌(含凭码接入、绑线的执行者)。助手、执行线(含看板派给座席的令牌)、审阅令牌 403。
- 同一写入方同一〔池, 窗〕10 秒内只收一条,多的 429 `RATE_LIMITED`。
- 表 `pool_readings` 在 `board.db`,只追加(改 / 删被触发器拒绝)。
- 应答 201 `{ok, reading:{id, pool, window, used_pct, resets_at, at, by}, pool:{id, state}, fresh_minutes:60}`。
- SSE:沿用 `pool.changed`,带完整的 `pools` / `global_stop` 与 `reason:"reading"`、`reading:{pool, window}`(不带百分比)。哨兵(`watchers/sse_watch.py`)按「哪些池用完」去重,读数不改变这个指纹,所以**不会叫醒协调席**。

`GET /api/pools/readings?limit=`(只给操作者)→ 最近的读数(新的在前,默认 50,最多 200):`{readings:[{id, pool, window, used_pct, resets_at, note, by, by_label, at}]}`。

### 有效读数

- 每〔池, 窗〕取最新一条;但 **60 分钟内有操作者的读数时,取最新的那条操作者读数**(压过更新的执行者读数)。
- 有效读数超过 60 分钟 = `stale`。

## 额度接口 `GET /api/home/quota`

只给操作者。顶层仍是 `{pools, generated_at}`;各池各一段,不合成一个数。池 = 配置里的每个 runtime;`other` 只在近 7 天账本里有它的行或有它的读数时才列出。

```
{ id, label,
  state: "down" | "low" | "ok" | "unknown",
  readings: [{ window, used_pct, resets_at, by: "operator"|"executor", by_label, at, stale }],
  ledger: { windows: [{ label: "5h"|"7d", tokens, usd, calls }], rate_per_h, coverage: "board_only",
            excludes: ["bridge_executors_without_usage", "coordinator_seat", "desktop_sessions"] },
  runway: { basis: "projected"|"unknown", minutes },
  windows: [{ label, used_pct, resets_at }] }      // 第 6 波面板在读的旧字段,形状不变
```

- `state`:`down` = 限流时记的;`low` / `ok` 只来自**新鲜**读数 —— 任一窗 `used_pct ≥ quota_low_at` 为 `low`,否则 `ok`;没有新鲜读数 = `unknown`(「待核实」)。
- `readings`:每个窗的有效读数,过期的也列出(`stale:true`),但不参与 `state`。`by_label`:操作者写「你」,执行者写它登记时的名字。
- `ledger`:看板账本里这一池近 5 小时 / 7 天的合计。`tokens` = 已知词元(输入 + 缓存写 + 缓存读 + 输出)之和,窗内一行已知词元都没有 = `null`(不是 0);`usd` 同理;`calls` = 窗内账本行数(一行 = 一轮模型调用);`rate_per_h` = 5 小时窗的 `tokens ÷ 5`。
- `runway`:同一窗最近两次读数(不分谁报的)的斜率推到 100%,从现在算起,各窗取最短。不足两次、两次同一时刻、斜率 ≤ 0(比如中间重置过)、较新的那次已过期、池已用完 = `unknown`。
- 旧字段 `windows`:用完时一格「看板暂停到」(`resets_at` 是看板的复查时刻,不是供应商的重置时刻);`ok` / `low` 时 = 各窗的新鲜读数;`unknown` 时一格空的「用量」。

首页设置 `GET` / `PUT /api/home/prefs` 多一个键 `quota_low_at`(低位线,默认 90,50–99 的整数;只有操作者能读写)。

## 助手简报

`GET /api/brief`(与助手的 `get_brief` 同一份)多一项 `pools:[{pool, label, state, window, used_pct, line}]`:每池一行,只有状态与最新一条新鲜读数的百分比(哪个窗)。不带 `by_label`、`note`、模型、会话、账本明细。`text` 不变(仍只写等本人处理的件)。
