# 对话式首页(第 1 批:服务端)

操作者在首页像聊天一样说要做什么,协调线回一份计划,人看过、改过,按下「按计划建卡」才建卡。
这份文档写服务端的接口与安全边界;面板的版式见 `docs/style-guide.md`。

## 一轮怎么跑

一条用户消息 = 协调线一轮 = 看板起一次 Claude CLI(订阅登录)。同一对话同一时刻只跑一轮。

- 首轮带 `--session-id <看板预分配的 UUID>`,之后 `--resume` 同一个会话;除提示词与会话参数外,每轮参数逐字相同
  (续接不记启动参数,参数一变前缀缓存整段失效)。对话建立时记下模型与强度,之后各轮沿用。
- 每轮的输入 = 看板摘要(各实现线的运行状态与未完成卡数、未完成的目标标题)+ 当前最新计划 + 用户消息。
  摘要与计划标为资料;人改过的字段注明「人改过」,已停用的卡注明「已停用」。
- 输出经 `--json-schema` 交回,服务端只读结果里的 `structured_output`:
  `{reply, title?, plan: null | {goal:{subject,description}, tasks:[{subject,summary,description,acceptance,line,after,needs_confirm,needs_bash}]}}`。
  不从正文里抠 JSON。
- 服务端再查一遍语义:1〜8 张、字数上限、`after` 只能指向排在前面的卡。通过才生成计划版本;不通过不生成,
  原因写进这一轮的 system 消息(`kind:"plan_rejected"`)。线名不在实现线里的,原样留在计划上,建卡时降级。
- 超时(默认 180 秒)或被停止时收掉整棵进程树。失败时对话 `status:"failed"`,`error` 写原因;再发一条消息就是重试。
  首轮没成功过就失败或被停止的,下一条消息换新会话号从头开始,并把没得到回复的消息一并带上。
  续接不到会话记录时不另开新会话(那样会丢上文而人不知道),对话停在失败。
- 每轮的用量(费用、四类词元、内部轮数、时长)记在协调线消息上,并累计到对话的 `usage`;未知的项是 `null`,不记成 0。
- 看板重启时还在跑的一轮标为失败;看板停止或重启前先收掉在跑的协调线进程。

配置(`fleet.config.json`,都可省):

```json
"coordinator": { "model": "claude-opus-5", "effort": "medium", "timeout_sec": 180 }
```

`model` 缺省取 `decompose_models[0]`,`effort` 缺省 `medium`。写了但写错,看板拒绝启动。

## 安全边界

- **只认操作员**:面板会话或操作员令牌。执行令牌、审阅令牌、执行者令牌 403;批准令牌本机接口不认;远程入口不开放这些路径。
- **协调线只读**:`--tools Read Glob Grep`、`--permission-mode dontAsk`、`--setting-sources ""`、`--strict-mcp-config`、
  `--disable-slash-commands`,不给 `--allowedTools`(不带路径的 `Read` 放行规则等于任意路径可读);写工具、执行工具、联网工具另被显式拒绝。
  读范围 = 专用空目录(cwd)+ 工作仓(`--add-dir`);数据目录、验证登记簿、全部认证目录按路径拒读。
  这一组与一键拆解相同,见 `core/board-claude-cli.mjs` 与 `SECURITY.md`。
- **协调线拿不到建卡接口和令牌**:环境剔除登记的凭据变量与看板的令牌类变量;它没有网络工具,也没有 MCP。
  建卡只发生在 `POST …/apply`,由人按下;界面上计划与建卡的状态只按服务端记录显示。
- **cwd 是专用空目录**:在系统临时目录下,按数据目录定名,看板重启后不变;起一轮前发现里面有文件就不启动。
- **源码闸**:当前版本没确认时协调线不可用(与执行线同一条规则)。
- 会话文件由 CLI 写在登录用户的 `~/.claude/projects/` 下,与用户自己的会话并列;看板不读也不清理它们。

## 接口

鉴权与现有写接口同一道。错误体 `{error, code?}`;计划检查不过是 `400 {error, issues:[{n, field, message}]}`。

| 接口 | 说明 |
|---|---|
| `GET /api/coordinator` | `{available, reason?, runtime:"claude", model, effort}`。CLI 找不到或当前版本没确认时 `available:false`,`reason` 写给人看 |
| `GET /api/conversations?archived=0\|1` | `{conversations:[…]}`,新的在前 |
| `POST /api/conversations` `{message}` | 建对话并起第 1 轮 → `201 {conversation, turn:{id, status:"running"}}`;协调线不可用 → `409 COORDINATOR_UNAVAILABLE` |
| `GET /api/conversations/:id` | `{conversation, messages, plans}`,计划按版本升序 |
| `POST /api/conversations/:id/messages` `{message}` | `202 {turn}`;正在跑 → `409 TURN_RUNNING` |
| `POST /api/conversations/:id/stop` | `{stopped}`:真的停了一轮才是 `true` |
| `PATCH /api/conversations/:id` `{title?, archived?}` | 改标题、归档 |
| `PUT /api/conversations/:id/plans/:rev` `{expected_rev, goal?:{subject?}, tasks:[{n, enabled?, line?, subject?}]}` | 人改计划,出新版本(`author:"human"`)。`:rev` 或 `expected_rev` 不是最新 → `409 PLAN_CONFLICT`;已建卡 → `409 PLAN_APPLIED` |
| `POST /api/conversations/:id/plans/:rev/apply` `{expected_rev}` | 按计划建卡 → `201 {goal_id, task_ids, demoted}`;冲突码同上 |

- `conversation`:`{id, title, status:"idle"|"running"|"failed", goal_id, plan_rev, plan_applied, updated_at, last_snippet, error?, usage:{turns, cost_usd, in, out, cr, cc}}`。
- `messages[]`:`{id, role:"user"|"coordinator"|"system", text, created_at, tools:{count, summary}|null, plan_rev, kind}`。
  `turn.id` 就是那条用户消息的 `id`。system 消息的 `kind`:`applied`、`stopped`、`plan_rejected`、`plan_ignored`。
- 计划:`{rev, author, base_rev, created_at, goal, tasks:[{n, …, enabled, edited}], applied:null|{at, by, goal_id, task_ids}}`。
  消息与计划版本只追加(库层触发器挡改写与删除)。
- 一条消息最多 4000 字(提示词随命令行交给 CLI,Windows 命令行有长度上限)。
- 事件:`/api/events` 推 `{type:"conversation.changed", id}`,只表示「该刷新了」。

## 人改与建卡

- 人只能改 `enabled`、`line`、`subject` 和目标标题;改过的字段记进 `edited`。`line` 只能取实现线或 `null`。
  协调线之后给出的新计划整份替换上一版:`edited` 清空、全部启用。第 1 批由提示词要求它保留人改过的值、不放回已停用的卡,服务端不强制。
- 建卡在一个事务里:目标卡 + 启用的子卡 + 建卡标记 + 一条 system 消息(`kind:"applied"`,写目标卡号与子卡号)。
  同一对话只成功一次(建卡标记是带前态条件的写入)。
- 子卡复用一键拆解的建卡段(`createPlanChildren`):`after` 序号换成卡号;线名不在实现线里降为「不指定线」并进 `demoted`;
  依赖指向已停用的卡时那条先后关系不带,system 消息里写明。子卡建好即可领。
- `needs_confirm` 的卡在卡面上加一段说明:动手前先停下来交人确认。它不改卡的放行与人工闸。
- 已建卡的对话还能继续聊;协调线再给计划不记版本(`kind:"plan_ignored"`)。要再拆一批,开新对话。
