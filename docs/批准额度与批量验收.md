# 批准额度、豁免、敏感标签与批量验收

合同 J6 / J7(第 9 波)。看板仍是公告板:**只记数、指路、排队并明示**。

- 批准额度 = 人批的一个带上限的许可。看板只记「批了多少、执行者报用了多少」,算出剩余与状态;
  **不据此放行或拦任何动作,也不判断「这次算不算在额度内」**。用不用、停不停在执行者那一侧。
  外部执行者是否遵守额度,看板管不了。
- 豁免只是一条记录,**不让任何闸变绿**:带未撤销豁免的卡不自动通过、不进批量。
- 批量验收只做「待本人验收」这一类,资格是许可型门:**任何一项读不到 / 判不出 = 不进**。

默认配置下(请求不带 `quota`、没有豁免、没有敏感标签、`bulk_lines` 为空)行为与旧版相同。
表都在 `board.db`,全部只追加(触发器拒改、拒删、拒按已有主键 REPLACE):`approval_grants`、`grant_uses`、
`waivers`、`waiver_revocations`、`card_sensitive`、`bulk_runs`。实现在 `core/approval-quota.mjs`。

## 批准额度

### 发起(执行者)

```
POST /api/approvals/request  {"action": "跑一次付费接口", "risk": "medium", "quota": {"uses": 3, "usd": 5, "ttl_minutes": 60}}
→ 201 {"request": {"id": 12, "approval_id": "request:12:1", ..., "quota": {"uses": 3, "usd": 5, "ttl_minutes": 60}}}
```

- `quota` 可选,至少一项:`uses` 1–100 的整数、`usd` 大于 0 不超过 10000 的数字、`ttl_minutes` 1–10080 的整数。
  不合规 → 400,请求不建。不带 `quota` = 一次性,同旧版(事项、决定、查询的形状都不变)。
- 待批准事项(`GET /api/approvals`)里这一项多一个 `quota`(请求提议的额度)。

### 决定(操作者)

```
POST /api/approvals/request:12:1/decide
{"decision": "approve", "source": {"client": "panel"}, "expected_version": 1, "grant": {"uses": 2, "usd": 1}}
```

- `grant` 可选,**只能改小不能改大**:请求写了的那一项,`grant` 不能比它大(400);请求没写的项可以加上(更严)。
  不带 = 照请求批。请求没带额度(一次性)时带 `grant` → 400:不能凭空给额度。拒绝时带 `grant` → 400。
- 最终额度写进决定记录(`decision.result.quota = {uses, usd, ttl_minutes, expires_at}`)与 `approval_grants`(同一事务)。
  到期时刻 = 决定时刻 + `ttl_minutes`;没写 = 不到期。

### 报用量(当事执行者)与查询

```
POST /api/approvals/request:12:1/use  {"run_id": "这一轮的 run_id", "usd": 0.4}
→ 200 {"grant": {"state": "active", "remaining": {"uses": 1, "usd": 0.6, "expires_at": "…"}, ...}, "note": "看板只计数…"}
```

- 只有**发起这个请求的执行者**能报(进执行者写白名单后再核当事人;别的执行者、操作者、worker、审阅、助手 → 403 `NOT_PARTY` / 403)。
- `run_id` 1–80 位字母、数字与 `_ . : -`(自报:用在哪一轮);额度带金额上限时每次都要带 `usd`(自报花费,没花钱写 0)。
- 状态:`active` / `exhausted`(次数到上限,或报的金额合计到上限;没写次数上限的额度最多也只记 100 次)/ `expired` / `revoked`。
  只在 `active` 时收;之后再报 → 409(`code` = `EXHAUSTED` / `EXPIRED` / `REVOKED`);还没批、被拒、一次性批准 → 409 `NOT_GRANTED`。
  报的金额超出剩余照记(事已发生),状态随之变 `exhausted`。
- 查询:`GET /api/approvals/request:12:1` 多一个 `grant:{proposed, granted, state, used:{uses, usd, last_at}, remaining:{uses, usd, expires_at}, revoked_at}`。
- 撤销:`POST /api/approvals/request:12:1/revoke {note?}`(只有操作者)= 追加一行;已撤销的再撤 → 409。
- 列表:`GET /api/approvals/grants`(只有操作者)= 批下过额度的请求,新的在前,带执行者显示名与动作原文。
- SSE:`approval.grant {id, op:"use"|"revoke", state}`。
- 桥工具 `use_approval {approval_id, card_id? | run_id?, usd?}`(见 [多执行者协作](多执行者协作.md))。

## 豁免

```
POST /api/waivers  {"rule": "规则名", "value": "被豁免的值(可选)", "scope": {"card": 12}, "note": "为什么", "expires_at": "2026-12-01T00:00:00Z"}
→ 201 {"waiver": {"id": 3, "rule": "规则名", "value_hash": "…", "scope": {"card": 12}, "note": "…", "granted_by": "operator", "via": "panel", "at": "…", "expires_at": "…", "revoked_at": null}}
```

- **只有操作者**读写(`GET /api/waivers?card=&line=&active=1`、`POST /api/waivers`、`POST /api/waivers/:id/revoke {note?}`)。
- `rule` 一行 ≤64 字;`value`(原值)只存 sha256,不存原值;也可直接给 `value_hash`(64 位十六进制),两者只给一个。
  `scope` 只给 `{card}` 或 `{line}` 一项(线上的豁免盖住这条线上所有卡)。`note` ≤200 字,存之前过脱敏。`expires_at` 一年以内。
- 卡对象 `waivers:[{id, rule, at, expires_at}]` = 盖住这张卡、**没撤销**的豁免(到期了也列:豁免下做过的活不因到期就当没豁免过)。
- 豁免不让闸变绿:经 `cred.registerGate("豁免")` 登记,带豁免的卡**不自动通过**(审阅判通过、线 `accept:auto` 都转人工),
  缺口写「已豁免:规则 X(操作者、2026-11-14 17:20)」;本人显式通过照常。带豁免的卡**不进批量**,敏感标签自动含 `waiver`。
- SSE:`waiver.changed {id, op:"add"|"revoke", card|line}`;卡上的豁免另发 `task.updated`。

## 敏感标签

- 卡对象 `sensitive:[…]`,取值只有 `security` / `waiver` / `spend` / `prod_write` / `secret` / `destructive` / `other`(固定顺序)。
- 只由操作者写:`POST /api/tasks/:id/sensitive {sensitive:[…]}`(空数组 = 清掉)、建卡 `POST /api/tasks {…, sensitive}`;
  或经操作者确认才建的计划项(`sensitive`;计划项 `needs_confirm:true` 而没写 → `["other"]`)。
  执行者、助手、worker、审阅令牌写不了(403;助手挂卡带这个字段 400)。未知值 → 400。
- 有未撤销豁免 → 自动含 `waiver`(不靠写)。标签不拦任何闸,只让卡不进批量。

## 批量验收

- 开关:`PUT /api/home/prefs {bulk_lines:[线]}`(只有操作者;线名要是看板上现有的线;默认 `[]` = 全关)。
- `GET /api/home/bulk`(只有操作者)→ `{items:[{approval_id, expected_version, task_id, title, line, digest, why:[…]}], excluded:[{task_id, title, line, why:[…]}], list_digest, lines}`。
  只看待验收(`waiting/review`)的卡;裁定、放行、亲手做、故障一律不进(也不列)。
- 资格(**全部满足才进;任何一项读不到 / 判不出 = 不进**,原因写「判不出:…」):
  1. 待本人验收,没有人工闸,批准列表里有它的验收项且没决定过;
  2. 线在 `bulk_lines` 里;
  3. 所有登记的自动通过闸都过(`autoGate` + 引用过期闸 + 包 / 复审 / 豁免闸);
  4. 徽标不是只凭自报(`machine_verified` / `cross_model_reviewed` / `independent_rerun`;认不出的档位不进);
  5. 没有 `stale` / `fingerprint_mismatch` / `fingerprint_missing` / `based_on_stale_spec` / `based_on_stale_ref` / `spec_deviation` / `not_target_env`,`package_gaps` 为空;
  6. `sensitive` 为空;没有豁免;
  7. 自批排除:交付者判得出(最近一次领卡的身份);卡不在审阅线上(审阅线自己交付、审阅结论也出自审阅座席 = 自批);
     徽标的依据不出自交付者自报;没有出自交付者本人的结论。
- `POST /api/home/bulk {items:[{approval_id, expected_version, digest}], list_digest}`(只有操作者):
  - `list_digest` 要等于交回的 `items` 算出来的(= GET 给的那整张清单);对不上 → 409 `LIST_CHANGED`,整次什么都不做。
  - 然后逐项重核资格与指纹(事项版本、交付指纹、徽标、标记、敏感标签、豁免、线、闸):**变了的那一项退出**(`changed`),其余照常走批准接口的决定
    (`via:"bulk"`,决定记录 `result.bulk_id` = 批号,不带 note:带 note 的通过等于交回原线)。原逻辑拒绝的(交付物闸等)进 `failed`。
  - 应答 `{bulk_id, done:[…], changed:[…], failed:[…]}`;只追加表 `bulk_runs(id, at, by, items_json, result_json)` 记一行;SSE `bulk.done`。
- 面板上唯一写口 = 一次确认框列清单(9f)。

## 助手

简报 `GET /api/brief` 多 `approvals:{grants_active, waivers, bulk_ready?, line}`:只给计数(进行中的批准额度 / 未撤销未到期的豁免 / 可批量验收),
不给内容、规则名或哈希;`mode=quiet` 时不出 `bulk_ready`;读不到的项为 `null`(不冒充 0)。「助手发起批准请求」不做。
