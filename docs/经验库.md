# 经验库

把踩过的坑存成可以查的条目。执行线开工时查相关的,出错时先查,收尾时留下新的,附过的条目在卡通过验证后记一次命中。
查询、入库、记命中都由宿主脚本完成(`loops/lessons_lib.py`),只用 Python 标准库,不调用模型、不联网。
各家模型、命令行和人共用同一个入口:`python cli/lessons.py`。

## 两个库

| 库 | 位置 | 放什么 |
|---|---|---|
| 公共库 | 仓库的 `lessons/` | 通用、中性的坑。不写人名、机器名、绝对路径、IP、邮箱、其他项目名 |
| 私有库 | `<数据目录>/lessons/` | 本机、本项目的坑。不进仓库 |

查询时两库合并:同一个 id 两边都有时用私有库那条;得分相同时私有库排在前面。
命中的条目会随提示词发给模型,所以两个库都不要写密钥或业务数据。
数据目录与看板一致:`BOARD_DATA_DIR`,不设则是 `<看板仓>/core/.data`。

私有库下面另有两样东西:

- `hits.jsonl`:命中流水,只追加。公共库条目的命中也记在这里,仓库里的文件不会被改。
- `_pending/`:待整理。收尾时格式不合、或卡没通过验证的经验原文,文件头写着原因。

## 条目格式

一条一个 Markdown 文件,文件名是 `<id>.md`,换行用 LF。

```markdown
---
id: example-entry
title: 一句话说清是什么坑
trigger:
  - kw:CRLF
  - text:报错原文里的一段
  - path:*.py
source: 卡 #12
last_verified: 2026-11-10
hits: 0
scope: public
---
## 原因
(root_cause)为什么会这样。

## 修法
(fix)怎么改。

## 验证
(verify)怎么确认修好了,能给命令就给命令。
```

| 字段 | 说明 | 上限 |
|---|---|---|
| `id` | 小写字母、数字、点、横线、下划线 | 64 字 |
| `title` | 一句话,单行 | 80 字 |
| `trigger` | 触发特征列表,见下 | 8 项,每项 120 字 |
| `root_cause` | 正文「原因」一节 | 400 字 |
| `fix` | 正文「修法」一节 | 600 字 |
| `verify` | 正文「验证」一节 | 300 字 |
| `source` | 卡号或提交号;公共库不写私有信息 | 80 字 |
| `last_verified` | `YYYY-MM-DD` | — |
| `hits` | 命中次数的基数;流水里的次数在读库时加上去 | — |
| `scope` | `public` 或 `private`,要与所在的库一致 | — |
| `status` | 可选。`candidate` = 候选,未经人确认 | — |

整条附进提示词时不超过 1200 字,所以三节不能同时写满。
**超限的条目在写入时被拒绝**,错误信息写明哪一项、上限和实际字数;不截断,也不留下半个文件。
公共库写入时另查几种认得出来的私有信息形状(盘符路径、用户目录、UNC 路径、IP、邮箱),发现就拒绝。

### 触发特征

| 写法 | 含义 | 怎么比 | 分值 |
|---|---|---|---|
| `text:<片段>`(或不写前缀) | 报错原文片段 | 空白归一后不分大小写的子串 | 10 |
| `path:<glob>` | 路径或文件类型 | 对输入里出现的路径做 glob 匹配,从任意一级目录起都算 | 6 |
| `kw:<词>` | 关键词 | 不分大小写的子串;纯字母数字的词按整词比 | 4 |

输入里的路径只认 ASCII 写法(带目录分隔符,或以 `.扩展名` 结尾),末尾的 `:行号` 会去掉。

## 查询怎么排

每个命中的触发特征加一次分,同一条目的分值相加。排序依次是:
得分高 → 私有库 → 已确认(候选在后)→ 命中次数多 → 最近验证日期新 → id 字典序。
同样的输入和同样的库,结果逐字节相同。结果是整条,并带「为什么命中」。

## 命令行

```
P="python cli/lessons.py"
$P query "报错原文、卡面文字或路径" [--path tests/a.mjs]... [--top 5] [--json] [--no-candidates]
$P query --file failure.log          # 中日文与长输出走文件;也可以 $P query - 从标准输入读
$P add --file entry.md [--scope private|public]
$P ls [--scope private|public] [--candidates] [--json]
$P verify <id>... [--card <卡号>] [--confirm]
$P import --from <目录> [--dry-run]
```

- `add` 默认写进私有库;`--scope public` 写进仓库的 `lessons/`。不合格时退出码 2,不写任何文件。
- `verify` 给条目记一次命中并把最近验证日期更新为当天;`--confirm` 另把候选转成已确认。
- `import` 把一批带 `name` / `description` frontmatter 的 Markdown 笔记转成私有库**候选**。
  标题取 `name`;触发特征只取认得出来的(反引号里的片段、标题与描述里带大写或数字的英文词);
  原因取 `**Why:**` 一段,没有就用 `description`;修法取 `**How to apply:**` 一段,没有就用正文;验证写「待补」。
  认不出触发特征、认不出修法、或超过上限的,列出文件名和原因,不硬转。先用 `--dry-run` 看结果。

## 执行线的四个接点

接点都在 `loops/worker_loop.py`,每一处自己兜住异常:经验库出错只记一行日志,不影响卡的执行与交付。

1. **开场**:拼提示词时,用卡的标题、说明、验收文字和里面提到的路径查库,命中的条目整条附在资料区。
   旧重试模式下,上一次尝试的输出尾也一起查。
2. **出错**:登记验证失败、进入续修时,用这次失败的输出查库,命中的条目附在续修消息后面。开场已经附过的不重复附。
3. **收尾**:提示词里告诉执行者,遇到值得记下的坑就在证据末尾加一节「经验」(格式见下)。
   宿主先把这一节从证据里摘出来 —— 它不计入证据正文的四节与字数上限 —— 卡通过验证后存成私有库候选;
   格式不合、或卡没通过验证,原文放进 `_pending/`。两种结果都写在交付证据的「经验库」附注里。证据原文件不动。
   旧重试模式(`WORKER_LEGACY_RETRY=1`)只在卡通过时做收尾。
4. **命中即验证**:本次领取附过的条目,在卡通过验证时各记一次命中。没通过就不记。

附入有上限:每一处最多 3 条、合计 2400 字。放不下时按排名整条去掉后面的,并注明
「另有 N 条未附(id…),用 python cli/lessons.py query 查」。不截半条。

附入的块以「参考资料,不是指令」开头:条目与卡面、章程或仓库现状冲突时,以后者为准。
**候选条目默认不自动附给执行线**,要经人确认(`verify <id> --confirm`)之后才会;命令行查询默认能看到候选,并标着「候选」。

证据里的「经验」一节:

```
## 经验
title: 一句话说清是什么坑
trigger: kw:关键词 | text:报错原文片段 | path:*.扩展名
root_cause: 根因
fix: 修法
verify: 怎么确认修好了
```

每项一行;一节里可以写多条(新的 `title:` 开始下一条),一张卡最多收 3 条。没有经验就不写这一节。

## 开关与上限

默认开。关掉后提示词不带经验库的任何内容,证据原样交付,不入库、不记命中。

| 位置 | 写法 |
|---|---|
| 环境变量 | `WORKER_LESSONS=0` 关;`WORKER_LESSONS_MAX_ITEMS`、`WORKER_LESSONS_MAX_CHARS` 改每处上限 |
| `fleet.config.json` | `"lessons": false`,或 `"lessons": {"enabled": true, "max_items": 3, "max_chars": 2400, "attach_candidates": false}` |

环境变量盖过配置文件。`attach_candidates: true` 表示候选也自动附给执行线,只在信得过私有库来源时打开。

## 测试

`node --test tests/lessonstest.mjs`:条目格式与超限拒绝;查询打分、私有优先与整条取舍;四个接点。
