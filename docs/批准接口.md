# 批准接口

看板里等人点头的事项散在几处:等裁定的卡、等验收的卡、显式执行配置的放行、版本确认、逾期的资源锁、
执行者主动提出的请求。批准接口把它们汇成一张单子,人在任何客户端(面板、命令行、远程客户端)批准或拒绝,
看板都记下来源和操作者。

批准接口不另起一套状态机:列表每次从现状算出来,决定路由回这类事项原有的处理逻辑
(裁定、放行、bless、更新、锁的强制释放),版本冲突照旧返回 409。

## 事项

`GET /api/approvals` 返回 `{approvals: [...], count, now}`,按 `created_at` 从早到晚排。每一项:

| 字段 | 含义 |
|---|---|
| `id` | `类型:对象:版本`。对象一变版本就变,同一个 id 只对应一个确定的状态,可以重放 |
| `kind` | 见下表 |
| `title` | 一行标题,例如 `#12 修导出按钮` |
| `summary` | 白话一行:卡片优先用 `result_summary`,其次 `summary`,再次标题 |
| `detail_ref` | 去哪看:`{type, id?, api, panel?}`,`api` 是本机看板上的详情接口 |
| `created_at` | 事项出现的时刻;版本确认没有自带时刻,取看板进程第一次看到它的时刻 |
| `expected_version` | 与 id 的版本段相同,决定时原样带回 |
| `actions` | 可选动作,`approve` / `reject` 的子集 |
| `labels` | 两个动作在这一类事项上的叫法,例如逾期锁是「强制释放 / 保留」 |
| `blocked` | 只有 `reject` 可选时,说明为什么现在批不了 |
| `risk`、`executor` | 只在执行者请求上 |

| `kind` | 什么时候出现 | 批准 | 拒绝 |
|---|---|---|---|
| `decision` | 卡在等待中、待裁定 | 原 resolve `approve` | 原 resolve `reject`,回到未开始 |
| `delivery` | 卡在等待中、待验收 | 原 resolve `approve`,交付物闸照常检查 | 原 resolve `reject` |
| `release` | 选了执行配置的卡未放行 | 原 release,带当前执行配置与续修轮数摘要 | 不改卡,只留记录 |
| `version` | 代码已更新待重启(`version:upgrade:…`),或当前版本待确认(`version:bless:<树>`) | 更新并重启 / 原 bless | 不改,只留记录 |
| `lock` | 资源锁超过预计结束加宽限仍未释放 | 原操作员强制释放,`note` 作理由 | 不改,只留记录 |
| `request` | 执行者主动请求 | 只留记录 | 只留记录 |

- `decision` / `delivery` 的 `note` 与面板、`board.py approve|reject` 的留言同义:写了留言就是给执行者的指示,
  卡交回原线继续,不会直接完成。
- `release` 的版本段含执行配置摘要;配置变了,旧 id 批不下去。配置不可用时只给 `reject`,`blocked` 写原因。
- 更新(`version:upgrade`)有卡正在跑时返回 409,`needs_force: true`;等它们交付后再批准,或在面板上更新。
  批准后返回 202,看板随即重启。
- 拒绝了的版本确认、逾期锁、放行确认靠决定记录不再列出;对象再变化(新版本、新的一次持有、卡被改过)会以新 id 出现。

`GET /api/approvals/:id` 返回 `{approval, decision}`:还在等就有 `approval`,决定过就有 `decision`,两者都没有是 404。
`GET /api/approvals/decisions?limit=` 是最近的决定记录。

## 执行者请求批准

执行者在做会打断别人的动作之前,可以先问人:

```
POST /api/approvals/request   {"action": "重启共享设备上的应用", "risk": "high"}
→ 201 {"request": {"id": 3, "approval_id": "request:3:1", "executor": "agent-one", ...}}
```

- 只接受执行者令牌。`action` 白话一行,最多 300 字;`risk` 是 `low` / `medium` / `high`。
  换行与制表符折成空格;其余控制字符(ESC 等)与双向控制符直接 400。各类事项的 `title` / `summary` 里
  若有这类字符(来自卡片标题、锁用途或旧数据),一律换成可见的占位符;`board.py approvals` 打印前再转义一遍。
- 请求存进只追加的表,同时写一条 `approval.requested` 流水。每个执行者同时待批准的请求最多 20 个。
- 执行者用 `GET /api/approvals/request:3:1` 查结果:`decision.decision` 是 `approve` 或 `reject`,`note` 是人的留言。
  批准只是记录,动作仍由执行者自己去做;需要占用设备的,照旧先拿锁。

## 决定

```
POST /api/approvals/:id/decide
{"decision": "approve", "note": "可选", "source": {"client": "phone-app", "device": "可选"}, "expected_version": 7}
```

- `id` 放进路径时做 URL 编码。`source.client` 小写字母开头,1–32 位;`device` 最多 64 字。
- 先核对:这一项还在、id 与当前一致、`expected_version` 一致、动作可选。不一致返回 409,带 `current`(当前这一项,
  可能为 null);已经决定过返回 409,带 `decision`。
- 路由到原有处理逻辑;原逻辑拒绝(交付物闸、版本冲突、配置变化)照旧返回它的状态码,这时不留决定记录。
- 成功后在同一个事务里写一条 `approval.decided` 流水和一条决定记录。流水正文形如
  `批准 delivery:12:7。操作者 operator,来源 phone-app/desk-1,经 remote 100.64.0.20。导出按钮修好了`。
- 决定记录只追加(触发器挡住 UPDATE、DELETE 与按已有主键的 REPLACE),主键是事项 id,所以同一项不可能决定两次。字段:`decision`、`note`、`actor`(操作者)、
  `via`(凭据通道)、`source`(客户端自报)、`ip`(只在远程入口)、`at`、`journal_id`、`result`。

`via` 由凭据决定,`source` 由客户端自报:

| 凭据 | `via` | `actor` |
|---|---|---|
| `board_token`(命令行) | `local` | `operator` |
| 面板配对凭据 | `panel` | `operator` |
| 批准令牌(远程入口) | `remote` | `approval-token:<令牌编号>` |

本机接口上只有操作员能决定;执行者、worker、审阅令牌一律 403。

## 面板与命令行

面板「设置」→「协作」顶部是「待你批准」:每项一行,按钮按两下生效,来源记为 `panel`。同区下方是批准令牌:
远程入口状态、有效令牌、吊销、生成。新令牌只显示一次。

```
python cli/board.py approvals ls
python cli/board.py approvals approve delivery:12:7
python cli/board.py approvals reject request:3:1 --file note.txt --device desk-1
python cli/board.py approval-token create --label phone --save <令牌文件>
python cli/board.py approval-token ls
python cli/board.py approval-token revoke 1
```

`approvals approve|reject` 不给 `--version` 时用 id 的版本段;`--client` 默认 `cli`。

## 远程入口

给另一台设备上的批准客户端用(例如私有手机上的 App 经 VPN 调用)。**默认关闭**,关闭时看板只监听回环地址,
行为与没有这项配置时完全一样。

```json
{
  "remote_access": {
    "enabled": true,
    "listen": ["100.64.0.10:47830"],
    "allow_ips": ["100.64.0.20", "192.0.2.0/28"]
  }
}
```

- `listen`:`"IP:端口"` 或 `"[IPv6]:端口"`,必须是显式 IP。通配地址 `0.0.0.0`、`::` 默认拒绝启动;
  确需监听全部网卡,另加 `"allow_wildcard_listen": true`。
- `allow_ips`:IP 或 CIDR,不接受 `/0`。不在列表里的来源一律 403。
- 打开时配置有一处不合格,看板拒绝启动并说明哪一项。监听失败(地址不在本机、端口被占)只记日志,
  本机看板照常;`approval-token ls` 和面板显示监听状态与失败原因。
- 改配置后重启看板生效。

远程入口只开放:

| 方法与路径 | 内容 |
|---|---|
| `GET /api/approvals` | 待批准事项 |
| `GET /api/approvals/:id` | 单项与决定记录 |
| `POST /api/approvals/:id/decide` | 决定,正文最多 4KB(按 UTF-8 字节算) |
| `GET /api/summary` | 只读摘要:看板计数与版本、执行者与各方状态、未释放的锁、最近 20 条流水 |

其他路径一律 403。

鉴权:

- 只认批准令牌:`Authorization: Bearer apr_…`。操作员令牌、面板配对凭据、执行者令牌、worker 令牌一律 401。
  本机接口也不认批准令牌。
- 批准令牌由操作员在面板或命令行生成,库里只存 sha256,明文只显示一次;吊销立即失效。有效令牌最多 20 枚。
- 同一来源 10 分钟内用无效令牌失败 10 次后,后续的无效令牌返回 429。令牌先于失败计数校验:有效令牌不受同一来源
  失败次数的影响(同地址的别的程序发坏请求锁不住持有者);不带令牌的请求只得到 401,不计入失败次数。
- 带 `Origin`、`Sec-Fetch-Site` 或 `Sec-Fetch-Mode` 头的请求视为浏览器请求,一律 403;远程入口不回 CORS 头。
- 带有效令牌的每次调用写一条只追加的审计:时刻、来源地址、方法、路径、状态码、令牌编号、拒绝原因。面板的批准令牌接口
  `GET /api/approval-tokens` 带最近 20 条。
- 没通过认证就被拒的请求(路径无效、来源不在白名单、浏览器请求、限流、无效令牌)不逐条写:每个来源每种原因每分钟
  只写第一条,其余只计数,一分钟后补一行「原因 +N」;全部来源合计每分钟最多 20 组,超出的并成一行来源为 `*` 的
  `denied +N`。审计表只追加、删不掉,所以未认证的来源不能决定它长多快。这类响应带 `Connection: close`;
  每个监听最多同时 256 个连接。

客户端示例:

```
curl -H "Authorization: Bearer $TOKEN" http://100.64.0.10:47830/api/approvals
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"decision":"approve","source":{"client":"phone-app","device":"phone-1"},"expected_version":7}' \
  http://100.64.0.10:47830/api/approvals/delivery%3A12%3A7/decide
```

### 安全边界

- **只适合经 VPN 或可信局域网访问,不要暴露到公网。** 不要做端口转发、公网隧道或反向代理到公网。
- **没有自带 TLS。** 令牌和内容在网络上是明文;链路加密靠 VPN(例如 WireGuard 类的加密隧道)。
  在不加密的局域网上,同网段的人能看到令牌。
- 来源地址白名单只是第一道;能伪造或借用白名单地址的人仍要有批准令牌。白名单和令牌都不防同一台设备上的恶意程序。
- 批准令牌能批准列表里的一切,包括让看板更新重启、强制释放别人的锁。手机丢了就立即吊销。
- 远程入口不能建卡、改卡、起停线、改设置、生成令牌,也读不到卡片正文与证据,只有事项摘要与只读摘要。
- 本机试用时可以把 `listen` 设成回环别名(例如 `127.0.0.2`),用它模拟另一个地址。
