# 执行器接入与首个任务

沿用「设置」页「执行线与自动拉取」里每条执行线旁的齿轮设置，不新增工作台或执行流程。模型、推理强度、许可、并发上限与冲突保护仍由原设置接口管理；中文展示沿用暖纸／暖褐色变量。

## 设置中可以确认什么

- 安装：只读检查现有 CLI 命令文件；文件存在不证明登录或模型可用。
- 配置：宿主命令是否已配置；执行器许可与执行线启动分别展示。
- 检查接入：显式执行原非调用探测，不领取任务、不验证登录、不调用模型。失败提供原诊断，不据此反推“未安装”。
- 真实任务：最近 100 次同线运行中，只有本轮宿主启动记录与最终尝试的结果回传同时存在，且执行器、模型、强度一致，才显示“已回传结果”。它不是人工验收或当前账号状态证明；旧历史缺记录仍显示“待核实”。

打开设置才读取一次接入事实，不让每秒刷新扫描历史，也不覆盖尚未提交的设置或 CAS 版本。重新打开后不沿用旧探测结果。

## 原生启动记录

Claude／Codex 任务由宿主在成功创建进程后报告。新记录复用 `task_events`，绑定当前卡、运行、租约、受管独立凭据、智能体实例和尝试次数；不续租、不推进状态、不增加重试。记录未送达时提示“待核实”，不为补记录重新调用模型。

领取、宿主创建进程、模型输出、结果回传、人工验收各自保留含义。Broker 继续只读原签名回执，不能用旧循环事件替代缺损回执；没有补造历史或更改数据库结构。

## 一张真实样本的必要条件

操作者提供并确认工作仓、执行器和预算；本人确认当前看板版本。样本使用新卡，保留既有任务与数据，不运行目标拆解、模型审阅或其他执行器。一次尝试、明确时限与预算，不自动重试；结果留在同一卡供操作者确认。

条件缺失时停在对应步骤，不把非调用探测或合成进程当作真实任务完成。Zcode 与直接 API 不在本批范围。
