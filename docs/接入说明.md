# 接入说明:让别的 AI 来看板领任务

看板是一块公告板:你把任务挂上去,接入的 AI 各自来领、干完回报,验收仍归你。看板不替 AI 跑工具,也不代管它们自己的批准。

下面按对方是谁分节,每节都是同一个顺序:**在面板发码 → 把配置粘到对方那里 → 发一句提示词 → 面板上应当看到什么 → 不用了就撤销**。
接口与规则的全文见 [多执行者协作.md](多执行者协作.md) 的「凭码接入」「值守」两节;本文只写操作步骤。路径一律用占位(`<看板目录>`、`<你的项目>`)。

## 共同的第一步:发接入码

1. 打开面板 → 设置 →「接入的 AI」→「接入一个 AI」。
2. 选种类(Claude / Codex / Zcode / 其他),名称可不填,按「发接入码」。
3. 面板显示三样东西,**只显示这一次**:接入码(`XXXXX-XXXXX`,一次性,10 分钟有效)、「要粘贴的配置」、「开工提示词」。
   两段文字旁边都有复制按钮。码过期了按「重新发码」。
4. 不指定线时,对方第一次连上(兑换成功)才新建一条外部执行线,线名由种类派生(`claude`、`codex`、`zcode`、`bot`,重名加序号)。
   码没用就过期,不留线。同时待兑换的码最多 5 个。

配置里的桥会在第一次启动时用码换到自己的令牌,存进当前用户应用数据目录下看板专用的子目录(不在看板数据目录里),之后不再需要码。

## Claude Code

1. 发码时选「Claude」。
2. 把「要粘贴的配置」并进项目根目录的 `.mcp.json`(`<你的项目>/.mcp.json`)的 `mcpServers` 里;文件不存在就新建,内容就是那一段。
   已有别的服务器时只加 `fleet-board` 这一项,别覆盖整份文件。
   ⚠ 这段配置里有本机的绝对路径(node、桥、令牌文件,路径里带 Windows 用户名):**不要把含它的 `.mcp.json` 提交进仓库**,
   项目受版本管理时先把 `.mcp.json` 加进 `.gitignore`(或改用 Claude Code 的用户级 MCP 配置)。
3. 在这个项目里重新开一个 Claude Code 会话;第一次会问你是否启用项目里的 MCP 服务器,选允许。`/mcp` 里应当看到 `fleet-board` 已连接。
4. 把「开工提示词」整句发给它。它会循环:等卡 → 读卡面 → 领取 → 干活(做得久会写一句「现在在做什么」)→ 交付 → 再等。
5. 面板上应当看到:「接入的 AI」里这一行从「等待接入」变成「空闲」;它领到卡后变「在做」,首页右栏那张卡写「在做 · 对方自报」,
   对话里的进度消息写「#13 Claude 在做(自报)」(执行方写发码时填的名称,没填就是种类名「Claude」;小写的 `claude` 是线名);
   交付后卡进「待你验收」。
6. 撤销:在「接入的 AI」那一行按「撤销」。令牌立即失效,手上的卡放回去等重新领取。再要接上就重新发码。

## Codex

1. 发码时选「Codex」。
2. 把「要粘贴的配置」(一段 `[mcp_servers.fleet-board]`)追加到 Codex 的 `config.toml`(当前用户目录下的 `.codex/config.toml`)。
   已有同名一节就先删掉旧的,不要留两节。
   片段里有一行 `default_tools_approval_mode = "approve"`:只对 `fleet-board` 这一个 MCP 服务的工具免批准,不改全局的
   `approval_policy`,别的 MCP 服务与命令执行仍按你原来的批准设置。没有这一行,`codex exec` 这类不交互的跑法第一次调工具就停在批准上。
   不想改 `config.toml`、只跑一次的话,片段最后一行注释里给了同一组设置的 `codex exec -c …` 覆盖形,复制那一串参数即可。
3. 重新启动 Codex(命令行或桌面版都要重开一次),让它读到新配置;它的 MCP 列表里应当有 `fleet-board`。
4. 把「开工提示词」整句发给它。
5. 面板上应当看到的与 Claude 一节相同(行名是 `codex`)。
6. 撤销同上。

## Zcode 桌面版

1. 发码时选「Zcode」。
2. 打开 Zcode 的 MCP 设置,把「要粘贴的配置」里 `mcp.servers` 下的 `fleet-board` 一项并进去。那一项带 `"protocolVersion": "legacy"`,
   别删:它让 Zcode 直接用桥支持的握手版本。
3. 保存后重启 Zcode(或在它的 MCP 设置里重连这一项),应当显示 `fleet-board` 已连接;连接失败多半是码过期或看板没在跑,重新发码再贴一次。
4. 新开一个对话,把「开工提示词」整句发给它。
5. 面板上应当看到的与 Claude 一节相同(行名是 `zcode`)。
6. 撤销同上。

这一节是「Zcode 桌面版自己当执行者」;由看板监管、按预算调用 Zcode 的那条路是另一回事,见 [Zcode接入.md](Zcode接入.md)。

## 其它 bot

发码时选「其他」。「要粘贴的配置」是一行 PowerShell 命令(每个参数都是单引号字面量),在要接入的那台机器、同一个 Windows 账户里运行,
它就是一个 stdio 的 MCP 服务器:你的 bot 若能挂 stdio MCP,就把这条命令配成它的服务器;不能挂 MCP 的 bot,
改用命令行 `python cli/board.py` 加 `--token-file <令牌文件>` 领卡和交付(见 [多执行者协作.md](多执行者协作.md)「执行者与令牌」)。
提示词、面板显示、撤销与上面相同(行名是 `bot`)。

## 证据图与说明的版本(所有执行者)

- **附截图**:`attach_evidence {card_id, path, note?}`。`path` 写本机文件的绝对路径;桥在你这一侧读文件、先验文件头与大小,再把字节传给看板,
  看板不按路径读盘。只收 png / jpeg / webp(按文件头判,不认扩展名),单个 ≤2MB,每张卡 ≤10 个,同一张图只记一次;
  只有手上持有这张卡时能附。图只给操作员在面板上看,不进简报、不进 md 导出(导出只写「附图 n 张」与哈希)。
- **说明改过了**:卡放行之后,标题 / 说明 / 验收 / 必需检查每改一次版本 +1(`get_card`、`claim_card` 给 `spec_version`)。
  `heartbeat` 的应答带 `spec_changed:{current, yours}` 时,先 `get_card` 重读卡面再接着做;`heartbeat` / `report_result` 可带
  `seen_spec_version` 写明按哪一版做的(不填时桥带上 `get_card` 给过的版本)。按旧版说明交付的卡会标「基于旧版说明」,不会自动通过。
- 老桥不带这两样也照常能用:不附图、不带版本;说明没改过就不会被标成旧版。

## 助手怎么接

给聊天机器人、可穿戴设备背后的常驻 AI 用:它不来领任务,而是把看板当工具——看近况、替你挂一张卡、有事时提醒你。

1. 发码时角色选「助手(只看和挂卡)」,种类按对方的应用选(多数选「其他」),名称写一个你认得出的(面板上会写「<名称> 挂上 · 待你放行」)。
   助手不绑线,不建线。
2. 把「要粘贴的配置」配成对方的 stdio MCP 服务器(与上面同一个桥,只是不带 `--line`;桥按令牌的角色只给它助手那几个工具)。
3. 把「开工提示词」发给它:「你是操作者的助手:先 get_brief;要记一件事就 post_card(会等操作者放行);空闲时 wait_for_attention。」
4. 它能用的工具:
   - `get_brief {max_chars?, since?, mode?}`:`text` 是给小屏幕看的中文(默认 ≤280 字,`max_chars` 80–600),**只写等你本人处理的件,
     每件一行、动词开头**(「验收 #12「…」」「去做 #13「…」」「放行 #15「…」」「查看「线 A 崩溃」」),放不下的写在末行「查看其余 N 件」;
     本周效率主句只在 `headline`;在做的、刚完成的在 `doing` / `done_recent` 条目里。面板「待我处理」那一栏就是它的「等你处理」。
     `lines` 是各线一行现况(`state` 在做 / 空闲 / 卡住 / 已停 / 离线、在做几张、一句 `note` 取自执行者自报的「现在在做什么」),
     全部遮蔽路径与令牌样串,不带会话标题;由本地会话登记的线只写「Claude 会话线」这类通用名。
     `cursor`:原样当 `since` 交回,下一次就多给 `changes`(这之后出现过的件与完成的卡,至多 50 条)。
   - `list_cards` / `get_card`:全板只读(卡面、状态、历史摘要;不含交付证据全文与裁定附件)。
   - `post_card {subject, description, acceptance, line?, origin?, quote?}`:挂上的卡**一律未放行**,首页「待我处理」写「<名称> 挂上 · 待你放行」,
     你核对后放行才会被领。它同时挂着的未放行卡最多 20 张。`origin` 是它**自报**的来源:`operator_said`(说是你亲口说的,`quote` 写原话,
     ≤200 字,压成一行、遮蔽路径)或 `ai_inferred`(它推断的,缺省)。看板不核实这一项,面板也只写「<名称> 称:…」,放行前照样核对卡面。
   - `wait_for_attention {timeout_sec, since?, mode?}`:有待验收、等你决定、待放行、AI 卡住、线故障时返回 `{items, cursor}`,到时返回
     `{none:true, cursor}`;同一件事只提醒一次。
     - **游标**:看板按它的令牌(只存哈希)记「已确认到哪」——它交回的最大 `since`。断线重连(新进程、不带 `since`)从记下的位置接着给,
       不重刷全部、也不漏;某件给出去了但它没来得及交回游标就断了,重连会再给一次(宁可重一次,不丢)。
       `since` 只认看板发过的值,乱写 400;它只决定从哪里开始给,给的内容与不带时同一份。撤销令牌时游标一起删掉。
     - **静音**:`mode:"quiet"`(会议中等不便打扰时)只给紧急的——线故障、AI 卡住、受阻;别的件不丢,`muted` 写压下了几件,
       切回 `normal` 后按游标补发,静音期间给过的紧急件不再重给。`get_brief` 带 `mode:"quiet"` 时 `attention` 与 `text` 也只留紧急件。
   - 它**不能**发起批准请求让你在它那边裁定:那等于让助手令牌转达你的裁定,属于权限取舍,目前不做。
5. 它不能领卡、交付、裁定、放行、改设置,也读不到会话清单与正文、运行记录、别人的「现在在做什么」和事件流(SSE)。
6. 撤销与上面相同:令牌立即失效。

## 只会读写文件的 AI(md 交接)

有的 AI 只能读写文件,不能挂 MCP、不能调命令。这时由人代为提交:看板把任务导出成一份 md 给它读,它把回报写成 md,人再交上来。
跨模型交接(一个模型写队列文件,另一个模型或看板接着做)也走这条路。三条命令都在 `<看板目录>` 下运行,都只认操作员令牌
(交付那一步按现有规则,执行者令牌或操作员令牌都行)。

```powershell
python cli/board.py export-md <卡号|目标号> [--out <文件>]
python cli/board.py import-md <文件> [--line <线>] [--goal <目标号>]
python cli/board.py report-md <卡号> <文件> --run <run_id> [--as <线>] [--token-file <令牌文件>]
```

**导出**:卡面(标题、说明、验收、线、依赖)和已有的回报、裁定写成一份 md;给目标号时 = 目标写在文件头,下面一卡一节(全部直接子卡)。
导出只改下面这几样,其余原样(代码块、`$ ` 命令行、`> ` 引用行、反引号里的内容、URL、提交号、长标识符、空行与换行都保留):

- 令牌样串换成「…」:`exe_` / `apr_` / `tok_` / `pat_` 开头的长串、`ghp_` 等 GitHub 令牌、`sk-` 开头的密钥、`xox?-` 开头的 Slack 令牌、
  `AKIA` / `ASIA` 开头的访问键、JWT 三段串、`Bearer` / `Basic` 后面的串。
- 用户家目录前缀换成 `~`(`C:\Users\<你>\proj\a.md` → `~\proj\a.md`);别的路径、内网地址、口令不遮,写进卡面前自己斟酌。
- 控制字符、零宽字符、双向控制字符去掉(换行与制表保留)。
- 结构行(`## 标题`、`#### 第 n 次 · 时刻 · 执行方 · 结果` 这类行里的标题、执行方名、线名)里的换行并成空格:
  字段里的换行不会在导出里另起一节,导出的文件再导入不会多出原来没有的卡。
- 正文里以 `#` 开头的行(含原文就以 `\#` 开头的行)前面加一个反斜杠;没有闭合的代码块围栏行也加一个,免得它吞掉后面的小节;
  标题以 `#` 开头时同样加一个(`## \#12 …`)。导入时各去掉一个,往返不变。

卡的历史、进度摘要、`live_note` 用的是另一套更重的清洗(私有路径、长 ID / 哈希、反引号内容、内网地址、
`密码` / `password` 后的值也遮),与导出无关。

**导入**:从一份 md 队列文件批量挂卡。

- 新卡**一律未放行**:导入后到面板上核对,再放行。
- 任何一节不合格,**整份不导入**,命令逐条列出「第 N 行:哪一节、什么问题」,退出码非 0。改好再导。
- 同一节再导一次不重复建卡,回「已存在 #卡号」(按内容哈希:标题 + 说明 + 验收 + 线 + 依赖 + 目标,改了任一样就算新卡)。
  上次建的那张已归档时不算已存在:重新建一张,命令写明「同一内容的 #旧卡号 已归档,重新建了一张」。
- `--goal` 只收目标卡的卡号(正整数);普通卡号、非数字一律拒绝。
- 线:节里写了「线」用节里的,没写用 `--line`,都没有就不指定线。`--goal` 把新卡挂到这个目标下(同一目标下标题不能重名)。

队列文件的格式:

- 第一个 `## ` 之前随便写(文件说明),导入时不读。
- 一卡一节:`## 标题`,下面是小节 `### 说明`、`### 验收`(两个都必须有内容),可选 `### 线`(一条线名)与 `### 依赖`
  (每行或逗号隔开一项:`#卡号` = 板上已有的卡;别的写法 = 本文件里排在它前面的那一节的标题)。
- 标题和第一个小节之间只能空着,或写 `> ` 开头的引用行(导出时卡号、状态写在这里,导入时不读)。
- 导出才有的 `### 回报`、`### 裁定` 导入时跳过;别的小节名一律报错(防止把「验证」错写成「验收」后悄悄丢掉)。
- 正文里以 `#` 开头的行前面加一个反斜杠(`\# …`),导入时去掉一个;代码块(``` 或 ~~~ 围起来,两种分开计:同一种字符、
  不短于开头那一行才算闭合)里的 `#` 不算标题。标题以 `#` 开头时写成 `## \#…`。

最小样例:

```markdown
## 写登录页
### 说明
做一个登录页,用户名加密码。
### 验收
能登录;错密码有提示。
### 线
alpha

## 写登录接口
### 说明
后端校验接口。
### 验收
接口测试通过。
### 依赖
写登录页
```

**回报**:`report-md` 就是 `done <卡号> --file <文件>`,同一条交付路径:要先有人领卡(`take <卡号> --version <版本>`,
输出里有 run_id),再把 AI 写好的 md 当证据交上来;卡进「待你验收」。卡要求四节证据时照旧校验,不合格就被拒。

## 可信(合同 H1–H4)

交付时可以多带几样(全部可选;不带 = 与以前完全相同):

```
report_result { id, outcome, evidence,
  base_commit?, head_commit?,                 // 完整 40/64 位十六进制;别的写法整次交付不收(400)
  files?:[{path, sha256}],                    // ≤50;相对工作仓;绝对路径、盘符、..、.git、冒号一律拒收
  checks?:[{name, status:"pass"|"fail"|"unverified", how?:"ran"|"inferred", baseline?:bool}] }   // ≤50;永远记成自报
```

- 看板给每次交付算一个 `digest`(提交 + 文件 + 交付正文的哈希,文件顺序无关)。线配置了看板可读的工作仓时(受管线 = 看板自己的工作仓;
  外部线在线配置里写 `"work_repo": "<绝对路径>"`),看板用只读 git 查询核对:`verified:true` 核过,`null` 核不了(= 自报),`false` 对不上
  (交付照收,徽标降到自报并标 `fingerprint_mismatch`)。`files[].sha256` 是该文件在 `head_commit` 里的内容(提交里的字节)的 sha256。
- 任务对象、卡详情与 `GET /api/tasks/:id/history`(操作员)多给:`fingerprint`、`checks`、`evidence_counts`、`badge`、`baseline`、
  `required_checks`、`conclusions`(审阅结论与人工验收,各带当时的 digest 与 `stale`)。助手的读面不变(不含这些)。
- 徽标与「机器验证」只由看板(受管线宿主的独立凭据)与审阅座席写;你报的 checks 再全是 pass 也只算自报。各档含义见 [可信度徽标](可信度徽标.md)。
- `required_checks:[name]`:操作者建卡时带(`POST /api/tasks`),或计划项带;之后只有操作者能改:`POST /api/tasks/:id/required-checks {required_checks:[...]}`(空数组 = 清掉)。
  有必需检查的卡,自动通过要它们全有已核的 pass;不满足转人工验收。
- 面板(合同 H7):已完成行、卡片与侧栏各一个徽标(来历在 ⓘ),侧栏「证据与检查」写三栏计数(已核 / 自报分开)、实查 / 推断、基线已红、必需检查逐项与证据图;
  人工验收的确认处逐条写缺什么(不拦人)。画法见 [可信度徽标](可信度徽标.md)「面板上怎么看」。

## 占用与整合(合同 I6–I9)

几张卡同时动一个仓时,看板帮人看清「谁在动哪里、合到哪了」。全部只提示或只读:看板不合并、不推送、不改工作仓,也不拦领卡。

- **文件占用**:操作者建卡(或计划项)时可写 `touches:[路径]`(相对工作仓,`/` 结尾 = 整个目录,≤50),之后用
  `POST /api/tasks/:id/touches` 改;执行者开工后用桥的 `declare_paths { card_id, paths }` 声明自己这一轮要动的路径(覆盖式,交付或停下后自动失效)。
  还没验收的卡,最近一次交付的 `files` 也算占用。`GET /api/occupancy` 列出每条路径上的卡与重叠;领卡、`declare_paths`、交付(done)的应答
  与任务对象都带 `overlaps:[{path, with:[{id, line}]}]`。同一对卡同一路径只发一次 `occupancy.overlap` 事件。助手只在简报里看到重叠条数。
- **整合阶段**:目标卡可写 `integrate:{target:"refs/heads/<分支>", assemble?:true}`(`POST /api/goals` 带,或 `POST /api/tasks/:id/integrate`)。
  线有看板可读的工作仓时,看板每 30 秒只读核一次:每张已完成子卡最近交付的 `head_commit` 是否已在目标分支里 → 子卡 `integration:{state:"merged"|"pending"|"unknown", target}`;
  首页组头 `stage` 在子卡全完成且有待合时为 `integrate`,`stage_detail.integrate:{merged,pending,unknown,target,target_sha}`。没写 `integrate` 的目标同以前。
- **候选组装卡**:`assemble:true` 的目标,子卡全部完成后看板在目标下出一张**未放行**的「候选组装」卡(`auto_kind:"assemble"`),说明列出
  待合提交(按依赖先后)、每笔已核 / 自报的检查与没跑的必需检查、文件重叠、基线红,最后一步「推送后核远端」。只出一次;子卡重开再完成时重拼说明。
- **条件放行**:未放行的卡可写 `release_on:{card:<卡号>, event:"done"|"delivered"}`(建卡、计划项或 `POST /api/tasks/:id/release-on`,`null` = 撤销)。
  源卡完成(或交付)后看板按人放行的同一条路放行这张卡(卡历史「按条件自动放行」,只触发一次);祖先没放行时照样领不走。
  等条件的卡不进「要本人做的事」;源卡不在了或归档 → `release_on.broken:true`,回到人手里。
- 这几样字段只有操作者能写:助手挂卡带了 400,worker 派生卡带了 403。
## 关系(合同 I1–I5)

卡之间的关系只由操作者写;执行者、助手、worker 令牌一概写不了(助手挂卡带这些字段 400,worker 派生卡带 403)。

- **能不能领只有一份判定**:`wait_for_card`(以及不带参数的 `GET /api/tasks?status=not_started` 列卡)只交出现在真能领的卡;
  旧桥不改也一样。领不了的卡在 `get_card` 的 `blockers` 里写阻塞码(如 `RESOURCE_BUSY`),`claim_card` 被拒时 409 带 `code` / `detail`。
- **取代**:`POST /api/tasks/:id/supersede {by}`(`by:null` = 撤销)。被取代的卡没开始 → 不可领(`SUPERSEDED`);你手上执行中的卡被取代 →
  `heartbeat` 应答带 `superseded:{by}` 与 next「停手,交回」(看板不强收,租约照常;用 `report_result outcome=wait` 说明停在哪)。
  依赖指向被取代的卡时,按取代链上最新一张算。
- **依赖作废**:依赖卡做完后又被重开,等它的卡(已完成 / 执行中 / 已交付)挂 `basis_changed:[{dep, at, kind:"reopened"}]`,
  执行中的 `heartbeat` 应答带上它 —— 做的前提可能变了,先 `get_card` 确认。操作者看过后 `POST /api/tasks/:id/basis/ack`。
  依赖卡没做完就被归档 → 下游阻塞码 `DEP_ARCHIVED`(进「要本人做的事」)。
- **同批**:建卡 / 计划项 `batch:"名字"`(或 update 改;同名至多 20 张)。依赖指向批里任何一张 = 等全批完成。
- **互斥资源**:建卡 / 计划项 `needs:["db:fixture"]`(名字规则同资源锁,一卡 ≤8),或 `POST /api/tasks/:id/needs {needs}`。
  有别的执行中卡声明了同名资源,或资源锁有人持着(逾期也算)→ 不可领(`RESOURCE_BUSY`,detail 写谁、哪张卡或哪把锁、多久)。
- 任务对象多给 `superseded_by` `supersedes` `batch:{key,members,done,total}` `needs` `basis_changed`。
- 被取代的卡不算占用、不进候选组装清单;条件放行的源卡被取代 → `release_on.broken:true`,由人处理。
- **面板上**:卡面、首页行与侧栏「关系与占用」一节写这些关系(弱化,说明在悬停);写入口只给操作者,在卡的「关系与占用…」对话框里
  (取代 / 撤销、同批名、需要的资源、会改的路径、条件放行、目标的整合分支与候选组装勾选),校验失败照服务端原因显示。
  「全部任务」工具条的「文件占用」列出 `GET /api/occupancy`,重叠的排前面。

## 引用、底提交与卡死(合同 I10a–c)

都由操作者写(建卡、计划项、专门接口;见 [多执行者协作](多执行者协作.md)「引用、底提交与卡死」)。执行者这一侧要知道的:

- **引用某一版说明**:卡上 `refs:[{card, pinned, current, stale}]` 说「照 #S 的第 v 版说明做」。`get_card` 你手上执行中的卡引用的卡
  —— 跨线也行 —— 只给标题、说明、验收与说明版本(`ref_view:true`);别的别线卡照旧读不到,交回之后也读不到。
  #S 的说明在钉之后改了:你在做 → `heartbeat` 应答带 `refs_stale:[{card, pinned, current}]` 与 next「规格已改,先读新版」(看板不强制);
  还没领 → 不可领(`REF_STALE`),等操作者看过后重钉(重钉会让你这张卡的 `spec_version` +1,走「说明的版本」那条路)。
  交付时引用已过期 → `based_on_stale_ref:true`,这张卡不自动通过。
- **复审卡**:操作者给引用打了 `review:true` 时,你交付后看板会在被引用卡那条线上出一张未放行的复审卡(`auto_kind:"spec_review"`)。
  领到复审卡的一方:对照卡面写的 #S 说明看交付,在 `report_result` 的 `checks` 里给一项 `spec_conformance`(pass = 符合,fail = 不符),偏差写进正文。
- **底提交**:卡上 `base:{commit, onto?}` 说「从这个提交开始做」。看板只读核:`state` = `ok` / `missing` / `diverged` / `unknown`,`behind` = `onto` 比它多几笔。
  `missing` / `diverged` 的卡不可领(`BASE_GONE`);你在做时变成这样 → `heartbeat` 应答带 `base_gone:{state}` 与 next「底变了,停手问人」。
  交付的 `base_commit` 与卡上的不同 → 徽标标 `base_differs`(只提示)。
- **卡死**:`report_result` / `ask_operator` 可带 `reason_code`(`[a-z0-9_]{1,32}`,如 `missing_input`)。同一张卡连着被回收、被退回、
  交回没做完、或以同一原因码停下达到阈值(默认 3)→ 卡上挂 `stuck`,不可领(`STUCK`),等操作者看过后清零;排队领会跳到下一张。
- 这几个阻塞在 `progress_blockers` 里带 `attention`(`decide` / `fault`),进操作者的「要本人做的事」。
- 复审卡判「不符」且结论没过期(这张卡之后没再交付、规格没改版本)→ 这张卡不自动通过,缺口写明是哪张复审卡判的;人的显式裁定不受限。
- 看板自动出、还没放行的卡(复审卡 / 核对卡 / 候选组装卡)不拖住目标结案,也不算进计划组头的「执行 n/m」;放行后照常计。
- **面板上**(第二轮):卡面、首页行与侧栏「关系与占用」写「引用 #S · 钉 vN」(过期「现 vM · 已过期」,侧栏有「重钉」)、
  「对照规格复审 · 板出的」与它复审哪张卡的哪次交付、底提交「在 / 不在了 / 分叉了 / 未核 · 落后 n」、「卡死 · 连续 n 次…」(展开看最近几步,
  侧栏「清零继续」可带一句备注);徽标弱化标记多「照的是过期的引用」「对照规格复审 · 一致」「复审判与规格不符」「交付的底与卡上的不同」。
  「要本人做的事」里引用过期的按钮字是「重钉」、卡死的是「清零继续」(都只带去侧栏)。「关系与占用…」对话框多三项:引用(≤8,每条可勾交付后对照复审,整组覆盖保存)、
  底提交(写 / 撤销)、目标环境;设置 → 协作里有「连续几次算卡死」。

## 包与环境差(合同 I10d–e)

有些交付最后要**人亲手跑**(部署脚本、迁移、贴到别的系统里的文件)。「包」让人跑之前确认:跑的就是预审过的那一份。
看板只登记各步的事实、从事实推出状态;不替谁跑、不按执行者给的路径读盘。

- **六格**:`draft`(`declare_package`)→ `frozen`(`freeze_package`,冻结哈希表)→ `committed`(`package_committed`,可选;
  线有看板可读的工作仓时 30 秒定时扫里只读核该提交里各文件的 sha256,单文件超 5MB 不核)→ `issued`(`issue_package`,桥算出包目录里的哈希,
  看板比对冻结表)→ `ran`(人跑完后在面板上点「我跑完了」= `POST /api/packages/:id/ran`,只有操作者)→ `pinned`(要核的项全 ok)。
  状态取已达到的最远一格;重新冻结 = 新的一轮,旧的提交 / 出包 / 跑都不再算。
- **drift**(对不上)的三种来路:冻结后重报的文件不同、提交里的内容与冻结表不同、出包的文件不同(含缺文件)。任务对象写明停在哪一格之前、哪一步对不上
  (`drift_detail:{before, step, why}`),审阅 / 验收结论绑 `frozen.digest`,对不上或重冻后过期。
- **谁能报**:只有这张卡的「当事执行者」—— 持这张卡的,或卡在等验收 / 等裁定时最近交付它的外部执行者。受管线本波不能报包;助手只看到 `packages_count`。
- **要本人做的事**:出包且一致 → 一条「亲手做」:做什么 = 跑包「名」,实物在哪 = label,期待 = expect(标「对方写的」),做完解锁 = 依赖这张卡的下游;
  出包不一致 → 一条故障「出包后的文件和预审时不一样,先别跑」。跑过之后不再列。
- **核对卡**:跑完(ok)且包写了 `pins` → 看板在原卡同一父卡下出一张未放行的核对卡(`auto_kind:"pin"`,线 = 原卡的线;同一包同一冻结轮只出一次);
  操作者在 `ran` 里带 `release_pin:true` 就由操作者放行。核对卡的持卡者用 `report_pin` 报每一项(自报),审阅座席报的算已核。
- **自动通过**:带包的卡,每个包都要跑过且 ok、要核的项全 ok、没有 drift,否则不自动通过、转人工;缺口逐条在任务对象 `package_gaps` 里。人的显式裁定不受限。
- **md 导出**只写包名、状态、冻结摘要短号,不写 label 与文件路径。
- **环境差**:操作者可给卡写 `target_env:"标签"`(建卡、计划项、`POST /api/tasks/:id/target-env`;单行 ≤40)。执行者交付的 `checks[]` 可带 `env`(自报);
  看板推 `env_gap:{target, verified_in, same}` —— 已核通过的检查里有 env = 目标 → `same:true`,有 env 但都不是 → `false`,没有 env 或没写目标 → `null`。
  机器验证而 `same` 不是 `true`(且写了目标)时徽标带 `not_target_env`。执行者可用 `report_env_diff` 报它那边与目标的差 → 任务对象 `env_diff:{by:"executor", items, at}`。
- **面板上**:卡有包时侧栏多一节「包」:每个包一条六格流水线(草稿 · 预审 · 已提交〔可空着〕· 出包 · 本人已跑 · 钉住 n/N〔已核 a / 自报 b〕),
  对不上时写明停在哪一格之前、哪一步对不上;出包一致且还没跑 → 「我跑完了」(确认框:结果成功 / 失败、一句备注、要钉的包可勾「同时放行核对卡」);
  label 原样显示,`expect` 标「对方写的」,文件哈希表收在展开区。卡面 / 首页行只放一个弱标记(例:「包 2 · 待你跑 1」)。
  「要本人做的事」里的包条目照接口给的 what / where / expect / 解锁显示。写了 `target_env` 的卡写「目标环境 X」,验证不在那里跑时写「验证跑在 Y,不是目标环境」,
  `not_target_env` 写进徽标 ⓘ;执行者报的差在侧栏列成小表(项 / 这里 / 目标,标「对方报的」)。
- 审阅座席经 `/api/packages/:id/pin` 写的核对项,卡历史写「审阅座席核过包「名」的「项」(已核)」;核对卡持卡者报的写「(自报)」。

## 回执与桥(合同 J3)

看板记下它发给执行者的东西对方「拉取过 / 应答里给过 / 确认过」,只给操作者看(任务对象 `receipts`);**回执不说明模型读懂了**,看板也不据此放行或拦任何动作。
表见 [多执行者协作](多执行者协作.md)「看板发给执行者的东西各有什么回执」。

- **拉取过**:每次 `get_card` 看板记一笔「谁、哪一版说明、几点」(5 秒节流)。读引用的别线卡记在那张卡上,单列,不算进 `read`。
- **提示确认**:`heartbeat` 应答带 `superseded` / `basis_changed` / `refs_stale` / `base_gone` 时另有 `notices`;照 `next` 处理后,下一次 `heartbeat` 带 `ack:[那些码]`。
  不带也照常能用,面板写「已送达 · 未确认」。未知码 400、这次心跳不收。
- **人写给你的话**:人打回 / 裁定时写的话,`get_card` 的 `operator_note:{text, at, kind, by}` 带给你(看板已遮掉路径与令牌样串)。再领到这张卡时先按它做。
  (核实过:这之前经桥的 `get_card` / `wait_for_card` / `claim_card` / `heartbeat` 都拿不到这段话。)
- **自报用量**:`report_result` 可带 `usage:{model?, in?, out?, cc?, cr?, cost_usd?, duration_ms?, calls?}`,只收数字与模型名,记成 `external-reported`;应答 `usage_recorded` = 记了几行。
- **在哪等人**:`ask_operator` 可带 `where_hint:{app?, host_label?}`(`app` 取 claude-desktop / claude-code / codex / zcode / other,`host_label` 一行 ≤40 字)。
  只是给人指路的自报说明:看板不跳转、不替谁点任何东西,也没有「已批准」的意思;助手看不到 `host_label`。
- **额度读数**:`report_pool {pool, window, used_pct, resets_at?, note?}` 报你这一侧看到的额度(自报),只影响额度条显示。
- **旧看板**:新字段全部可选。看板不认时桥在应答里明示(`ack_unsupported` / `where_hint_unsupported` / `usage_recorded:null` / `UNSUPPORTED_BY_BOARD`「看板版本不支持」),不静默吞。

## 已知限制

- 接入的 AI 与看板在同一个 Windows 账户下运行时,有文件工具的 AI 理论上读得到本机其它文件,包括看板数据目录里的操作员令牌。
  令牌目录已经移出数据目录,但真正的隔离靠对方应用自己的权限设置(允许读写的目录、沙箱)。不要让接入的 AI 能读看板数据目录。
- 看板自己监管的执行线对令牌目录(`<应用数据>\ai-fleet-board\executors`)的禁读,与对数据目录的禁读在同样的通道生效:
  API / SDK 通道、Claude 命令行座席、看板自起的 Claude 命令行(拆解、压缩、协调线)。Codex 命令行座席本来就没有路径级禁读
  (数据目录也没拦,只有提示词纪律),令牌目录同样没拦。用 `--token-file` 放到别处的令牌文件不在保护范围内。
- 「设置 → 本地会话」把一段桌面对话登记成线时,这条线带着那段会话的全部内容;它交付的证据别的执行者读得到,内容会随证据外流。
  有不该外传的内容的会话,不要登记成线。
- 看板只看得到对方的请求,看不到它的进程:外部执行者的「在做」是它领卡后自己发的心跳(面板写「对方自报」),不是看板观察到的。
- 交付不等于验收,裁定仍归你。
- 助手挂的卡同样是任务数据:放行前请核对卡面,别把一句随口的话直接交给执行线。
