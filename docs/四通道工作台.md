# 单项目四通道工作台

Kanban 继续管理任务、放行、领取、回报和人工验收。CLI 与 API 是不同执行通道；界面、任务状态机、关联和原数据库沿用，不复制其他工作台。

## 通道与安装

| 执行配置 | 入口 | 认证与计费 |
| --- | --- | --- |
| `claude-cli` | 原 Claude 执行循环 | 独立 Claude 订阅登录 |
| `codex-cli` | 原 Codex 执行循环 | 独立 ChatGPT 登录，保留原解禁门 |
| `claude-api` | Claude Agent SDK 0.2.174 | 独立 Anthropic API 凭据 |
| `gpt-api` | Codex SDK 0.164.0 | 独立 OpenAI API 凭据，不借用 ChatGPT 订阅 |

旧智能体没有 `execution_profile_id` 时仍沿原 CLI 路径运行。显式选择配置后不自动换账号、通道、模型或收费来源，不触发共享池的额外模型探测。API 默认未启用且无预算，不因安装 SDK 自动获得调用许可。

兼容约定变更（2026-10-28，操作者决定）：原先「旧路径行为不变」，无执行配置的旧线与审阅线原样继承宿主环境、只拒绝数据目录内的固定文件。现改为两处：一、宿主环境去掉所有配置登记的 `credential_env` 变量（含自定义名称）；二、Claude CLI 文件工具拒绝读写全部配置的认证目录。原因是自定义名称的 API 凭据（如 `CLAUDE_PROD_KEY`）原样进了旧线的 CLI 子进程和验证命令，认证目录自定义到数据目录之外时旧线文件工具也能读。旧线只剔登记名，不套显式配置的整套名称规则：`ANTHROPIC_API_KEY`、`CLAUDE_CONFIG_DIR` 等标准变量照常继承，旧 CLI 依赖它们登录时不受影响；但若把某个标准名登记成 `credential_env`，旧线也拿不到它。

在看板源码目录安装固定依赖；不会升级全局 CLI：

```powershell
npm.cmd ci --ignore-scripts
python -m pip install -r runners/requirements.txt
```

## 私有配置

在本机私有 `fleet.config.json` 的 `execution_profiles` 中覆盖内置配置。密钥只由指定的宿主环境变量提供，不写进配置、任务、日志或 Git；所有配置的凭据变量（含自定义名称）都不进入 CLI、审阅线或其他 API 执行线。例如以下配置仍保持禁用：

```json
{
  "execution_profiles": [
    { "id": "claude-api", "enabled": false,
      "credential_env": "KANBAN_ANTHROPIC_API_KEY", "budget": null },
    { "id": "gpt-api", "enabled": false,
      "credential_env": "KANBAN_OPENAI_API_KEY", "budget": null,
      "provider_spend_limit_confirmed": false }
  ]
}
```

启用前由操作者明确模型和预算。Claude CLI 与两个 API 配置仍要求 `budget.timeout_sec`、`max_turns`、`max_cost_usd`；Codex CLI 只要求正数 `timeout_sec`，`max_turns`、`max_cost_usd` 可为 `null`，不能为了通过配置门填写虚构金额。GPT SDK 本机只提供时限／步骤控制，不能承诺金额硬封顶；须由用户配置供应商项目侧花费限制并明确确认 `provider_spend_limit_confirmed`。实际扣费以供应商账单为准，未知费用不能记为零。

各通道的内部计数并不相同：Claude 使用原生轮次限制，GPT SDK 将 `max_turns` 用作文件工具步骤预算，不能把步骤数当成模型请求次数。当前 Codex CLI 仅强制单次执行与宿主超时，没有已核实的内部轮次或金额硬帽；若授权要求“最多若干内部轮次”，该授权不足以启动 Codex CLI，须先由操作者另定可接受的边界，不能静默放宽。

Codex CLI 保留 `BOARD_CODEX_RELEASED=1` 与 `BOARD_CODEX_CMD` 指向原生绝对 `.exe` 的原解禁门；不接受 `.cmd`／`.bat`。显式配置示例为 `{"id":"codex-cli","enabled":true,"auth_home":"<工作仓外的订阅认证目录>","budget":{"timeout_sec":600,"max_turns":null,"max_cost_usd":null}}`。宿主先用不带强制认证参数的 `codex login status` 只读核实登录方式，API key 登录、未知或超时均拒绝生成，不注销原登录；不能直接对日常认证目录运行强制 ChatGPT 的生成命令，以免 CLI 清除原 API 登录。核实后才用 `forced_login_method="chatgpt"` 固定订阅认证，并复用既有凭据过滤，只恢复该配置的 `CODEX_HOME`；worker、审阅线和协调模板共用此合同，不允许自动改用 API key。旧线未设 `CODEX_HOME` 时也先核实其默认登录。启用前由操作者在所选目录完成 ChatGPT 登录，不能复制其他通道凭据代替登录。

开发板 #4 本批只验证通道闭环与[协调线一轮模板](Codex协调线模板.md)，认证目录、看板令牌与登记簿的路径隔离已由操作者移至未放行的 #8。本批不初始化提权沙箱，也不宣称上述敏感路径已被 CLI shell 隔离；环境剔除与只读沙箱均不能代替路径拒读。

每个配置使用互不重叠且位于工作仓外的 `auth_home`；默认在本机数据目录的 `auth/<配置标识>`。显式 CLI 配置需要用户在对应目录完成订阅登录，不能以命令存在冒充已登录；API 不覆盖用户日常登录。修改私有配置后按原停止／启动流程重启，保留数据目录，不重新 setup 覆盖配置。看板向每条执行线下传全部配置的认证目录清单，所有 Claude CLI 执行线（旧线、审阅线、显式配置）的文件工具按路径拒绝读写这些目录，数据目录内的 `auth/**` 规则不变；Windows 上 Claude Code 2.1.234 实测 Read、Grep、Glob 都被拒，未列入的对照目录照常可读。本看板当前 Codex CLI 接线未完成认证目录路径隔离：0.149.0 的权限档虽有拒读条目（filesystem 访问 `none`），但 Windows 上只有提权沙箱后端能执行，未提权的受限令牌沙箱遇到拒读条目直接拒绝运行（实测报 `Restricted read-only access requires the elevated Windows sandbox backend`）；提权后端要管理员安装，会创建沙箱本地账户并改认证目录的 ACL，看板不代为启用。CLI 通道与看板以同一个系统用户运行，Codex CLI 的 shell 和宿主执行的验证命令都不能按路径限制，若要将宿主验证命令也隔离，须另行设计独立系统账户或受控执行边界。0.149 的结论仅是该版本的历史证据，不能代替 0.165 的路径拒读验证。

看板服务端自己也直接调用 Claude CLI：一键拆解与上下文压缩（`core/board-claude-cli.mjs`）。两者沿用用户默认登录，环境与旧线同一规则：剔除全部配置登记的凭据变量，另去掉看板自身的令牌类变量，标准登录变量保留。两者都不读用户、项目、本地设置（`--setting-sources ""`），其中的放行规则和 hooks 不起作用；订阅登录不受影响，靠 settings.json 的 `apiKeyHelper` 或 `env` 登录的部署会在调用时报错。cwd 是看板自建的空目录，不继承看板进程的工作目录。拆解器只开放 Read、Glob、Grep（`--tools` 白名单、`--permission-mode dontAsk`、不加载 MCP、关掉斜杠命令），只挂工作仓、不挂 `core/`，也不给 `--allowedTools`：不带路径的 `Read` 放行规则会放行任意路径。读范围因此只有空 cwd 与工作仓，仓内敏感路径靠拒绝规则挡。计划经 `--json-schema` 的结构化输出交回，看板只读结果里的 `structured_output`，按同一份结构校验后建卡，不从正文提取，也不写结果文件。压缩的两步不开放任何工具；斜杠命令照常保留，因为关掉会连 `/compact` 一起关掉。两者都按路径拒绝读写整个数据目录、验证登记簿和全部配置的认证目录，写法与执行线相同。2026-10-28 用 Claude Code 2.1.234（haiku、假数据、不带宿主会话的环境变量）实测：订阅登录照常，拆解交回合格的 `structured_output`；读令牌、读登记簿、读认证目录文件、列认证目录、读工作仓外的文件均被拒，跨工作仓 Grep 的结果不含登记簿内容，允许的仓库文件照常可读；写工具和执行工具不在 CLI 报告的可用工具里；从专用空 cwd 续接别处建的会话、无工具压缩，照常写入压缩记录。

## 从看板派发和回报

1. 在执行线齿轮里选择执行配置、已允许模型与强度；CAS 保存沿原规则，运行中的进程不热换身份。
2. 新建卡片，选择该线已配置的组合。显式配置卡默认未放行、仅一次尝试。
3. 在侧栏核对通道、当前项目目录、权限和预算，两次确认放行。补预算后，未放行卡先展示最新预览；放行固定目录身份、权限与配置摘要，旧运行快照不改写。
4. 启动对应执行线。领取只匹配同一执行配置、摘要、模型、强度、目录身份与权限；更换工作仓或工具档后须重新核对放行，其他通道和旧 CLI 不能捡走该卡。
5. 宿主进程、SDK 模型活动、终态和结果回传分别记录。SDK 的文件工具限于工作仓，获准检查仍由宿主验证登记簿执行；验证命令在宿主环境运行，环境中不带供应商密钥和认证目录路径（如 `CLAUDE_CONFIG_DIR`、`CODEX_HOME`），API 密钥只交给本次 SDK 运行器。缺少权限时停下，不默认绕过。GPT SDK 内层在本次私有任务目录运行，通过固定 MCP 文件桥操作实际目标工作仓；不声称 SDK 原生 shell 在业务仓运行或提供了整个宿主的文件系统隔离。
6. 报告回到原卡，由操作者验收。结果回传不等于验收；失败、超时或费用／认证问题不触发其他收费通道或自动重跑。显式配置的执行循环退出即停线；在途任务回收或租约过期时标为结果未知、未放行，须本人核对，不能自动再派。打回、通过并备注或重新打开后同样取消放行，须本人重新核对放行后才再次计费运行。

SDK 文件工具同时保护实际看板数据目录、验证登记簿、管理配置与所有认证目录。Claude 的宽范围搜索若可能进入这些目录会被拒绝，可缩小到具体源码子目录；GPT 文件桥会过滤受保护项目。模型产物留在工作仓，证据回传由宿主写入看板数据目录。

## 真实验收与切换前提

真实调用另行确认预算、模型、时限和轮次；旧的单次 Claude 授权不扩张到四通道。本轮清单为 Claude API 促销归属探针一个会话，再加四通道各一张隔离开发样本。一个会话可能包含多次模型请求。

每张样本须完成“放行 → 正确领取 → 实际启动 → 产物和获准检查 → 原卡回报 → 本人人工验收 → 历史追溯”。促销归属还须由供应商账单确认，不由 SDK 名称、费用估算或响应成功推定；未明确时不重复探针或自动充值。

切换须对应候选 Windows CI 全绿、一次独立差异审阅、数据备份以及本人确认源码版本。四通道真实验收全部完成前，状态保持“未完成验收”；不因此宣称 Zcode、双机或旧联邦全部里程碑完成。

## 停止与回滚

沿用 `node cli/status.mjs`、`start.mjs --background`、`open.mjs`、`stop.mjs`。先停止执行线并确认无活动运行，再停板或换项目；不覆盖旧库、运行身份、未提交文件或备份。回滚先保留本次数据快照，再用原备份工具恢复到新的隔离目录，按既有恢复说明人工接续，不重派在途任务。

当前 Windows 单机试用明确使用 `windows.sandbox="unelevated"`，不触发本轮未授权的提权沙箱初始化；只读与工作仓写入模式、原认证和审批闸保持原值。该后端的网络隔离较弱且不提供路径拒读，不是通用部署的安全推荐；认证目录路径隔离仍由第 8 卡另行处理。受管要求若不允许此后端，应直接拒绝，不删除策略或改走无沙箱。
