# 单项目四通道工作台

Kanban 继续管理任务、放行、领取、回报和人工验收。CLI 与 API 是不同执行通道；界面、任务状态机、关联和原数据库沿用，不复制其他工作台。

## 通道与安装

| 执行配置 | 入口 | 认证与计费 |
| --- | --- | --- |
| `claude-cli` | 原 Claude 执行循环 | 独立 Claude 订阅登录 |
| `codex-cli` | 原 Codex 执行循环 | 独立 ChatGPT 登录，保留原解禁门 |
| `claude-api` | Claude Agent SDK 0.2.174 | 独立 Anthropic API 凭据 |
| `gpt-api` | Codex SDK 0.164.0 | 独立 OpenAI API 凭据，不借用 ChatGPT 订阅 |

旧智能体没有 `execution_profile_id` 时仍沿原 CLI 路径运行。显式选择配置后不自动换账号、通道、模型或收费来源，不触发共享池的额外模型探测。API 默认未启用且无预算，不因安装 SDK 自动获得调用许可。

在看板源码目录安装固定依赖；不会升级全局 CLI：

```powershell
npm.cmd ci --ignore-scripts
python -m pip install -r runners/requirements.txt
```

## 私有配置

在本机私有 `fleet.config.json` 的 `execution_profiles` 中覆盖内置配置。密钥只由指定的宿主环境变量提供，不写进配置、任务、日志或 Git。例如以下配置仍保持禁用：

```json
{
  "execution_profiles": [
    { "id": "claude-api", "enabled": false,
      "credential_env": "KANBAN_ANTHROPIC_API_KEY", "budget": null },
    { "id": "gpt-api", "enabled": false,
      "credential_env": "KANBAN_OPENAI_API_KEY", "budget": null,
      "provider_spend_limit_confirmed": false }
  ]
}
```

启用前由操作者明确模型及 `budget.timeout_sec`、`max_turns`、`max_cost_usd`。GPT SDK 本机只提供时限／步骤控制，不能承诺金额硬封顶；须由用户配置供应商项目侧花费限制并明确确认 `provider_spend_limit_confirmed`。实际扣费以供应商账单为准，未知费用不能记为零。

各通道的内部计数并不相同：Claude 使用原生轮次限制，GPT SDK 将 `max_turns` 用作文件工具步骤预算，不能把步骤数当成模型请求次数。当前 Codex CLI 仅强制单次执行与宿主超时，没有已核实的内部轮次或金额硬帽；若授权要求“最多若干内部轮次”，该授权不足以启动 Codex CLI，须先由操作者另定可接受的边界，不能静默放宽。

每个配置使用互不重叠且位于工作仓外的 `auth_home`；默认在本机数据目录的 `auth/<配置标识>`。显式 CLI 配置需要用户在对应目录完成订阅登录，不能以命令存在冒充已登录；API 不覆盖用户日常登录。修改私有配置后按原停止／启动流程重启，保留数据目录，不重新 setup 覆盖配置。

## 从看板派发和回报

1. 在执行线齿轮里选择执行配置、已允许模型与强度；CAS 保存沿原规则，运行中的进程不热换身份。
2. 新建卡片，选择该线已配置的组合。显式配置卡默认未放行、仅一次尝试。
3. 在侧栏核对通道、当前项目目录、权限和预算，两次确认放行。补预算后，未放行卡先展示最新预览；放行固定目录身份、权限与配置摘要，旧运行快照不改写。
4. 启动对应执行线。领取只匹配同一执行配置、摘要、模型、强度、目录身份与权限；更换工作仓或工具档后须重新核对放行，其他通道和旧 CLI 不能捡走该卡。
5. 宿主进程、SDK 模型活动、终态和结果回传分别记录。SDK 的文件工具限于工作仓，获准检查仍由宿主验证登记簿执行；缺少权限时停下，不默认绕过。GPT SDK 内层在本次私有任务目录运行，通过固定 MCP 文件桥操作实际目标工作仓；不声称 SDK 原生 shell 在业务仓运行或提供了整个宿主的文件系统隔离。
6. 报告回到原卡，由操作者验收。结果回传不等于验收；失败、超时或费用／认证问题不触发其他收费通道或自动重跑。显式配置的执行循环退出即停线；在途任务回收或租约过期时标为结果未知、未放行，须本人核对，不能自动再派。

SDK 文件工具同时保护实际看板数据目录、验证登记簿、管理配置与所有认证目录。Claude 的宽范围搜索若可能进入这些目录会被拒绝，可缩小到具体源码子目录；GPT 文件桥会过滤受保护项目。模型产物留在工作仓，证据回传由宿主写入看板数据目录。

## 真实验收与切换前提

真实调用另行确认预算、模型、时限和轮次；旧的单次 Claude 授权不扩张到四通道。本轮清单为 Claude API 促销归属探针一个会话，再加四通道各一张隔离开发样本。一个会话可能包含多次模型请求。

每张样本须完成“放行 → 正确领取 → 实际启动 → 产物和获准检查 → 原卡回报 → 本人人工验收 → 历史追溯”。促销归属还须由供应商账单确认，不由 SDK 名称、费用估算或响应成功推定；未明确时不重复探针或自动充值。

切换须对应候选 Windows CI 全绿、一次独立差异审阅、数据备份以及本人确认源码版本。四通道真实验收全部完成前，状态保持“未完成验收”；不因此宣称 Zcode、双机或旧联邦全部里程碑完成。

## 停止与回滚

沿用 `node cli/status.mjs`、`start.mjs --background`、`open.mjs`、`stop.mjs`。先停止执行线并确认无活动运行，再停板或换项目；不覆盖旧库、运行身份、未提交文件或备份。回滚先保留本次数据快照，再用原备份工具恢复到新的隔离目录，按既有恢复说明人工接续，不重派在途任务。
