# Kandev 单机复用试点实施记录

本批以 Kandev v0.97.0（`e43881c7555372897b57ec51c705f1e05da43c40`）为主工作台，复用自有交付校验，不迁移旧看板数据库，不启动旧验收服务。

## 交付边界

- 独立插件仓库 `kandev-plugin-fleet-acceptance`；宿主仅增加严格完成策略与必要的只读 SDK 补齐。
- Windows 原生单机，Claude 实现、Codex 独立审查、人工验收；API、跨机器联邦留待后续。
- 未经有效回执不可 Done；原生人工覆盖、删除必需条件、直接验证都不能绕过。
- 回执保存在 Kandev 原生完成条件与审计历史；插件 Host state 只缓存待验收候选。
- 所有运行、数据库、工具链位于隔离目录，不覆盖原看板和原配置。

## 已实现

| 层 | 交付 | 复用边界 |
| --- | --- | --- |
| 共享校验 | `gates/delivery_check.js`、`cli/check-delivery.mjs`，原服务调用同一实现 | 无独立验收服务；严格模式不继承旧门禁关闭开关和缓存 |
| Kandev 宿主 | 可选只读门禁 SDK、真实用户校验、启动严格策略、完成事务前实时复核 | 原生任务／条件／历史唯一；没有新任务表或迁移 |
| 独立插件 | 提交、通过、驳回、原生证据恢复与原生桌面／手机任务面板 | 不移动任务、不调用模型、不自动重派；只读恢复不重复写入决定 |

必需条件绑定指定插件安装身份；浏览器不能自报操作者或 worktree 路径。候选绑定任务／会话版本、实现与审查运行时、分支、HEAD、实际产物摘要及校验代码摘要。最终完成还检查已结束轮次的先后顺序与活动会话。独立审查内容的语义是否充分，仍由人确认。

本批仅支持 Windows amd64、单机 SQLite、原生 Worktree、单任务单仓库。宿主策略开启后保护普通任务，内部临时会话除外；为避免影响现有任务，只在独立实例试点。运行步骤见同级独立插件仓库的 `README.md`。

## 验证结果与边界（2026-10-16）

- 共享校验新增 7 项测试、原门禁 30 项测试、原服务相关回归 198 项通过；新测试已接入原默认测试链。没有在本地扩大到无关全量回归。
- 插件通过依赖锁、格式、静态分析、竞态测试、面板注册生命周期测试；官方打包器生成 Windows 包并逐项复核 3 个载荷的 SHA-256。
- 宿主受影响的 SDK、插件、任务服务、校验器及配置定向测试通过竞态检测；SQLguard 通过。新增回归包含批量／整列移动、会话变化、错误审查顺序和仍活动的执行。
- 真实宿主＋真实插件安装与授权＋模拟 Claude/Codex 轮次的集成通过：无回执拒绝完成、防删除必需条件、人工通过、修改实际产物拒绝完成、桌面 28px 控件、手机触摸提交和验收、原生完成及宿主重启恢复。
- 上游通用持久化一致性套件未全通过：夹具 SQL 在此 Windows 检出被转成 CRLF，原始 Git 内容及恢复 LF 后的摘要均与清单一致；存储测试使用 `/tmp` 路径。配置包的路径引号与 HOME 相关断言已在原固定基线复现。未修改这些无关测试，也未将失败计为通过；PostgreSQL 不在本批支持范围。

浏览器是本机 Chromium 的桌面与触摸模拟，**不是实体手机验收**；模拟轮次**不是实际模型任务验收**。本次没有调用真实 Claude/Codex、没有消耗模型额度，没有切换现有实例、修改原数据或公开发布。真实 CLI 验收须操作员允许额度使用并确认登录配置后各跑一个小任务，缺条件则停在此清单。

## 可重建交付

共享校验基线为 ai-fleet-kanban v0.24.0（`0cf92696e9cb236fb061b54bb781a85f01bde146`）。独立插件的 `compat/` 附两份由 Git 生成的兼容补丁：宿主完整补丁及共享校验补丁，分别针对上述固定基线，不依赖手动复制的协议文件。包中不包含仓库、日志、密码、数据库或工具缓存。

恢复与回退沿用宿主备份流程，遇身份／管理权冲突由人处理；停止隔离实例后回到原实例及原数据目录。不要用未打补丁的宿主继续办理试点受保护任务。

## 后续开发队列

1. 获准后进行 Claude 实现／Codex 独立审查的真实 CLI 小任务验收，确认真实登录、轮次和 Git 提交；不以本次模拟结论代替。
2. 小范围实际试用，收集原生工作流／面板的缺口；已有能力优先用上游配置或插件扩展，不再实现第二套看板、会话、审计或 worktree 管理。
3. API 接入另立阶段：先评估上游原生执行器与官方 SDK，再补确实缺失的适配与统一用量／预算边界；不在本批引入 API 密钥、计费或跨机器路由。

## 界面约束

复用 Kandev 原生任务面板。桌面在任务面板内展示候选和验收动作；手机沿用任务面板的全高单列结构，一个内部纵向滚动区，44px 触摸目标，底部安全区，状态与动作不依赖悬停。

```text
桌面任务面板             手机任务面板
┌─交付验收──────────┐    ┌─交付验收────────┐
│说明／实现／审查会话│    │状态与候选提交    │
│候选提交与文件摘要  │    │交付说明          │
│检查  人工通过  驳回│    │实现／审查会话    │
└──────────────────┘    │文件摘要          │
                         │检查／通过／驳回  │
                         └─────────────────┘
```

最终放行前实时核对任务资源版本、会话轮次、当前 HEAD、产物摘要与校验代码版本。文件检查只证明完成动作时的观察窗口，不宣称抵御本机管理员直接改数据库或操作系统文件。
