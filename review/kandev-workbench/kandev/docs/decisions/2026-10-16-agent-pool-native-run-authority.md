# ADR-2026-10-16-agent-pool-native-run-authority: 任务池沿用原生运行权

**Status:** accepted
**Date:** 2026-10-16
**Area:** backend, frontend, workflow

## 背景

用户授权设计自己的任务工作台，要求看到 Agent 从池中领取并开工，并明确优先复用。当前固定基线已经有 `runs`、全局消费者、领取账本和原生工作流。插件管理权声明并不是一次 CLI 领取，任务会话的创建时间也不是模型开工证明。

本记录是本地设计选择；对应需求和设计保持 draft，尚未实施，不表示上游或用户已作功能验收。

## 决策

1. 池是原生任务／工作流的入口与读视图，不是另一个任务系统。通过既有共享队列和执行器启动 CLI；不要求部署 Office 自主工作区或额外协调 Agent。
2. 首版按阶段限定单个执行配置。原生调度器代表该 Agent 完成原子领取；界面明确“领取已登记”和“实际开工”是两个节点，不声称 CLI 在网络上自行轮询了公共池。
3. 使用原生阶段进入身份派生稳定派发键，专用池请求不与普通唤醒合并。每次领取引用既有 `office_launch_ledger.id`，不用会被恢复清空的 `runs.claimed_at` 作为历史主键。
4. 为本池的模糊执行禁用基于时间的盲目重新领取。只在原有恢复入口对本池身份做窄范围区分；不重写普通任务的恢复政策。不确定状态交给人工核实。
5. 优先复用原生卡片、导航、关联及任务详情。需要领取账本与开工证据的有界宿主读投影时，使用窄宿主补丁；验收插件继续独立，不从插件读取私有 store 或数据库。

## 后果

可以保持任务、运行、审计的单一事实来源，但不是纯 CSS 换皮。仍须补本池派发身份、开始证据关联、有界读视图和恢复门禁。前端不能凭负责人或进程状态推出已开工。

不新增全局任务编号、调度数据库或队列线程。首版只支持单后端 Windows／SQLite／Worktree 和固定 Claude、Codex CLI；已有动态提供商路由的配置必须显式判为不支持，不能静默改全局路由来通过测试。

## 备选方案

- 自建 worker 轮询、租约和任务表：控制面完整，但重复实现调度、依赖和审计，升级与双写风险高，因此不采用。
- 只把卡片负责人显示为已领取：最省改动，但无法回答是否被执行，拒绝。
- 全面采用 Office 自主团队作为首版前提：可以使用其成熟能力，但增加自主唤醒、运行时与额度治理范围。保留未来评估，不作为本次工作的必备条件。
- 仅用插件缓存所有状态：不能证明后端重启后的真实领取及执行，拒绝。
