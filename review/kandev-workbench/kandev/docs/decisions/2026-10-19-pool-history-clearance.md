# ADR-2026-10-19-pool-history-clearance: 原生池历史清理后保留派发凭证

**Status:** accepted
**Date:** 2026-10-19
**Area:** backend

## 背景

原生维护删除终态 runs 和 run_events 后，同一批准失去去重依据，
历史也被误读成未入队。不可变领取账本仍在，但没有任务／阶段关联。
用户明确选择 A：最小原生派发／清理凭证，继续沿用清理政策。

## 决定

由现有 Office schema 所有者安装 runs 所有的最小清理凭证和启用边界。
原生维护在删除事务内核验池运行的规范派发键和批准绑定，写入凭证，
然后删除原运行及回执；任何错误均回滚整个批次。普通运行政策不变。
发布器在既有 SQLite 写事务内检查凭证，旧批准不得再生成运行。
未知的升级前空记录须新批准，不推定从未派发。

tasks 只读投影关联凭证与原生领取账本，明确显示 history_cleaned，
不构造活动 Run，不推断开工／结束时间，不赋予完成或恢复权限。
格式、事务、升级、容量和验证见[所属设计](../specs/tasks/system-design/agent-pool-history-clearance.md)。

## 影响

这是原零迁移计划的明确窄例外，不是第二份任务库、队列或调度器。
凭证不随普通历史年龄清理，避免恢复旧批准的可重放性。
存量关联缺失只能待核实；有凭证不代表执行曾开工。
保留 ACL、最大 50 项、严格 Done 门禁及生产关闭边界。

## 考虑的替代方案

- B，完整保留池运行和回执：不需新结构，但改变保留政策并持续保存完整历史；用户未选。
- 只保留摘要缓存或按时间猜清理：不能形成防重派依据。
- 借用其他工作流动作 marker：违背 queue_run 的原生去重所有权。
