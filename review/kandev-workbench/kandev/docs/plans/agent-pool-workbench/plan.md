# Agent 任务池工作台开发计划

## 结果与顺序

在现有 Kandev 试点上形成“任务指挥”默认视图：知道哪些卡待处理、何时入池、哪个 Agent 领取、何时实际开工、被什么阻塞以及卡片关系。原生工作台和严格验收保留。

先确保一张卡沿共享队列真正启动且可证明，再做只读投影、桌面／手机界面及人工恢复。用户已选择 A：最小原生清理凭证。四份工单已完成隔离范围验收：包含清理防重派、两端真实重启、依赖／阻塞导航、严格 Done 与可重放增量。选择记录见[数据保留边界](decision-history-retention.md)，当前来源及边界见[隔离交付核对](acceptance-audit.md)。implemented 不等于真实模型、实体手机、全库全绿或生产开放。

## 范围

### 包含

- 单后端、Windows、SQLite、Worktree、固定 Claude／Codex CLI。
- 原生工作流队列的可选择池流程；角色由阶段指定，Agent 并发首版使用原生限额 1。
- 单一派发身份、领取账本、真实开工证据、有界查询、中文工作台、父子／依赖导航及人工恢复。

### 不包含

- 跨机器自由抢占、智能选 Agent、API 密钥／计费、自动换模型、常驻协调模型。
- 全量重写 Kandev 首页／聊天／终端，第二任务库、第二队列、第三方关系图系统。
- 对原实例部署、公开发布、PR、提交或实际模型额度消耗；这些不由设计授权。

## 设计假设与已核对事实

用户已确认“领取并开始”的含义，并委托设计。设计选择：按原生工作流固定角色；调度器代表 Agent 领取，CLI 活动证明开工；默认查看只读。首页保持中文、低噪声和技术详情折叠，不新增品牌资产。

2026-10-20 当前隔离交付包含原生清理凭证、防重派、有界投影、任务指挥页面和版本化撤回／停止／重试。01 的旧确认重放已用固定时钟复现并修复；该机制不能追认此前未保存现场的精确原因。严格门禁与固定基线失败的证据见[隔离交付核对](acceptance-audit.md)。历史试用数据保留，但入口不能凭过去运行记录宣称当前在线；各工单的历史检查点不代表当前最终状态。

已核对共享队列、Claim CAS、领取账本、原生会话与依赖模型、卡片插槽及手机原生抽屉／直达详情。第十四检查点已通过私有真实宿主＋模拟 CLI 的派发、领取、开工、停止与重启闭环；未调用真实提供商，不代替异常中断、剩余入口审计或工作台验收。

采用既有 [共享运行设计](../../specs/tasks/system-design/run-scheduling.md) 和 [本次决策](../../decisions/2026-10-16-agent-pool-native-run-authority.md)。任务系统边界已有此能力，无需添加另一份 UI 或 Office 需求。原复用试点的后续队列与此设计互补，不把之前的模拟结果用作本功能的测试结果。

## 技术路径

| 边界 | 现有接点 | 本次最小增量 |
| --- | --- | --- |
| 入池与领取 | `QueueRunCallback`、`Service.QueueRunAndReturn`、`ClaimNextEligibleRun` | 可信池标记、稳定阶段键、禁止本池合并、同任务手动启动准入 |
| 尝试与证据 | `office_launch_ledger`、`run_events`、CLI 流事件、`persistLaunchedSession` | 传递 claim ID；事务内追加版本化绑定／开工回执 |
| 读取 | `internal/task/statussummary`、原生权限、任务与运行仓储 | 两个只读投影入口，可选 `pool_execution` 摘要；最大 50 项 |
| 桌面／手机 | `src/spa-routes.tsx`、原生导航、`kanban-card-content.tsx`、task layout | 可选默认“任务指挥”页面与共享卡片摘要；不访问插件私有 store |
| 恢复 | `RecoverStale`、`RequeueClaimedRun`、原生停止／取消／重试 | 对本池模糊启动窄范围隔离，带版本确认的人工处置 |

除用户选择 A 所需的[原生清理凭证](../../specs/tasks/system-design/agent-pool-history-clearance.md)外不新增表；公开 SDK RPC／分布式锁仍不在本批。不会复制宿主数据，既有验收插件不承担调度。

### 传输兼容矩阵

| 情况 | 证据 | 首版行为 | 不支持时 |
| --- | --- | --- | --- |
| 固定 Codex CLI | 匹配当前 claim / session / turn、带提供商 `turn/started` 来源的事件或工作活动 | 确认开工，记录实际执行配置 | 公共同名提示发送事件不算；缺绑定则等待回执 |
| 固定 Claude CLI | 匹配当前轮次的 `message_chunk` / `tool_call`；如有真实开始事件可用 | 首个工作活动确认开工；启动欢迎消息不算 | 无活动只显示已领取 |
| 普通手动启动任务 | 原生交互会话资料 | 保持原功能，不伪造池领取 | 在详情说明不是从池领取 |
| 动态路由、API、远端、多个执行配置 | 本批未证明 | 不纳入池能力白名单 | 阻止本池入队并指出原因；不自动改设置 |

所有传输测试先用隔离模拟代理。不做真实 CLI 调用直至操作者授权额度和登录配置；真实调用通过前只能报告模拟闭环。

## ASCII UI preview

线框均为拟议，不是当前界面截图。边框表达层级，不规定像素；文字与色彩用现有 i18n、图标和设计 token 实现。状态数据共用一套投影。

### UI-01：桌面任务指挥，正常执行

入口：原生导航“任务指挥”。左导航、顶栏固定；列表和右侧详情各自有明确的内容滚动区。新页面不挂载隐藏的终端或全部会话。

```text
+------------+-----------------------------------------------------------+
| 任务指挥   | 工作区 v   搜索...       筛选 v       [+ 原生新建任务]   |
| 原生看板   +-----------------------------------------------------------+
| 会话       | 待我处理 2 | 任务池 4 | 执行中 1 | 待验收 1             |
| 设置       +-----------------------------+-----------------------------+
|            | 修复登录回调                 | 修复登录回调                |
|            | 实施 / 运行中                | 阶段: 实施  Agent: Claude   |
|            | Claude  开工 10:03           | 10:02 批准入池              |
|            | 任务最近活动 20 秒前         | 10:02 入队                  |
|            | 父: 账户模块  依赖: 登录接口 | 10:02:04 领取已登记         |
|            | [查看轨迹] [...]            | 10:03 首次工作活动 / 开工   |
|            |                             | 关系 | 尝试历史 | 技术详情  |
|            |                             | [打开原生工作台]            |
+------------+-----------------------------+-----------------------------+
```

主动作取决于状态：未入池且条件满足为“批准并入池”；排队为“撤回”；已领取／开工为“打开原生工作台”；待验收为原验收面板入口。普通桌面动作 28px。关联采用标题链接，UUID 不占卡面。

### UI-02：手机任务池与完整详情

入口：原生手机导航“任务指挥”。分类按钮和筛选可见；筛选为 inset 底部 Drawer。卡片点击直达完整详情，返回保留筛选／滚动，不把右预览压到卡片下方。

```text
+------------------------------+     +------------------------------+
| 任务指挥     工作区 v   [...] |     | < 返回       修复登录回调    |
| [任务池 v]         [筛选]    |     | 实施 / 运行中     Claude     |
+------------------------------+     +------------------------------+
| 修复登录回调                 |     | 10:02    批准入池            |
| 实施 / 运行中   Claude       | --> | 10:02    入队                |
| 领取 10:02  开工 10:03        |     | 10:02:04 领取已登记          |
| 任务最近活动 20 秒前         |     | 10:03    开工已确认          |
| 依赖 登录接口 >              |     | 父任务 / 依赖 / 阻塞谁       |
|                              |     | 历史尝试 / 技术详情          |
+------------------------------+     +------------------------------+
| [+ 原生新建任务]             |     | [打开原生工作台]             |
+------------------------------+     +------------------------------+
```

列表或详情主体是唯一纵向滚动所有者，头部和主要动作固定并留安全区；`100dvh`，动作目标名义 48px、实测至少 44px；宽度小于 768px 的精细指针也按手机组合，粗指针平板另查。桌面偏好不因手机筛选被覆盖。

### UI-03：待派发与关系

```text
+-------------------------------------------+
| 完善账户模块   方案确认 / 未派发           |
| 计划执行者: Claude  尚无领取记录           |
| 前置: 登录接口 [未完成，阻塞]              |
| 子任务: 接口联调 >  权限测试 >             |
| [批准并入池: 不可用] 原因: 前置未完成      |
+-------------------------------------------+
```

前置解除后可用动作仍要求人的明确批准；开卡、查看关系和删除前置都不能替人批准。实现、审查、验收默认沿一张主卡进行。

### UI-04：数据未知与人工恢复

```text
+-------------------------------------------+
| 修复登录回调   实施 / 待核实               |
| 已确认领取 10:02   开工回执: 缺失          |
| 最后确认 10:05   连接已中断                |
| [刷新状态] [查看原生运行]                 |
| [核实并重试: 不可用] 执行是否停止尚未知    |
+-------------------------------------------+
```

不是失败重试按钮。失败／停机确认后才可打开恢复确认，显示旧运行及风险；请求结果未知继续查同一操作。空池、加载失败和权限拒绝使用不同文案；不能都渲染“暂无任务”。
