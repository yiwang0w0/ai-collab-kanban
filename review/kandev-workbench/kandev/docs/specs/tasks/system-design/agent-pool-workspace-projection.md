# 工作区任务池的批量只读契约

## 范围与权威

本文细化[工作台设计](agent-pool-workbench.md)的工作区列表。tasks 所有的 poolview 负责有界卡片及提示，poolhistory 继续拥有[原生执行证据投影](agent-pool-history-projection.md)；两者均不拥有队列、调度、任务状态或恢复权。沿用[原生运行权决策](../../../decisions/2026-10-16-agent-pool-native-run-authority.md)。用户已选 A 的[清理凭证](agent-pool-history-clearance.md)由原生事务写入；查询不建副本或写修复。

列表面向工作区内未归档、非临时的原生主卡和子卡，未绑定池的卡也可出现，pool_execution 为空。这使工作台可以分类待处理、执行及验收，而不要求为换 Agent 建立副本。任务指挥已基于此有界页面实现分类、筛选与完整详情；不把本页分类数量冒充整个工作区总量。

HTTP 卡片与原生 TaskStatusSummary 的可选 pool_execution 共用原生执行投影，摘要通过既有原生版本／传输收敛，详见[摘要与提交后刷新](agent-pool-summary-refresh.md)。新页面的刷新交互、断线提示及桌面／手机仍以[工单 02](../../../plans/agent-pool-workbench/task-02-pool-projection.md)和后续工单为准；本段不是完整工作台验收。

## HTTP、分页与权限

GET /api/v1/workspaces/:id/task-pool 接受 limit 和 cursor。默认或零 limit 为 50，负数、非整数及大于 50 均返回 400。游标采用版本 1 的规范编码，绑定 workspace_id 和最后的主卡 ID；不同工作区、未知／重复字段、非规范编码均拒绝。按不可变主卡 ID 升序前进，不因标题、状态或活动时间变化跳页。新增／删除仍是动态原生数据，不承诺跨多个请求锁住整个工作区。

外层复用工作区读权限，异域和不存在返回相同的 workspace_not_found 404；原生 reader 在同一个只读事务中重查工作区和全部选中行。服务重新核对来源工作区、每张卡作用域、50 项边界及严格递增／无重复 ID，不能把错误来源的结果直接发给客户端。权限拒绝、无能力、来源故障和合法空工作区分别处理。

成功返回 workspace_id、snapshot_version、items、next_cursor。空页的 items 为数组。400 使用 pool_projection_invalid_query，来源失败／空或矛盾快照返回 503 pool_projection_unavailable；不回显数据库诊断。读预算三秒并传入实际来源，取消后不确认成功快照；它不是对网络传输或任意宿主性能的三秒 SLA。

## 卡片及来源

| 卡片资料 | 原生来源与边界 |
|---|---|
| 标题、业务状态、流程及阶段 | tasks、同工作区 workflows 和 workflow_steps；不读取正文 |
| pool_execution | 最新池批准、原生 runs、不可变 office_launch_ledger 和对应 pool.* 回执 |
| eligibility | 原生阶段池配置、WIP、依赖、静态 Profile 资料及已知执行状态的提示 |
| relations | 原生 parent_id、task_blockers 的同工作区可见关系计数 |

标题最多 256 字符、阶段名称最多 128 字符。卡片只暴露阶段及有界执行资料，不返回原始提示、转录、运行 payload、阶段事件或 Agent TUI 配置。来源的阶段事件、TUI 配置、池封装及回执均限制为 16 KiB；不能把被截断或无法解析的输入当作正常配置。

一次事务批量读取最多 50 张卡及其上下文、最新池批准、运行、领取和证据，不逐卡调用历史 API，也不逐卡加载会话。运行候选总量按两倍键数加一条溢出探测限制，超限时批次标证据不完整；原生唯一键正常情况下每键一条。领取统计批量读取，当前匹配账本每 run 最多两条。每个选中运行的匹配／无法归属池事件最多 17 条，超过 16 条标该行证据不完整，不能因一个坏事件把邻卡正常事实改成成功或丢掉卡片。

实现目前只支持 SQLite；PGX 在专用 SQL 前拒绝，没有宣称实际 PostgreSQL 验收。A 增加一次按键集合批量读取清理凭证，预算由列表 8／摘要 6／单卡历史 6 调整为 9／7／7；仍要求 1／50 项查询数相等。计数仅覆盖仓储源的 Query／Exec，不含 HTTP 认证／授权、原生摘要 CAS 写入、事务开始／结束及夹具准备。各项使用独立三秒预算，读取前后原生事实不变；最新实际测量以工单为准，不是生产规模或端到端 SLA。

## 执行身份及阶段变化

pool_execution 复用单卡投影的原生身份工厂和事实时间。计划 Profile 与实际领取 Profile 分开，唯一不可变领取账本 ID 才是 attempt 身份。原生 run 的当前 claimed_at 仅用于核对当前账本；不能取 MAX(claimed_at)，也不能把时间作为领取 ID。

阶段变更与执行终结是两个事实。原生移动可以在尚无活跃会话时发生，而已领取的 run 仍未终结。列表因此读取最新池批准及最新任意阶段进入，保留已知 run／claim／时间；进入或流程／阶段不再匹配时标 unknown、current_stage_unverified，且 current 为 false。不把旧轮次显示成新阶段已开工，也不因移动而删除执行事实。

回合结束、执行停止、本轮终结和主卡完成仍分开；ended 不放行严格 Done。缺失、冲突、陈旧绑定、事件过量及无法归属显示待核实，不查询触发重派。

## 资格提示与原生关系

eligibility 表达显示原因，不是启动授权，也不包含可由浏览器自报的领取、时刻或验收结果。它可区分未配置池阶段、需要真人额度确认、批准尚未入队、已有执行占用、需要重新核验、缺失／禁用静态 Profile、WIP／依赖阻塞及未知事实。

Profile 静态检查复用 PoolExecutionCandidate.ValidateProfile，原生写侧的 Validate 继续额外核对实际 Worktree 执行器。列表不宣称验证了凭据、执行器可用、工作树释放或当前运行时空闲；所有实际派发／恢复继续经过原生权限、版本、依赖、执行配置和执行占用门禁。只读角色的动作权限由原生工作区能力提供，不能凭资格标签绕过写授权。

原生阶段 updated_at 晚于已确认 released_at 时，列表显示 requires_revalidation／pool_stage_configuration_changed，即使 Profile ID 仍相同也不能把旧批准显示为可继续派发。移除池配置或切换阶段执行者同样保留旧运行／领取事实，显示需重新核验；已确认的时间和实际领取者不改写。此提示跟随原生 LoadPoolRelease 的配置版本门禁，不签发新的批准或启动许可。

父子和依赖继续受原生同工作区约束。列表只返回同工作区未归档非临时目标的父引用及子卡／依赖／被依赖计数；详情导航和关系写入仍复用原生接口。缺失、异域、已归档或未完成前置保留为阻塞，但不输出不可见目标的 ID、标题或关系计数。查询不清理脏边，也不把前置删除解释成完成。

## 版本、刷新与验证

snapshot_version 是返回页的稳定语义摘要，包含卡片、已知执行、关系、资格提示和游标，不含查询时钟；相同事实应在重复读取和宿主重启重建后保持一致。它不是原生写版本，不用于恢复操作的授权或 CAS。

读取不创建卡、运行、账本、回执，也不修改任务状态或资源。原生摘要的提交后失效与持久重读，以及新页面的最后确认时间、失效和隐藏页面停查均已接线；不把内部通知发送当作持久确认。实际前台验收见工单 03／04。

验证使用真实原生任务／队列／领取仓储，覆盖 51 张卡分页、作用域、查询只读、历史账本不抢当前身份、原生移动后保留未终结领取、关系脏边与来源故障。宿主验证使用新编译私有二进制、原生登录和实际 mock-agent CLI；结果以工单最新终态为准，不代替真实模型、插件正例、实体手机或生产验证。
