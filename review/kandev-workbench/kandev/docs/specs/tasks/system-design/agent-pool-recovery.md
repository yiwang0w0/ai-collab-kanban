# 任务池版本化人工恢复

本文细化[工作台设计](agent-pool-workbench.md)的人工恢复，依赖[原生执行停止与终结](agent-pool-execution-retirement.md)。正式生产池入口仍关闭；源码实现与验证范围以[工单 04](../../../plans/agent-pool-workbench/task-04-manual-recovery.md)的结果记录为准。

## 实施合同

- 查询只读取得同一任务的当前原生 run、唯一领取账本及比较版本；任务版本保留原生纳秒字符串，运行版本是不透明的“原始行＋最后事件序号”摘要，不以 claimed_at 替代 claim ID。
- 操作者须为真实浏览器会话，不能由 synthetic、PAT、Agent 自报身份或无会话上下文签发确认。任务写入和会话操作分别沿原生 task.write、session.control／session.exec 权限；管理角色不自动获得其他人的工作区可见性。
- 操作 ID 为客户端防重放 nonce，不是执行身份或时刻。任务／run／操作与真实 actor 绑定后，回执保存在已有 run_events 的宿主保留命名空间，不建恢复表或第二调度器。重放先查同一回执，再决定是否比较新写入前提；同 ID 不同正文拒绝。响应丢失先查原操作，不能自动重发产生新动作。
- 撤回复用原生任务启动准入，先取得 SQLite 写权，再重查任务版本、当前批准、队列原始行和事件版本。仅 queued、没有领取账本／会话／启动证据的运行可由 CAS 进入 cancelled；撤回及其回执同事务提交，不移动主卡、不补开工、不签发 Done。并发领取若先成立，撤回必须冲突。
- 停止的回执只说明宿主接受了该身份的停止请求，后续还须核对真实 instance／task／session／execution 的原生停止证据。请求超时或宿主重启不等于停止成功，也不会因此重排。
- 旧 Office 路由的容量停放、下一候选重排及工作区解除停放写入口，也必须按宿主保留键排除池行；不能因载荷损坏或路由配置变化清空其领取／会话。普通非池行保持既有重排政策。
- 核实后重试须明确确认额度，持有原生生命周期与任务屏障，并在同一写事务重查当前 claim、分配、停止／终结凭证和实际 checkout／宿主空闲。仍使用同一个任务及 run，以 CAS 重入原生队列；保留原领取账本与历史事件，下一次领取产生新的账本 ID。缺证明不 reset、不换 Agent、不增建 run。
- 重入队时间由恢复提交事件提供，不能沿用首次 requested_at 冒充本轮排队时刻。历史停止／终结保留其原 claim 的凭证，不能由新的 run.status 覆盖旧尝试；旧回调不能写新 claim。回执清理继续沿既有防重派凭证规则。
- 以上是 04 的实施合同；当前实现与逐项验收范围以工单的最新结果为准，不能由按钮存在推断已经停止或通过正式验收。

## 接口与显示边界

- `GET /api/v1/tasks/:id/pool-recovery?run_id=...` 在同一只读快照取得任务、运行及原生管理权版本，事务受三秒期限限制。工作区只读成员可以查看，但动作权限仍为否；任务 ID 与运行不匹配和运行不存在均返回 404。
- `POST /api/v1/tasks/:id/pool-recovery` 只接受明确动作、操作 UUID、原始任务／运行／管理权版本、预期 claim 及确认。正文最多 16 KiB，未知字段或多个 JSON 正文拒绝，不接收浏览器自报 actor、execution 或停止时间。隔离实现已接通撤回、停止与核实后重试；缺少任一原生能力或凭证仍失败关闭。
- `GET /api/v1/tasks/:id/pool-recovery/:operation_id?run_id=...` 返回同一原生回执的选择性结果，不暴露运行输入或内部执行参数。相同正文重放及查询返回一致结果，不产生新的任务、运行或恢复事件。
- 新写入前复用原生管理权资源版本；插件持有管理权、其他人接管或确认后管理权版本变化均冲突。无管理权或当前操作者持有的最新人工管理权可继续核对准入条件；重放不冒充新动作。
- 撤回只有同时匹配原生取消行、没有 claim／执行绑定、唯一合法撤回回执及其提交时间才显示 `withdrawn`，归待我处理。只有 cancelled 行、缺回执或证据过量仍为待核实，不能显示成执行已停止或主卡已完成。
- 浏览器会话存储仅保存待查询操作凭据，按宿主地址、登录用户、工作区、任务及运行隔离，最多 32 项、65536 字符（浏览器字符串长度）。保存失败不发送新动作；结果未知时重新打开仍只查询原操作，不自动重发。它不是任务状态、停止事实或恢复成功的权威来源。

## 停止及重入队的原生边界

- 停止在原生生命周期与任务准入屏障内捕获当前唯一 execution；短事务提交请求回执后释放屏障，再通过原生受关闭管理的后续工作停止这个不可变 execution。提交失败不停止，重复回执不再次停止，不能改按新 session 当前执行重新选择目标。
- 控制回执带原 claim 和原生分配身份，但不是开工或停止凭证。投影单独校验它，不抹掉真实开工；请求确认提示明确说明尚不代表执行停止或资源释放。
- 重试复用原生 stopped／finished 核验、宿主静止屏障与 checkout 空闲检查。终结、同 run 重新排队和恢复回执在同一写事务提交；任一步失败全部回滚，提交后才唤醒既有消费者。
- 原生停止后主卡可仍为 IN_PROGRESS。只在完整停止证明及人工额度确认后，或下一领取已核对同一原生重试回执后，允许这类主卡继续候选检查；首次派发仍拒绝 IN_PROGRESS，不修改主卡状态或 Done 门禁。
- 下一领取的启动准入先核对前一池事件为有效重入队回执及其原终结序号，再核对依赖、占用和候选能力；未知重排不能再次启动 CLI。原 requested_at 保留，当前排队时间来自重入队事件，后续各 claim 通过准入前的事件因果边取回各自排队时刻。
- 历史保留旧领取与原停止／结束时间；当前待领取轮次无 claim，不补领取或开工。读源只加载选中领取和有界因果事件，不加载完整日志；资格 GET 先结束只读事务，再检查宿主静止，避免锁序倒置。界面在原生尝试变化时即时重读资格，不等待轮询或乐观解锁。
