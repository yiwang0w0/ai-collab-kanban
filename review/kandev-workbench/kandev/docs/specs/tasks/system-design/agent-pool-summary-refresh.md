# 任务池原生摘要与提交后刷新契约

## 范围与权威

本文细化[工作台设计](agent-pool-workbench.md)中原生任务摘要、持久重建和客户端版本接收的同一条链路。复用 `TaskStatusSummary`、现有 CAS 仓储、原生投影器和 `task.status_summary.updated`；不增加任务库、执行状态机、持久通知表或浏览器签发的执行证据。

执行事实继续由[单卡历史](agent-pool-history-projection.md)的原生批准、run、不可变领取账本及池回执确定；[工作区列表](agent-pool-workspace-projection.md)与摘要共用该投影。运行终结不是主卡 Done，读模型不能绕过严格完成门禁。生产池执行仍未注入，本契约不授权真实模型、API、自动重派或部署。

## 摘要字段与兼容

`internal/task/statussummary.TaskStatusSummary` 的可选 `pool_execution` 使用 `PoolExecutionSummary`，沿用已有 `poolhistory.Item` 的有界字段和事实时间。计划 Profile 与实际领取 Profile 分开；attempt 以不可变 claim ID 关联，不以时间或最近一条通知关联。

语义比较包含本字段，复制时深拷贝可选时间。边界校验约束已知状态、非负 entry ID、有效 UTF-8、ID／原因／标签长度及非零可选时间；此校验仅防止坏摘要进入共享状态，不代替原生回执身份核对。无池绑定时字段省略，旧任务和未使用新字段的客户端保持兼容。

原生摘要是完整、带 revision 的投影，不把新字段做增量补丁：较新完整摘要省略 `pool_execution` 时须清除旧值；无关任务部分更新省略整个摘要时则保留已有摘要。队列等其他域的更新必须从完整已存基线重建，不得顺手抹掉池执行事实。

## 原生有界来源与重建

`ReadPoolSummarySnapshot` 在同一 SQLite 只读事务中读取已授权任务的卡片头、批准、运行、领取和池证据，不加载正文、转录或完整会话，也不为每张卡调用历史接口。每批 1–50 个唯一、非空且长度受限的 task ID；按原生工作区分组、分批，继承总计三秒的读取预算。与未归档工作区列表不同，摘要也覆盖仍可见的归档任务。

来源结果必须符合工作区、请求 ID 集合、排序、数量及无重复约束。单卡投影器先解析实际任务归属并复用工作区读授权，不能相信通知自报的 workspace。列表摘要重建复用已授权的原生任务集合。PGX 专用读取提前拒绝；原生摘要路径保持旧存储的可选能力兼容，不声称 PostgreSQL 池功能已经验收。

`ReconcileTaskStatusSummaries` 继续先修复原生基础摘要，再覆盖池执行一域，最多使用已有的三次 CAS 尝试。CAS 输给并发更新后同时重载胜出的完整摘要与最新原生池事实；不能只提高旧 claim 的 revision。其他域保留胜出者的数据，成功后复用原生摘要通知。

只读源查询不写入任何原生事实。现有摘要重建可更新已有的可重建摘要表，这不等于修改任务、运行、批准、领取或回执。持久化失败不得把未保存的新投影当作成功确认。

## 提交后失效与所有者

池发布、分配、工作／回合、停止和终结仅在相应原生事务成功返回后发出失效提示；领取由已验证的 `ClaimedRun` 接缝提示。`runs` 的可选 `PoolProjectionCommit` 观察器只是进程内提示，不是新增回执或 attempt 权威，生产默认构造不因此开放池执行。

协调器的 `ObservePoolCommit` 复用已有 `startOwnedLifecycleFollowup` 的根上下文、超时、等待组与关闭规则，避免在原执行回调锁内重查运行资源或同步构建摘要。至多 128 个 task／run／claim 键的临时序号缓存用于抑制重复提示，不调度任务，也不保证持久送达。

原生 `DeleteRunBatch` 仅在事务提交成功后通知已保存清理凭证的任务；回滚、放弃和无删除均不通知。每批最多通知 128 个不同任务，所有凭证仍完整保存，其余靠原生后续读取收敛。`history_cleaned` 使用独立去重域，不伪造 `run_events` 序号，避免与入队的零序号互相吞掉。后台启动构造实际接入同一观察器，不开放生产池执行。

内部 `task.pool_execution.committed` 事件只传 task ID，使现有投影器重新读取原生资料；不从通知复制 state、claim 或时间，不把它新增为公开 WebSocket 主题。任务创建、更新和阶段变化同样触发重读。成功保存后客户端仍收到原有 `task.status_summary.updated`。

通知不是事务提交回执：Memory bus 同步处理与 NATS 入队的语义不同，Publish 返回不代表摘要已经落盘。漏通知或重启后依靠原生列表／详情的摘要重建收敛，不查询触发派发，也不添加常驻写修复轮询。仅在明确任务已不存在时跳过事件，短暂来源错误不能冒充不存在。

## 未知、客户端与重连

来源失败或摘要边界无效时，投影标记 `unknown`／`pool_read_unavailable`、`current=false`，保留已经确认的身份与时间；不能继续显示旧的正常执行状态。明确读取到无绑定时则清空池摘要。已知开工不会因为后续读取不可测而被改成“从未开始”，也不会由未知状态自动重试。

Web 的 `TaskStatusSummary` 类型接纳同一可选字段；共享任务状态、看板与归档页继续使用既有原生合并机制。已有 revision 比较拒绝旧快照，完整摘要可清空字段，部分任务补丁保留摘要；连接读日志和请求代际使迟到 HTTP／重连响应不能覆盖已接收的新领取。没有再实现一套池专用客户端缓存。

任务池新页面已在界面工单接入最后确认时间、30 秒待刷新、隐藏停查、十秒读取及错误退避至三十秒，复用原生摘要失效；只保留当前有界页面而不另建池权威缓存。后端和共享缓存测试不代替界面交互，桌面正例与手机进度见工单 03，整体尚未验收。

## 验证边界

契约测试覆盖序列化及旧任务省略、语义版本、无关队列更新保留字段、已提交资料重读、自报事件不能伪造事实、明确清空与读错保留已知时间。原生 SQLite 测试覆盖只读连接、来源边界、重建、真实第二次领取与竞争 CAS；测试中的 Git 元数据胜出值不是物理 Git 验收。

协调器测试覆盖异步所有者、重复提示抑制、后续序号与关闭拒绝。前端测试覆盖两看板及归档共享状态、完整省略／部分省略、旧 revision、重连及迟到读取，无需改写既有生产合并代码。

私有真实宿主测试新编译二进制、原生登录、实际 mock-agent CLI 和 Git Worktree，在任何历史／任务池 GET 之前查询已持久摘要，逐项核对开工、回合结束、停止与终结时间；真实二进制重启及 external_id 重放后池摘要正文不变。该测试仍只证明模拟链路与缺回执的 Done 409，不代表真实提供商、验收插件正例、实体手机或生产验证。最终结果及整组存储失败见[工单 02](../../../plans/agent-pool-workbench/task-02-pool-projection.md)。

历史清理标记、规模／查询预算、资格提示与实际准入一致性及异常覆盖已在工单 02 补齐，最终来源、测量和保留失败见[隔离交付核对](../../../plans/agent-pool-workbench/acceptance-audit.md)。摘要契约不替代完整工作台或真实提供商验收。
