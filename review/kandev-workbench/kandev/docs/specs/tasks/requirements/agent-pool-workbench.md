# Agent 任务池工作台需求

## 目标与范围

让操作者知道一张卡是否已经派发、由哪个 Agent 领取、何时真正开始、当前卡在哪里，以及与其他卡的关系。保留 Kandev 的会话、终端、代码差异、工作区、原生看板及验收能力。

任务系统拥有任务级派发与执行关联，因此本能力归 tasks；共享运行队列继续服从既有调度契约，不另立任务池数据库或调度权。

已确认：用户要求 Agent 从任务池领取并开始，保留大部分原生功能，优先复用。首版约束为 Windows 单机、固定 CLI 配置、按阶段指定可领取的 Agent；不是任意 Agent 抢所有卡。当前隔离实现及真实宿主＋模拟代理验收见开发计划；真实提供商组合仍关闭，跨机器和模型 API 留待后续。

## 术语

- **业务阶段**：待办、方案确认、实施、独立审查、人工验收、完成。
- **派发**：操作者批准把某个阶段的任务交给指定能力的 Agent；派发已提交和运行已入队是两个可区分的事实。
- **领取**：宿主调度器代表实际 Agent 完成排他性领取登记。它不等于模型已收到提示或已开始生成。
- **开工**：本次运行的执行端产生可归属到当前轮次的开始或工作活动证据；进程存在、指定负责人、用户发出提示均不够。
- **本轮结束**：一次执行结束，不等于任务验收完成。
- **待核实**：证据缺失、过期或互相矛盾，不能推定为待领取、失败或完成。

## 需求

### REQ-TASKS-AGENT-POOL-001: 受控入池与排他领取

**意图：** 可以自动领取已经批准的工作，而不会因为分配了负责人、打开卡片或刷新页面就开始消耗额度。

#### 验收条件

- **AC-TASKS-AGENT-POOL-001.1:** 当任务尚未获准进入可执行阶段时，系统应保持未派发；设置负责人、打开卡片、查询或恢复界面不得派发任务。入池操作应告知将调用现有 CLI 并消耗订阅额度。
- **AC-TASKS-AGENT-POOL-001.2:** 当任务入池时，系统应验证当前阶段、前置依赖、批准状态、执行配置和操作者权限；不满足时显示具体原因，不能把拒绝或结果未知显示为已派发。
- **AC-TASKS-AGENT-POOL-001.3:** 对同一任务的同一次阶段派发，重复点击、请求重试及多个领取尝试应只对应一份逻辑运行；历史清理后不得重建同次派发。仅允许该阶段指定的 Agent 领取，实施和独立审查不得被同一运行时冒领。
- **AC-TASKS-AGENT-POOL-001.4:** 当任务已有未终结的池内执行时，另一路手动开始或再次入池应被拒绝并引导至当前运行；普通非池任务保持原有启动行为。

### REQ-TASKS-AGENT-POOL-002: 可核验的执行轨迹

**意图：** 区分派发、领取、开工与结束，历史不会被下一次尝试覆盖。

#### 验收条件

- **AC-TASKS-AGENT-POOL-002.1:** 每次派发应显示已确认的派发、入队、领取、开工时间和实际 Agent；缺失时间应明确留空或标未知，不得使用任务更新时间或当前时间补造。
- **AC-TASKS-AGENT-POOL-002.2:** 仅有领取登记或执行器启动时应显示已领取／等待开工回执；收到匹配本次执行的活动后才显示已开工。旧轮次、其他会话和子 Agent 的事件不得冒充本轮开工。
- **AC-TASKS-AGENT-POOL-002.3:** 刷新、重启、失败和显式重试后，历史领取与开工记录应保留；当前状态不得被延迟到达的旧记录覆盖。按既有政策清理原始证据后，应明确显示已清理、保留可核验的原派发／领取关联，已删除的开工时间不补造。无可核验的关联时显示待核实。
- **AC-TASKS-AGENT-POOL-002.4:** 一次执行结束只应显示本轮结束；任务完成仍须原生完成动作及已有交付验收门禁通过。

### REQ-TASKS-AGENT-POOL-003: 低噪声的工作台与移动端

**意图：** 操作者先看到需要处理的事情，而不是日志、运行编号和配置细节。

#### 验收条件

- **AC-TASKS-AGENT-POOL-003.1:** 默认工作台应提供待我处理、任务池、执行中、待验收入口；卡片显示阶段、执行状态、Agent、关键时间和最近活动。原生看板、会话、终端、Changes 和设置保留可发现入口。
- **AC-TASKS-AGENT-POOL-003.2:** 点开卡片应可查看完整时间线、当前阻塞原因与下一步动作。技术标识放详情；缺失配置、权限拒绝、加载失败、空池和数据陈旧均有不同提示，不以空列表代替失败。
- **AC-TASKS-AGENT-POOL-003.3:** 手机应可从原生导航进入单列任务池、筛选、打开完整详情并执行有权限的主要动作；触摸目标至少 44px，不依赖悬停、右键或横向拖拽。手机视图不得改写桌面布局偏好。
- **AC-TASKS-AGENT-POOL-003.4:** 状态查询应在工作区权限内有界返回；列表不加载全量会话或日志。连接失效时保留最后确认时间并标待刷新，不能继续把旧绿色状态当作实时状态。

### REQ-TASKS-AGENT-POOL-004: 单一主卡与原生关系

**意图：** 能沿任务关系导航，又不为实现、审查、验收制造三份互相漂移的任务。

#### 验收条件

- **AC-TASKS-AGENT-POOL-004.1:** 一张主卡应串联其方案、实现、独立审查和验收记录；独立交付才拆子任务，不因换 Agent 自动复制卡片。
- **AC-TASKS-AGENT-POOL-004.2:** 卡片详情应展示父子、依赖谁、阻塞谁，并可双向跳转；循环依赖、不可见任务和失效链接应沿用原生校验和权限行为。
- **AC-TASKS-AGENT-POOL-004.3:** 调整关联、切换页面、重启或删除前置任务不得被本功能解释成成功执行或批准；能否启动继续由原生依赖和阶段规则决定。

### REQ-TASKS-AGENT-POOL-005: 不确定执行的安全处置

**意图：** 避免已开工但回执丢失时，再派一份造成重复执行与重复消耗。

#### 验收条件

- **AC-TASKS-AGENT-POOL-005.1:** 排队时间长、启动时间长、暂时没有输出或连接中断应显示各自原因；不得仅凭静默判为失败或失联，不得由界面计时器重派。
- **AC-TASKS-AGENT-POOL-005.2:** 对本池中已领取且启动结果不确定的执行，重启或过期恢复不得静默再次启动；应要求核实。升级前已批准但派发证据不明的工作不能视为从未派发；须新批准。非池任务的既有恢复政策不在本需求中改写。
- **AC-TASKS-AGENT-POOL-005.3:** 撤回排队项、停止执行、重新入池应区分为不同动作；恢复前应验证当前执行和资源状态，并要求有权限的人明确确认。结果未知时先查同一操作，不能新建任务或更换 Agent 重试。
- **AC-TASKS-AGENT-POOL-005.4:** 浏览器不得自报 Agent 身份、领取／开工时间或验收结果；越权、陈旧操作、管理权冲突和校验不可测均应拒绝。池内操作不得绕过原有严格 Done 门禁。

## 明确不做

- 分布式抢占、跨机器接管、任意 Agent 自由抢所有任务、常驻协调模型。
- 第二套任务表、运行队列、对话、Git 工作区或完成／验收数据库。
- API 执行、价格／余额估算、自动模型切换、自动修复及自动重新派发。
- 证明模型在某一物理瞬间只执行一次；不可观察的外部副作用只能保守核实。
- 本次设计不代表真实 CLI、实体手机或生产验收通过。
