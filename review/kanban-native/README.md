# Kanban 原生增强：审查入口

## 已明确的产品方向

主产品是 **ai-fleet-kanban**。目标是让原 Kanban 的工作台体验、任务执行可见性、卡片关联和中文表达逐步达到用户期望的水平；Kandev 仅作交互与设计参考，不再作为产品宿主，不制作换皮分支，也不以其任务库、执行器或权限系统接管原看板。

用户同时要求：全站文案信达雅地中文化；可以采用轻量工作流提高效率，但不能过度开发、重复复核或为了流程再造一套系统。

## 本分支实际交付

只有本说明及 [下一轮路线](ROADMAP.md)，**没有实现新的 Kanban 功能**。本分支基于公开 `main` 的固定提交 `afe1b5a6efccae17ef2a1a44019cff46485e1b7b`；根目录应用、CI 和现有任务数据均未修改。实施前还须确认当前维护分支与未合并改动，不能把本审查基线当作最新开发版并覆盖其他人的工作。

原生实现的主要权威仍是：

- [任务状态、领取、租约与完成门禁](../../core/store.js)。
- [原 REST／SSE 服务与权限入口](../../core/server.mjs)。
- [原看板界面](../../core/panel.html)、[既有设计规范](../../docs/style-guide.md)。
- [原执行循环](../../loops/worker_loop.py)、[项目词汇表](../../docs/GLOSSARY.md)。

此前 Kandev 宿主方案方向已停止。其源码只保留在 [历史试验审查分支](https://github.com/yiwang0w0/ai-fleet-kanban/tree/codex/kandev-review-20261021/review/kandev-workbench) 供复盘，不应合并为产品实现；历史模拟测试不能证明原 Kanban 已实现相同能力。本原生增强分支没有携带 Kandev 源码副本、插件、补丁、框架或 SDK 依赖。

## 给独立 AI 审阅者

请固定本分支提交，先审查产品边界，再对照根目录原 Kanban 代码评估路线的必要性。优先指出“现有功能已经解决”“可以直接配置”“只需界面改进”的项，避免再次建议换宿主、重建调度或复制另一套任务状态。

发现缺陷或缺口时给出文件、行号、触发条件、已有能力和最小改动建议，区分确定问题、待验证问题与风格偏好。只读审查，不调用模型、不启用权限自动批准、不派发真实任务，也不修改数据库。

本轮只检查新增文档、引用、公开范围与提交增量敏感信息；不重复运行原系统全套测试，不把文档评审当作功能验收。
